# 접근 제어 (Access Control)

> [!important] 출제 빈도 ★★★★★
> 10회차 중 3회 이상 출제. 설명 → MAC/DAC/RBAC 이름 쓰기

---

## 3가지 접근 제어 모델 비교

| 구분        | MAC                  | DAC              | RBAC                |
| --------- | -------------------- | ---------------- | ------------------- |
| **이름**    | 강제적 접근 통제            | 임의적 접근 통제        | 역할 기반 접근 통제         |
| **영어**    | Mandatory AC         | Discretionary AC | Role-Based AC       |
| **권한 설정** | 중앙에서 **강제** 설정       | **소유자**가 자유롭게 설정 | **역할(Role)**에 묶어 설정 |
| **주체 개입** | 주체가 변경 ❌             | 소유자가 자유 변경 ✅     | 역할 변경으로 간접 변경       |
| **보안 수준** | 가장 강함                | 상대적으로 낮음         | 중간                  |
| **사용 환경** | 군사/국가기밀              | 파일 시스템           | 기업 조직 관리            |
| **분류 기준** | 보안 등급 (Top Secret 등) | 신분/신원 기반         | 직무/역할 기반            |

---

## MAC (강제적 접근 통제, Mandatory Access Control)

- 중앙에서 보안 정책을 **일괄적으로 설정**
- 주체(사용자)가 임의로 수정하거나 변경 **불가**
- 보안 등급: `Top Secret > Secret > Confidential > Unclassified`
- 주로 **군사 기밀, 국가 보안** 환경에서 사용
- **규칙 기반 (Rule-Based)** 접근 통제 정책

> [!example] 기출 (2025년 3회차 18번, 2023년 3회차 7번)
> "중앙에서 보안 정책을 일괄 설정, 주체가 변경 불가, 보안 등급에 따라 접근 결정" → **MAC**

---

## DAC (임의적 접근 통제, Discretionary Access Control)

- **자원의 소유자(Owner)**가 접근 권한을 자유롭게 부여/회수
- 파일이나 폴더의 소유자가 읽기/쓰기/실행 권한 설정
- **신분 기반 (Identity-Based)** 접근 통제 정책
- 사용자 임의 설정 가능 → **보안성 상대적으로 낮음**
- `chmod` 명령어로 리눅스 파일 권한 설정 = DAC의 예

> [!example] 기출 (2025년 3회차 18번)
> "자원의 소유자가 접근 권한을 자유롭게 부여하거나 회수" → **DAC**

---

## RBAC (역할 기반 접근 통제, Role-Based Access Control)

- 조직 내 **직무나 역할(Role)**에 따라 접근 권한 부여
- 개별 사용자에게 직접 권한 설정 ❌ → **역할에 권한을 묶어** 부여
- 직무 변경 시 **역할만 변경하면 됨** → 관리 용이
- 기업 환경에서 가장 많이 사용

> [!example] 기출 (2025년 3회차 18번, 2023년 3회차 7번)
> "부여된 직무나 역할에 따라 접근 권한, 역할 변경만으로 권한 변경" → **RBAC**

## 관련 개념

### OAuth (오어스)
- 사용자 비밀번호 없이 **제3자 앱에 접근 권한 위임**
- Access Token 발급 방식
- 소셜 로그인 (Facebook, Google 등)의 기반
- SSO와 다름: SSO는 같은 시스템 내 인증, OAuth는 서로 다른 서비스 간 권한 위임

### OTP (일회용 패스워드)
- 한 번 사용 후 즉시 폐기 → **재사용 불가**
- 시간 동기화 또는 카운터 기반으로 새로운 값 생성
- 재전송 공격 방지
- 은행 인증 등 고보안 영역 사용
