### 오답 메모

**페이지 교체 알고리즘 구분 (LRU/LFU/FIFO/OPT)**
- 2026-10-06: 프레임 3개, 참조열 1,2,3,4,1,2,5,1,2,3,4,5의 FIFO 페이지 부재 횟수 → 10으로 오답(정답 9). 10은 LRU 결과값 → 정의 구분(09-28 정답)은 되지만 **직접 계산할 때 FIFO와 LRU의 교체 기준이 섞임**
- 본인 분석: 다시 계산해 보니 정답이 나옴 (계산 실수). 앞으로 페이지 부재 계산은 **FIFO · LRU · LFU 세 방식 모두** 풀게 해서 방식 간 혼동 방지
- 핵심: FIFO는 적중(hit)해도 순서가 바뀌지 않음(먼저 들어온 것 교체), LRU는 적중 시 "최근 사용"으로 갱신. 표를 그려 프레임별로 들어온 순서를 추적. 이 참조열은 Belady의 모순 예제(FIFO 프레임 4개 → 10회)
- 2026-10-08 (세 방식 모두): 프레임 3, `7,0,1,2,0,3,0,4,2,3` → FIFO 6 / LRU 7 / LFU 8로 답함(정답 9 / 8 / 8). LFU만 정답. FIFO·LRU가 각각 정확히 정답보다 1~3 작음 → **처음 빈 프레임을 채우는 초기 부재 3회를 빼먹었을 가능성**. 다음엔 표를 그려 풀이 과정까지 확인
- (페이지 교체) 2026-10-14 (세 방식, 단답): ⚠️ **10-08과 같은 참조열(`7,0,1,2,0,3,0,4,2,3`) 재출제(출제 실수)**. 7 / 9 / 8로 답함(정답 FIFO 9 / LRU 8 / LFU 8) → LFU만 정답, 10-08(6/7/8)과 같은 결과. FIFO·LRU는 오히려 서로 뒤바뀐 듯 계산이 흔들림(LRU 9는 FIFO 값). 본인 분석: **"겹치는 것(hit)을 만났을 때 그다음에 어디를 덮어쓰는지가 헷갈리기 시작함"**. 핵심: hit가 나면 FIFO는 순서 불변 / LRU는 그 페이지를 최근 사용으로 이동 / LFU는 횟수 +1. 📘 [[../99-나를위한개념/페이지교체-hit-규칙]]. 표로 큐 상태를 적으며 확인 (FIFO 큐: [7] [7,0] [7,0,1] [0,1,2] hit [1,2,3] [2,3,0] [3,0,4] [0,4,2] [4,2,3] = 9)
- (페이지 교체) 2026-10-14 자율학습 (기록용, 시도 수 미반영): 기본 노트 FIFO 표 오류 발견·수정(10~12번 프레임). "FIFO = 참조와 무관하게 제일 고인물" 이해. 연습 `3 1 3 2 3 4 1 2 4 1` → FIFO 4 ✅ / LRU 5→7 ❌(정답 6) / LFU 8 ✅. LRU는 6~8번 연속 교체에서 꼬임 → 큐(왼쪽=외면, 오른쪽=방금)를 **매 줄 새로 적기**, 확인은 참조열 거꾸로 훑기

**HRN 스케줄링 우선순위 계산**
- 2026-10-08: 본인 "수업 때도 못 들어본 것 같다"며 모름 (정답 C: (20+5)/5 = 5)
- 핵심: 우선순위 = **(대기 시간 + 서비스 시간) ÷ 서비스 시간**, 클수록 먼저. SJF의 기아 현상 보완, 비선점

**프로세스 상태 전이 (Dispatch 등)**
- 2026-10-08: 실행 → 준비(시간 다 씀) → Dispatch로 오답(정답 Timer Run Out)
- 핵심: 준비→실행 Dispatch / 실행→준비 Timer Run Out / 실행→대기 Block / 대기→준비 Wake Up (대기에서 바로 실행 X)

**스래싱**
- 2026-10-12: "페이지 교체에 더 많은 시간을 써 CPU 활용률 급락" → 스래싱 정답
- 핵심: 다중 프로그래밍 정도가 과하면 발생. 방지: Working Set, PFF(페이지 부재 빈도), 다중 프로그래밍 정도 조절

**메모리 배치 전략 (First/Best/Worst-fit)**
- 2026-10-14: 빈 공간 100K, 500K, 200K, 300K, 600K에서 212K를 Best-fit → 300K **정답**
- 핵심: First-fit = 앞에서부터 처음 들어가는 곳(500K), Best-fit = 남는 조각이 가장 작은 곳(300K), Worst-fit = 가장 큰 곳(600K). 외부 단편화·압축과 함께 출제

**세마포어 (P / V 연산)**
- 2026-10-14: P = 진입 전 값 감소(대기), V = 반납 시 값 증가 **정답**
- 핵심: P(wait/획득) / V(signal/반납), 네덜란드어 Proberen·Verhogen. 이진 세마포어(0/1, 상호배제) vs 계수 세마포어. 뮤텍스와 구분
