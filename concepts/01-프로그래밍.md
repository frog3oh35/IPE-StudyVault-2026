### 오답 메모

**static vs 인스턴스 메서드 바인딩**
- 혼동: static 메서드도 인스턴스 메서드처럼 오버라이딩되어 런타임(실제 객체) 기준으로 호출된다고 착각
- 핵심: 인스턴스 메서드는 런타임 바인딩(실제 객체 타입), static 메서드는 컴파일타임 바인딩(참조 타입) — static은 오버라이딩이 아니라 숨김(hiding)
- 2026-09-28: 다른 코드(Animal/Dog)로 재출제했는데도 동일하게 static·인스턴스 둘 다 실제객체(Dog) 기준으로 판단함 → 규칙 자체가 아직 체화되지 않음. "메서드 호출 전 static인지부터 확인" 습관화 필요
- 2026-09-30: Parent/Child 코드로 재출제. static은 참조 타입 기준으로 맞게 풀었지만, 이번엔 인스턴스 메서드까지 참조 타입(Parent) 기준으로 계산해 13으로 오답(정답 23) → 지난번(둘 다 실제 객체 기준)과 정반대 방향으로 틀림. 규칙을 "static이면 참조 타입, 오버라이딩된 인스턴스 메서드면 실제 객체"처럼 메서드 종류별로 나눠 적용하지 못하는 상태
- 2026-10-01: A/B 코드(x.g() + x.f() + B.f())로 재출제 → bAB 정답. 처음으로 두 규칙을 메서드 종류별로 분리 적용 성공. 다음엔 필드 숨김(참조 타입 기준) 변형으로 재확인 필요
- 2026-10-06: 필드 숨김 변형 `obj.x + obj.getX() * 10` (A.x=1, B.x=2) → 30으로 오답(정답 21 = 1 + 2×10). 30 = (1+2)×10이라 바인딩(필드 1, 메서드 2)은 맞았을 가능성이 높고 **연산자 우선순위(곱셈 먼저)**를 놓친 것으로 보임. 다음엔 우선순위 함정 없이 필드 숨김만 재확인하고, 풀이를 말로 설명하게 해서 원인 확정
- 2026-10-06 (일일체크 외 추가 연습, 통계 미반영): "필드"가 뭔지부터 헷갈려서 개념 설명 후 재출제. P(n=10, get, show) / C(n=20, get만 오버라이딩), `P o = new C(); o.n + "," + o.get() + "," + o.show()` → 10,20,21로 오답(정답 10,20,11). **필드 직접 접근(10)과 오버라이딩 메서드(20)는 정답** → 기본 두 규칙은 잡힘. 틀린 곳은 오버라이딩되지 않은 `show()` 안의 n: P에 적힌 메서드라 **P의 n**(10)을 씀
- 규칙 정리: ① 필드 직접 접근 `o.n` → 선언 타입 ② 메서드 호출 → 실제 객체부터 찾고 없으면 부모로 ③ **메서드 안의 필드 → 그 메서드가 적혀 있는 클래스의 필드**. 판별법: 괄호 없으면 필드, 있으면 메서드. 다음엔 ③번 규칙을 다른 코드로 확인
- 2026-10-08: A(v=1, calc, get) / B(v=5, calc만 오버라이딩), `A o = new B(); o.get() + o.v` → 4로 오답(정답 17 = B.calc 15 + A의 v 1 + o.v 1). 4 = 전부 A 기준 → 이번엔 **규칙 ②(오버라이딩된 calc는 B 것)**를 놓침 (09-30과 같은 방향). get() 안에서 부르는 calc()도 `this.calc()`라 실제 객체 기준이라는 점까지 연결 필요

**C 포인터 산술 / 음수 인덱스**
- 혼동: `p += 2` 후 `*p + *(p+1) - p[-1]`에서 40으로 오답(정답 50 = 30 + 40 − 20) → `p[-1]`을 p가 가리키는 현재 위치 기준 상대 인덱스로 계산하지 못함
- 핵심: `p[i]` ≡ `*(p + i)` — 인덱스는 배열 시작이 아니라 **p의 현재 위치** 기준. `p[-1]`은 p 바로 앞 원소
- 2026-10-06: 문자 배열 `p = s + 3; *p, p[-2], *(p+2)` → DBF 정답. 다음엔 `p++` 이후 기준점 이동, `*p + 1` vs `*(p+1)` 구분으로 확인

**Python 슬라이싱 (음수 인덱스 + step)**
- 2026-10-06: `[10,20,30,40,50,60][-4:-1:2]` → [20, 40]으로 오답(정답 [30, 50]) → 시작점 -4를 한 칸 앞(-5, 값 20)으로 잡음
- 본인 분석: Python 입문 때 `[i:j]` 형태만 배워서 step과 음수 인덱스가 같이 나오자 막힘 (개념 이해 부족)
- 핵심: -1이 마지막 원소, 음수 인덱스 = 음수 + len (-4 + 6 = 2). end는 미포함. 음수 step이면 역방향 (`a[::-1]`)
- 📘 개념 노트: [[../99-나를위한개념/Python-슬라이싱]]
- 2026-10-08: `[1..8][-2:1:-2]` → [7, 5, 3] 정답. 99 노트 학습 후 음수 step까지 해결

**비트 연산 (&, ^, >>)**
- 2026-10-06: a=12, b=10에서 `(a&b) + (a^b) + (a>>2)` → 20으로 오답(정답 17 = 8 + 6 + 3)
- 본인 분석: **시프트 연산(`>>`)을 잊어버려서** 틀림. &(8), ^(6)는 맞게 계산함 → 다음 체크에서 시프트 위주로 재확인
- 핵심: 2진수 자리값 8 4 2 1로 변환 후 계산. & = 둘 다 1, | = 하나라도 1, ^ = 서로 다르면 1. `>> n` = ÷2ⁿ, `<< n` = ×2ⁿ, `~a` = -(a+1)
- 2026-10-08: a=13, `(a<<2) - (a>>1) + (a>>3)` → 47 정답 (52 − 6 + 1). 시프트 회복

**Java 문자열 비교 (== vs equals)**
- 2026-10-08: `a="hi"; b="hi"; c=new String("hi")` → `a==b, a==c, a.equals(c)`를 false false true로 오답(정답 true false true)
- 혼동: 리터럴끼리도 `==`면 false라고 생각 → **String Pool** 개념을 모름
- 핵심: `==` = 참조(주소) 비교, `equals()` = 내용 비교. 같은 리터럴은 Pool의 같은 객체를 공유 → `==` true. `new String()`은 항상 새 객체 → `==` false

**Python set · dict 메서드 (get 등)**
- 2026-10-08: `len(s) + len(d) + d.get('z', 10)` → 본인이 "get이 뭔지 모르겠다"며 오답 처리 (정답 17 = 4 + 3 + 10)
- 핵심: `d.get(k, 기본값)` = 키가 없으면 기본값 반환 (생략 시 None). `d[k]`는 없으면 KeyError. set의 `add`(1개) / `update`(여러 개) / `remove`(없으면 오류) / `discard`(없어도 OK)

**switch fall-through (break)**
- 2026-10-08: x=2, case 2(+2) → case 3(+3, break) → 15로 오답(정답 5). default(+10)까지 더함
- 핵심: 일치하는 case부터 **break를 만날 때까지만** 아래로 실행. break 뒤의 case와 default는 실행 안 됨
