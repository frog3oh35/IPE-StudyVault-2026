### 오답 메모

**static vs 인스턴스 메서드 바인딩**
- 혼동: static 메서드도 인스턴스 메서드처럼 오버라이딩되어 런타임(실제 객체) 기준으로 호출된다고 착각
- 핵심: 인스턴스 메서드는 런타임 바인딩(실제 객체 타입), static 메서드는 컴파일타임 바인딩(참조 타입) — static은 오버라이딩이 아니라 숨김(hiding)
- 2026-09-28: 다른 코드(Animal/Dog)로 재출제했는데도 동일하게 static·인스턴스 둘 다 실제객체(Dog) 기준으로 판단함 → 규칙 자체가 아직 체화되지 않음. "메서드 호출 전 static인지부터 확인" 습관화 필요
- 2026-09-30: Parent/Child 코드로 재출제. static은 참조 타입 기준으로 맞게 풀었지만, 이번엔 인스턴스 메서드까지 참조 타입(Parent) 기준으로 계산해 13으로 오답(정답 23) → 지난번(둘 다 실제 객체 기준)과 정반대 방향으로 틀림. 규칙을 "static이면 참조 타입, 오버라이딩된 인스턴스 메서드면 실제 객체"처럼 메서드 종류별로 나눠 적용하지 못하는 상태
- 2026-10-01: A/B 코드(x.g() + x.f() + B.f())로 재출제 → bAB 정답. 처음으로 두 규칙을 메서드 종류별로 분리 적용 성공. 다음엔 필드 숨김(참조 타입 기준) 변형으로 재확인 필요

**C 포인터 산술 / 음수 인덱스**
- 혼동: `p += 2` 후 `*p + *(p+1) - p[-1]`에서 40으로 오답(정답 50 = 30 + 40 − 20) → `p[-1]`을 p가 가리키는 현재 위치 기준 상대 인덱스로 계산하지 못함
- 핵심: `p[i]` ≡ `*(p + i)` — 인덱스는 배열 시작이 아니라 **p의 현재 위치** 기준. `p[-1]`은 p 바로 앞 원소
