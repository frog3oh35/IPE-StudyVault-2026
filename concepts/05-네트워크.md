- 2026-09-18: 255.255.255.224(/27) 호스트 수 계산에서 62(그건 /26=255.255.255.192)를 답함 → 192와 224 마스크를 헷갈림
- 2026-09-28: 255.255.254.0(/23) 네트워크 주소 계산 자체를 몰라서 "모르겠음"으로 응답 → 비트 AND 연산 절차를 옥텟 단위로 직접 손으로 풀어보는 연습 필요
- 2026-09-30: 172.16.5.130/26의 브로드캐스트 주소를 구하는 방법을 몰라 "모르겠음"으로 응답(정답 .191) → 블록 크기(256 − 마스크 옥텟값)로 구간을 나누는 방법부터 익힐 필요
- 2026-10-01: 10.0.0.77/28 네트워크 주소 → 보기는 .64로 맞혔으나 **찍은 것**이라고 본인이 밝혀 오답 처리. 풀이 절차(블록 크기 = 256 − 마스크 옥텟값 → 구간 나누기 → 해당 구간 첫 값)를 아직 직접 적용해 본 적이 없음. 다음엔 풀이 과정을 설명하게 하는 방식으로 확인 필요
- 2026-10-06: 192.168.10.100/27 브로드캐스트(정답 .127) → 본인이 "개념부터 공부해야 함"이라며 패스. 5회 연속 미해결 → **문제 풀이보다 개념 학습이 먼저.** 일일 리포트 Q17에 단계별 풀이(블록 32 → 96~127 구간 → 끝 값 .127)를 정리해 둠. 다음 체크 전에 `05-네트워크/IP-서브넷.md` 학습 권장
- 핵심: 마스크를 2진수로 펼쳐서 1의 개수(네트워크 비트)/0의 개수(호스트 비트)부터 세는 습관화, CIDR-호스트수 대응표(/24=254, /25=126, /26=62, /27=30, /28=14) 암기

**오류제어 FEC vs BEC 구분**
- 혼동: FEC/BEC 정의 자체를 몰라서 "모르겠음"으로 응답
- 핵심: FEC(전진 오류 수정) = 재전송 없이 수신측이 직접 수정 (예: Hamming). BEC(후진 오류 수정) = 오류 발견 시 송신측에 재전송 요청 (예: CRC, Parity Check)
- 2026-10-01: "재전송 없이 직접 정정하는 코드" → 해밍 코드 정답

**주소 변환 프로토콜 (ARP vs RARP)**
- 2026-10-06: "내 MAC은 알지만 IP를 모를 때 IP 요청" → ARP로 오답(정답 RARP) → 변환 방향을 반대로 기억
- 핵심: ARP = IP → MAC, RARP(Reverse) = MAC → IP. RARP는 BOOTP → DHCP로 대체됨
