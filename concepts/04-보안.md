### 오답 메모

**보안 프로토콜 식별 (SSH/IPSec/OAuth/OTP)**
- 2026-09-18: "네트워크 계층(3계층)에서 IP패킷 암호화, AH+ESP, VPN 구현"을 SSH로 오답 → SSH는 응용 계층 원격 접속 프로토콜(포트22)이고, "계층 + AH/ESP" 키워드가 나오면 IPSec임을 놓침
- 2026-09-28: "Access Token으로 제3자 앱에 권한 위임"은 OAuth로 정답 처리됨 — 다만 이전 IPSec 관련 혼동은 아직 재검증 안 됨(다른 세부 프로토콜 출제 시 재확인 필요)
- 2026-10-01: "IPSec에서 무결성·인증만 제공, 암호화 없음" → SSL/TLS로 오답(정답 AH). "IPSec에서"라는 조건이 있는데 IPSec 외부 프로토콜을 고름 → IPSec 내부 구성(AH/ESP/IKE)을 모르는 상태. 암기: **A**H = **A**uthentication만, **E**SP = **E**ncryption까지, IKE = 키 교환
- 2026-10-06: "IPSec에서 암호화 + 무결성·인증" (보기 AH/IKE/ESP/L2TP) → ESP 정답. AH/ESP/IKE 구분 회복. 다음엔 전송 모드 vs 터널 모드로 확인

**공격기법 구분 (스머프 vs 워터링홀 등)**
- 혼동: "대상에게 응답이 몰려서 서비스 거부가 일어난다"는 설명을 워터링홀로 착각
- 핵심: 워터링홀은 "특정 조직이 자주 방문하는 정상 사이트에 악성코드 심기"가 핵심 — 트래픽 폭주형 DoS 설명이 아님. IP 위장 + 브로드캐스트 ICMP Echo Request로 응답이 대상에 몰리는 방식은 스머프(Smurf)
- 2026-10-01: 워터링홀 정의 쪽에서 역방향으로 출제(보기: 스피어 피싱/파밍/스머프) → 정답. 다음엔 파밍 vs 피싱, SYN Flooding vs Land 등 인접 기법으로 확인
- 2026-10-06: "정상 URL 입력에도 DNS/hosts 변조로 위조 사이트 접속" → 파밍 정답. 다음엔 SYN Flooding vs Land vs Ping of Death로 확인
