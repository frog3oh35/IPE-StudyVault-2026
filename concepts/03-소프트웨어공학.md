### 오답 메모

**응집도 종류 구분 (교환적 vs 절차적 vs 논리적)**
- 혼동: "순서대로 수행"이라는 키워드만 보고 절차적 응집도로 판단
- 핵심: 교환적(통신적) 응집도는 "동일한 입력/출력을 공유"하는지가 판별 기준. 절차적 응집도는 입출력 공유 언급 없이 순서 관계만 있는 경우
- 2026-09-28: 이번엔 반대로 "순서대로 실행되지만 연관성 약함"(절차적의 정확한 정의)을 논리적 응집도로 잘못 답함 → 절차적과 논리적을 구분하는 기준("순서 관계가 있는지 여부")이 아직 안 잡힘. 논리적 응집도는 순서 없이 "비슷한 성격의 기능을 매개변수로 선택"하는 경우
- 2026-09-30: "코드값(1=등록, 2=조회, 3=삭제)으로 유사 기능 중 하나를 선택"하는 논리적 응집도의 정의 그대로를 기능적 응집도로 오답 → "매개변수/플래그로 선택"이 논리적 응집도의 키워드라는 점이 아직 연결되지 않음. 기능적 응집도는 "단일 기능"뿐이며, 기능이 여러 개면 해당하지 않음
- 2026-10-01: "동일한 사원 레코드를 입력받아 서로 다른 두 기능 수행" → 교환적 응집도 정답. 다음엔 순차적(출력→입력) vs 교환적(같은 입력 공유) 구분으로 재확인 필요
- 2026-10-06: "한 활동의 출력이 다음 활동의 입력" → 순차적 응집도 정답. 2연속 정답. 다음엔 시간적 응집도(초기화 모듈) 구분으로 확인
- 2026-10-08 (단답식): "초기화 모듈처럼 특정 시점에 함께 실행" → 시간적 정답. 3연속 정답

**구조 패턴 구분 (Adapter vs Bridge 등)**
- 혼동: "호환되지 않는 인터페이스를 변환"(Adapter 정의)을 Bridge로 오답 — 이름의 "연결" 뉘앙스에 끌림
- 핵심: Adapter = 인터페이스 **변환**(사후 대응), Bridge = 추상과 구현 **분리**(사전 설계). 구조 패턴 7개 "ABCD FFP"
- 2026-10-08: "상속 없이 감싸서 책임을 동적으로 덧붙임" → Decorator 정답. 감싸는 3형제 Adapter(변환) / Decorator(기능 추가) / Proxy(접근 제어·대리)

**결합도 종류 구분 (스탬프 등)**
- 2026-10-08 (단답식): "플래그(제어 신호)를 넘겨 상대 모듈의 처리 흐름 결정" → 공통으로 오답(정답 제어 결합도)
- 핵심: 약→강 **자스제외공내** (자료 < 스탬프 < 제어 < 외부 < 공통 < 내용). 제어 = 플래그 전달, 공통 = 전역 변수 공유. 응집도의 논리적(플래그로 기능 선택)과 짝으로 기억

**화이트박스 커버리지 (결정 vs 조건)**
- 2026-10-08: "전체 조건식이 참 1번, 거짓 1번" → 조건 커버리지로 오답(정답 결정 커버리지)
- 핵심: `if (A && B)`에서 **결정 = 전체 (A && B)** 의 참/거짓, **조건 = A, B 각각**의 참/거짓. 구문 < 결정 < 조건 < 조건/결정 < MC/DC < 다중 조건

**UML 관계 (집합/포함/일반화 등)**
- 2026-10-08: "전체-부분이지만 부분이 독립적으로 존재 (컴퓨터-키보드)" → 일반화로 오답(정답 집합)
- 핵심: 일반화 = is-a(상속), 집합 = has-a + 독립 생존(◇), 포함(합성) = has-a + 생명주기 공유(◆), 의존 = 점선 화살표, 실체화 = 인터페이스 구현
