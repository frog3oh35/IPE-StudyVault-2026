### 오답 메모

**COUNT(DISTINCT) 집계함수**
- 혼동: `WHERE`로 필터링된 행의 개수(50)와 `COUNT(DISTINCT 컬럼)`의 결과(값 종류 수)를 헷갈림
- 핵심: WHERE가 먼저 적용되어 행을 줄인 뒤, DISTINCT는 남은 행의 "서로 다른 값의 개수"를 셈 — 필터 후 값이 하나뿐이면 결과는 1
- 2026-09-28: WHERE절이 아예 없는 버전(전체 컬럼에 DISTINCT)으로 재출제했는데도 전체 행 수(10)를 답함 → DISTINCT 자체가 "값의 종류 수를 센다"는 정의가 아직 안 잡힘. WHERE 유무와 무관하게 COUNT(DISTINCT x) = x의 서로 다른 값 개수라는 점부터 재학습 필요
- 2026-09-30: NULL이 섞인 컬럼으로 COUNT(*), COUNT(컬럼), COUNT(DISTINCT 컬럼)을 한 번에 출제. 앞의 둘(6, 5)은 정답이었고 DISTINCT도 "종류 수"로 이해했지만, NULL까지 한 종류로 세어 4로 오답(정답 3) → 진전은 있음. 남은 약점: COUNT(DISTINCT)도 NULL을 제외함 (SELECT DISTINCT는 NULL을 출력한다는 점과 구분)
- 2026-10-01: WHERE + NULL 조합으로 COUNT(컬럼), COUNT(DISTINCT 컬럼) 출제. WHERE 필터는 맞게 적용했으나 5, 4로 오답(정답 4, 3) → 이번엔 COUNT(컬럼)에서도 NULL을 셈. NULL 처리 규칙이 문제마다 흔들림. **"NULL을 세는 건 COUNT(*) 하나뿐"** 한 문장으로 고정 암기 필요
- 2026-10-06: NULL 섞인 bonus로 COUNT(*), COUNT(bonus), AVG(bonus) 출제 → 5, 3, 120으로 오답(정답 5, 3, 200). **COUNT(*)와 COUNT(컬럼)의 NULL 처리는 처음으로 둘 다 맞힘(진전)**. 남은 약점: AVG도 NULL을 분모에서까지 제외(600/3). "NULL을 세는 건 COUNT(*) 하나뿐 = 나머지 집계함수는 전부 NULL 무시"로 확장 필요
- 본인 분석: 집계함수에 자꾸 NULL을 넣음. 다짐을 하고도 잊음 → **반복 출제** 대상 ([[../00-Dashboard/오답-분석]])
- 2026-10-08: 점수 60, NULL, 90, NULL, 90에서 `SUM/COUNT(*)`, `AVG` → 48, 80 **정답**. Q16(HAVING AVG + COUNT(금액), 대구 150/NULL)에서도 NULL 제외를 정확히 적용 → 처음으로 AVG까지 완전 정답. 형태 바꿔 한 번 더 확인 후 졸업
- 2026-10-12: COUNT(v), COUNT(*), SUM(v)/COUNT(v) (10, NULL, 20, NULL) → 2, 4, 15 **정답**. 형태를 바꿔도 NULL 규칙 유지 (2회 연속 정답 → 졸업 후보)

**정규화 단계 (부분 함수 종속 → 2NF)**
- 혼동: 복합키 (학번, 과목코드) 중 학번에만 종속된 속성 제거 → BCNF로 오답(정답 2NF)
- 핵심: 기본키 **일부**에 종속 = 부분 함수 종속 → 제거하면 2NF. BCNF는 "결정자이지만 후보키가 아닌" 경우. 암기 "도부이결다조"
- 2026-10-06: 단일키 사원번호 → 부서코드 → 부서명 (이행적 종속) → 2NF로 오답(정답 3NF). 문제에서 "이미 2NF"라고 했고 단일키라 부분 종속이 불가능함을 놓침. **복합키 여부 확인 → 2NF / 키 아닌 속성끼리 종속(A→B→C) → 3NF**로 판별 순서 고정 필요
- 본인 분석 (critical): 학부 때부터 정규형과 DB 기본 개념이 많이 미숙함 → 📘 [[../99-나를위한개념/DB-기본개념]]로 함수 종속부터 다시 학습
- 2026-10-12: 수강(학번, 과목코드, 과목명, 성적) PK=(학번, 과목코드), 과목코드→과목명 → "만족하는 가장 높은 정규형"을 2NF로 오답(정답 1NF). **부분 함수 종속이 있으면 2NF를 만족하지 못함**(제거해야 2NF가 됨) — "위반"과 "만족"을 혼동한 것으로 보임(본인 코멘트 없음)
- (정규화) 2026-10-14: R(학번, 과목, 교수) `{학번,과목}→교수`, `교수→과목` → "만족하는 가장 높은 정규형"을 1NF로 오답(정답 3NF). **4연속 오답.** 10-12(2NF라 답함, 정답 1NF)와 달리 이번엔 정답보다 **낮게** 답함 → 방향이 매번 다름. 핵심: 키 후보 {학번,과목}, {학번,교수} → 과목은 후보키의 일부(주속성)라 부분 종속·이행 종속 없음(2NF·3NF 통과), 그러나 `교수→과목`에서 결정자 교수가 후보키가 아니라 **BCNF만 위반** → 3NF. "결정자가 후보키 아님 + 종속 대상이 주속성" = 3NF OK, BCNF 위반의 전형. 📘 [[../99-나를위한개념/DB-기본개념]] §9-2

**OUTER JOIN 결과 행 수**
- 2026-10-06: 학생 4명 LEFT JOIN 수강(학번 1이 2건) → 4로 오답(정답 5) → "LEFT JOIN = 왼쪽 행 수 그대로"라고 착각
- 본인 분석: OUTER JOIN 개념이 미숙했음
- 핵심: 왼쪽 행은 모두 남지만 1:N 매칭이면 행이 늘어남. 매칭 없으면 오른쪽 컬럼 NULL. 오른쪽에만 있는 행은 버려짐 (FULL이면 포함)
- 2026-10-08: 학생 3 FULL OUTER JOIN 수강(1이 2건, 4·5는 오른쪽에만) → 6 정답 (매칭 2 + 왼쪽만 2 + 오른쪽만 2)
- 2026-10-18: LEFT JOIN + `WHERE 오른쪽 IS NULL`(짝 없는 고객 찾기) → 2 **정답**

**WHERE vs HAVING 실행 순서**
- 2026-10-06: WHERE 금액≥100 → GROUP BY → HAVING SUM≥200 → 1로 오답(정답 2: 서울 300, 대구 300)
- 본인 분석: **SUM을 AVG로 착각**함 (실행 순서보다 집계함수를 잘못 읽은 것) → 재출제 시 집계함수 종류를 섞어서 확인
- 핵심: FROM → WHERE(행 필터) → GROUP BY → HAVING(그룹 필터) → SELECT → ORDER BY. HAVING은 그룹 **합계** 기준. WHERE가 그룹 합계를 바꿀 수 있음(부산 200 → 150)
- 2026-10-08: GROUP BY 지역 HAVING AVG(금액) >= 150 + SELECT COUNT(금액) → 서울 2, 대구 1 정답. 집계함수 종류(AVG/COUNT)를 섞어도 정확히 읽음
- 2026-10-18: HAVING COUNT(*) >= 2 AND SUM >= 250 + SELECT COUNT(금액)(A에 NULL 1건) → A 2, B 2 **정답**. HAVING의 COUNT(*)와 SELECT의 COUNT(컬럼)을 구분함

**트랜잭션 특성 (ACID)**
- 2026-10-06: "동시 실행 트랜잭션이 서로의 중간 결과 참조 불가" → 원자성으로 오답(정답 격리성)
- 핵심: 원자성 = All or Nothing (트랜잭션 하나 안), 일관성 = 실행 전후 일관된 상태, 격리성 = 동시 실행 간섭 금지(Locking), 지속성 = 완료 결과 영구 반영(Log)
- 📘 개념 노트: [[../99-나를위한개념/DB-기본개념]] §6
- 2026-10-08: 계좌 이체 중 장애 → 출금까지 Rollback → 일관성으로 오답(정답 원자성). 10-06(격리성→원자성)에 이어 2연속 오답, 방향은 매번 다름 → 네 특성의 경계가 안 잡힘
- 판별 키워드: **Rollback / 전부 아니면 전무 → 원자성**, 제약조건·총액 유지 → 일관성, 동시 실행·Locking → 격리성, 완료 후 영구 반영·장애 후에도 유지 → 지속성
- 2026-10-12: 주문 COMMIT 직후 정전, 재기동 후에도 내역 유지(로그로 회복) → 일관성으로 오답(정답 지속성). **3연속 오답**(격리성→원자성, 원자성→일관성, 지속성→일관성). 일관성으로 답하는 경향 → 일관성 = "제약조건 유지"로 좁혀 기억하고 나머지는 키워드(Rollback / Locking / 영구 반영·로그)로 분리
- (ACID) 2026-10-14: 동시 실행 트랜잭션의 중간 결과를 못 보게 → 고립성 **정답**. 3연속 오답 끝에 첫 정답. "동시 실행·중간 결과 → 고립성" 키워드는 잡힘. 한 번 더 확인 후 졸업

**키의 종류 (슈퍼키/후보키/기본키)**
- 2026-10-08: "유일성 O, 최소성 X (학번, 이름)" → 후보키로 오답(정답 슈퍼키)
- 핵심: 슈퍼키 = 유일성만, 후보키 = 유일성 + **최소성**, 기본키 = 후보키 중 선택, 대체키 = 남은 후보키. 포함 관계 기본키 ⊂ 후보키 ⊂ 슈퍼키
- 📘 [[../99-나를위한개념/DB-기본개념]]
- (키) 2026-10-14: {학번, 이름} 유일성 O·최소성 X → 대체키로 오답(정답 슈퍼키). ⚠️ **10-08과 사실상 같은 문제(출제 실수)**. 10-08은 후보키, 이번은 대체키로 오답. 핵심: 최소성을 만족하는 키 = 후보키, 후보키 중 기본키로 안 뽑힌 것 = 대체키. 최소성이 없으면 후보키·대체키 둘 다 아니고 **슈퍼키**. 순서: 슈퍼키(유일성) → 후보키(+최소성) → 기본키(1개 선택) / 나머지 = 대체키. 📘 [[../99-나를위한개념/DB-기본개념]] §9-1

**DDL 옵션 (RESTRICT vs CASCADE)**
- 2026-10-08: "참조 중이면 삭제 취소" → TRUNCATE로 오답(정답 RESTRICT)
- 핵심: RESTRICT = 참조 중이면 거부, CASCADE = 참조하는 쪽까지 연쇄 삭제. TRUNCATE는 옵션이 아니라 "구조는 두고 데이터 전부 삭제"하는 별도 명령
- 2026-10-18: 뷰 v_영업이 참조하는 상태에서 `DROP TABLE 사원 RESTRICT` → "사원만 삭제, 뷰는 남음"으로 오답(정답 삭제 거부). 본인: "뷰랑 RESTRICT 몰라" → **뷰 개념(SELECT문에 이름 붙인 가상 테이블 = 원본에 의존)부터 없음**. RESTRICT = 거부 / CASCADE = 함께 삭제. 2연속 오답

**관계대수 연산자 (σ/π/⋈/÷)**
- 2026-10-08: "조건을 만족하는 튜플 추출" → ⋈로 오답(정답 σ)
- 핵심: σ(Select) = 행 추출 = SQL WHERE, π(Project) = 열 추출 = SQL SELECT 컬럼, ⋈(Join) = 결합, ÷(Division) = 모두 포함하는 튜플. 관계대수 "Select"가 SQL WHERE라는 이름 함정 주의

**UNION vs UNION ALL**
- 2026-10-12: A(1,2,2) UNION B(2,3) → 3행 정답
- 핵심: UNION = 중복 제거(정렬 포함), UNION ALL = 중복 유지(5행). 각 SELECT의 컬럼 수·타입이 같아야 함

**DCL (GRANT / REVOKE / WITH GRANT OPTION)**
- 2026-10-14: `GRANT SELECT ON emp TO user1 WITH GRANT OPTION;` → 본인 "GRANT 모른다"며 모름(오답 처리)
- 핵심: GRANT = 권한 부여, REVOKE = 회수. `WITH GRANT OPTION` = 받은 권한을 **다른 사용자에게 다시 부여**할 수 있음. REVOKE ... CASCADE = 그 사용자가 준 권한까지 연쇄 회수. DCL: GRANT / REVOKE (+ COMMIT / ROLLBACK은 TCL). 📘 [[../99-나를위한개념/DB-기본개념]] §9-3
- 2026-10-18: DBA→kim(WITH GRANT OPTION)→lee 후 `REVOKE ... FROM kim CASCADE` → 본인 "아예 모른다"(오답, 정답 둘 다 회수). 2연속 모름. **GRANT ... TO / REVOKE ... FROM** 문법 모양부터 익히기

**LIKE 와일드카드 (_ / %)**
- 2026-10-14: `name LIKE '_a%'`, (Kim, Park, Lee, Jang, Han, Baker) → 3개로 오답(정답 4개: Park, Jang, Han, Baker). Baker를 놓쳤을 가능성(B-a-ker, 두 번째 글자가 a). 본인 코멘트 없음
- 핵심: `_` = 글자 **정확히 1개**, `%` = 0개 이상. `'_a%'` = 두 번째 글자가 a. 하나씩 글자를 세어 표시하며 확인
- 2026-10-18: `'%S_'`(끝에서 두 번째가 S), (AS1, BS, CAS9, S2, ASK, XSS) → 4로 오답(정답 5). **S2(`%` = 0글자)나 XSS를 놓친 것으로 보임**(본인 코멘트 없음). 2연속 1개 차이 오답 → 개념은 아는데 **하나씩 표시하며 세는 습관**이 부족

**논리 연산자 우선순위 (NOT > AND > OR)**
- 2026-10-18: `부서='개발' OR 부서='영업' AND 급여>=4000` → 2로 오답(정답 3). 왼쪽부터 `(개발 OR 영업) AND 급여`로 묶음
- 핵심: **AND가 OR보다 먼저** (AND = 곱, OR = 합). 괄호 없으면 AND 양쪽부터 괄호로 묶고 시작. 기출 2024-1회 18번 같은 유형

**NULL 비교 (= NULL vs IS NULL)**
- 2026-10-18: `bonus = NULL` / `bonus IS NULL` 행 수 → 본인 "is와 =의 차이를 솔직히 모르겠다"(모름)
- 핵심: NULL은 값이 아니라 "모름" 상태 → `= NULL`은 항상 UNKNOWN → WHERE에서 **0행**. NULL 확인은 반드시 `IS NULL` / `IS NOT NULL`. 0은 NULL이 아님. (같은 날 Q14에서 `IS NULL`이 들어간 LEFT JOIN은 맞힘)

**INNER JOIN / CROSS JOIN 행 수**
- 2026-10-18: 사원(D1, D2, D1, NULL, D4) INNER JOIN 부서(D1, D2, D3) → 4로 오답(정답 3), CROSS JOIN은 "뭔지 몰라"(정답 5×3=15)
- 핵심: INNER = 양쪽 짝 있는 행만. **NULL은 어떤 값과도 매칭 안 됨**, 상대 테이블에 없는 값(D4)도 탈락. CROSS = 모든 조합(행 수 곱, 관계대수 교차곱 ×). 실기에선 `CROSS JOIN` 키워드보다 관계대수 ×나 `FROM A, B`(조건 없음) 형태로 나옴

**ALTER TABLE (ADD / DROP / MODIFY)**
- 2026-10-18: 컬럼 추가/삭제 빈칸 → 본인 "INSERT, MODIFY, ADD 쪽은 잘 모른다. DROP이 찐 삭제라는 것 쯤만 앎"(모름, ② DROP은 알았음)
- 핵심: ALTER는 구조(DDL)라서 **ADD / DROP (COLUMN) / MODIFY**. INSERT·DELETE는 행을 다루는 DML이라 ALTER 안에 못 씀. DDL ↔ DML 짝: CREATE↔INSERT, ALTER↔UPDATE, DROP↔DELETE

**서브쿼리 비교 (ALL / ANY)**
- 2026-10-18: `가격 > ALL (100, 300)` → 본인 "ALL의 의미를 모르겠어"(모름, 정답 P4·P5)
- 핵심: `> ALL` = 모든 값보다 큼 = `> MAX`, `> ANY` = 하나보다만 크면 됨 = `> MIN`, `= ANY` = IN

**ORDER BY 다중 정렬 (ASC / DESC)**
- 2026-10-18: `ORDER BY 반 DESC, 점수 ASC` → 반을 1반부터(ASC) 정렬해 오답(정답 라, 나, 가, 마, 다). 점수 ASC는 맞게 적용
- 핵심: **DESC = 큰 것부터**(Descend = 내려감), ASC = 작은 것부터(기본값). 정렬 키워드는 바로 앞 컬럼에만 적용

**DML UPDATE (순차 실행)**
- 2026-10-18: UPDATE 두 문장 연속 후 SUM → 본인 "UPDATE를 잘 몰라"(모름, 정답 8000)
- 핵심: `UPDATE 테이블 SET 컬럼 = 새 값 WHERE 조건` = 조건 맞는 행의 값 변경. 문장은 **순서대로** 적용되고 두 번째 문장은 바뀐 결과를 기준으로 조건을 검사. WHERE 없으면 전 행 변경
- 본인 분석 (10-18): "DCL DDL (하나 더 = DML) 어느 쪽을 아예 모르는지 느낌이 온다" → **SELECT 외의 명령문(DDL·DML·DCL) 전반이 비어 있음**. SELECT 읽기 5/8 vs 명령문 0/4
