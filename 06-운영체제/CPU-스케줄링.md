# CPU 스케줄링

> [!important] 출제 빈도 ★★★★
> 거의 매 회차. 평균 대기시간 계산 또는 스케줄링 방식 식별

---

## 스케줄링 알고리즘 종류

| 방식 | 선점/비선점 | 특징 |
|------|-----------|------|
| **FCFS** (First Come First Served) | 비선점 | 도착 순서 처리 |
| **SJF** (Shortest Job First) | 비선점 | CPU burst 짧은 순 |
| **SRT** (Shortest Remaining Time) | **선점** | SJF의 선점 버전, 더 짧은 프로세스 오면 뺏음 |
| **RR** (Round Robin) | **선점** | 타임 퀀텀씩 순환 |
| **Priority** | 선점/비선점 | 우선순위 높은 순 |

> [!example] 기출 (2025년 2회차 4번)
> "(1) CPU burst 짧은 순, Shortest Next CPU Burst, 선점/비선점 가능" → **SJF**
> "(2) SJF를 선점으로 구현, 더 짧은 burst 가진 프로세스가 CPU 선점" → **SRT**

## RR (Round Robin) 평균 대기시간 계산

> [!example] 기출 (2025년 2회차 13번) — 타임 퀀텀 4ms

| 프로세스 | 도착 | 실행 |
|---------|------|------|
| P1 | 0 | 8 |
| P2 | 1 | 4 |
| P3 | 2 | 9 |
| P4 | 3 | 5 |

```
타임퀀텀=4, 간트 차트:
0~4:  P1 (4ms 실행, 남은 4ms)
4~8:  P2 (4ms 실행, 완료) ✓  → 완료시간=8
8~12: P3 (4ms 실행, 남은 5ms)
12~16: P4 (4ms 실행, 남은 1ms)
16~20: P1 (4ms 실행, 완료) ✓  → 완료시간=20
20~25: P3 (5ms 실행, 완료) ✓  → 완료시간=25
25~26: P4 (1ms 실행, 완료) ✓  → 완료시간=26

대기시간 = 완료시간 - 도착시간 - 실행시간
P1: 20-0-8=12, P2: 8-1-4=3, P3: 25-2-9=14, P4: 26-3-5=18
평균: (12+3+14+18)/4 = 47/4 = 11.75ms
```

> 정답: **11.75ms**

## SRT 평균 대기시간 계산

> [!example] 기출 (2024년 2회차 12번)

| 프로세스 | 도착 | 실행 |
|---------|------|------|
| A | 0 | 8 |
| B | 1 | 4 |
| C | 2 | 9 |
| D | 3 | 5 |

```
SRT = 남은 실행시간이 가장 짧은 프로세스 선택 (선점)
t=0: A 실행 (남은: A=8)
t=1: B 도착 (남은: A=7, B=4) → B가 더 짧음 → B로 선점
t=1~5: B 실행 (남은: A=7, B→0) → B 완료 ✓ (완료=5)
t=5: C 도착(t=2, 남은 7), D 도착(t=3, 남은 4), A(남은 7)
t=5~7: D 실행 (남은: A=7, C=7, D=4→남은2)... 등
[상세 계산 추적 필요]

결과: 평균 대기시간 = 6.5ms
```

> 정답: **6.5ms**

## 페이지 교체 알고리즘

### LRU (Least Recently Used)
- **가장 오래 사용하지 않은** 페이지 교체
- 최근성(Locality) 원리 기반

### LFU (Least Frequently Used)
- **가장 적게 사용된** (사용 횟수가 가장 적은) 페이지 교체

> [!example] 기출 (2024년 2회차 4번)
> 페이지 참조: 7 0 1 2 0 3 0 4 2 3 0 3 2 1 2 0 1 7 0 1, 프레임 3개
> LRU 페이지 부재 횟수: **?** (상세 시뮬레이션 필요)

> [!example] 기출 (2024년 1회차 9번)
> 페이지 참조: 1 2 3 1 2 4 1 2 5 7, 프레임 3개
> LRU: 6, LFU: 6
