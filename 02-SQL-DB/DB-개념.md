# 데이터베이스 핵심 개념

---

## 릴레이션 구성요소

| 용어 | 대응 | 설명 |
|------|------|------|
| **튜플(Tuple)** | 행(Row), 레코드 | 한 행 = 하나의 레코드 |
| **속성(Attribute)** | 열(Column), 필드 | 데이터 항목의 특성, 고유한 이름 |
| **카디널리티(Cardinality)** | 행의 수 | 튜플의 총 개수 |
| **차수(Degree)** | 열의 수 | 속성의 총 개수 |
| **인스턴스(Instance)** | 저장된 데이터 전체 | 특정 시점의 테이블 내용 |
| **도메인(Domain)** | 속성의 값 범위 | 가능한 값들의 집합 |

> [!warning] 카디널리티 vs 차수 혼동 금지!
> - **카디널리티** = 행 개수 (세로로 셈)
> - **차수** = 열 개수 (가로로 셈)

> [!example] 기출 (2025년 3회차 16번)
> ㄱ. 테이블의 한 행 → **튜플**
> ㄴ. 현재 저장된 데이터 전체 → **인스턴스**
> ㄷ. 행의 총 개수 → **카디널리티**

> [!example] 기출 (2024년 2회차 4번)
> Cardinality: **5** (행 수), Degree: **4** (열 수)

## 스키마 (Schema) 3단계

| 스키마 | 관점 | 설명 | 특징 |
|--------|------|------|------|
| **외부 스키마** | 사용자/응용 | 개인별 논리적 구조 정의 | 서브 스키마, 여러 개 가능 |
| **개념 스키마** | 조직 전체 | 전체 데이터의 논리적 구조 | **하나만 존재**, 관계/제약 정의 |
| **내부 스키마** | 시스템/물리 | 실제 저장 방법, 물리적 구조 | 시스템 프로그래머 관리 |

> [!example] 기출 (2023년 1회차 18번)
> 1. 사용자/응용프로그래머 관점, 서브스키마 → **외부 스키마**
> 2. 조직 전체, 하나만 존재, 제약 정의 → **개념 스키마**
> 3. 물리적 저장 방법, 레코드 물리 구조 → **내부 스키마**

## 키(Key) 종류

| 키 | 조건 | 설명 |
|----|------|------|
| **슈퍼키(Super Key)** | 유일성 ✅, 최소성 ❌ | 유일 식별은 하지만 최소성 불만족 |
| **후보키(Candidate Key)** | 유일성 ✅, 최소성 ✅ | 기본키 될 수 있는 후보 |
| **기본키(Primary Key)** | NULL ❌, 중복 ❌ | 후보키 중 선택된 대표 키 |
| **대체키(Alternate Key)** | - | 후보키 중 기본키 제외한 나머지 |
| **외래키(Foreign Key)** | - | 다른 릴레이션의 PK를 참조하는 속성 |

> [!example] 기출 (2024년 3회차 15번)
> (1) 다른 테이블 PK 참조 → **외래키**
> (2) 유일 식별 최소 속성집합 → **후보키**
> (3) 후보키 중 기본키 제외 나머지 → **대체키**
> (4) 유일 식별 가능 속성 집합 → **슈퍼키**

> [!example] 기출 (2025년 1회차 8번)
> 릴레이션에서: (1) 속성 개수=**차수(Degree)**, (2) 튜플 개수=**카디널리티**, (3) 다른 릴레이션 PK 참조=**외래키**, (4) 값 유형/범위=**도메인**

## 무결성 제약 조건

| 무결성 | 설명 |
|--------|------|
| **개체 무결성** | 기본키는 NULL이거나 중복 ❌ |
| **참조 무결성** | 외래키는 참조 대상 릴레이션의 PK값으로 존재해야 함 |
| **도메인 무결성** | 속성값은 정의된 도메인 범위 내에 있어야 함 |

> [!example] 기출 (2025년 1회차 2번, 2024년 2회차 8번)
> 기본키가 NULL인 경우 → **개체 무결성** 위반

> [!example] 기출 (2023년 3회차 20번)
> "외래키가 선언된 릴레이션의 외래키 값은 참조 대상 PK 값으로 존재해야" → **참조 무결성**
