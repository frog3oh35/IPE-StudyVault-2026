# 오류 검출 & 수정

> [!important] 출제 빈도 ★★★★
> 거의 매 회차. 오류 처리 방식 → 이름 매핑, 방식별 분류

---

## 핵심 분류: FEC vs BEC

| 방식 | 이름 | 설명 | 해당 기법 |
|------|------|------|-----------|
| **FEC** | 전진 오류 수정 (Forward Error Correction) | **재전송 없이** 수신측이 직접 오류 수정 | Hamming Code |
| **BEC** | 후진 오류 수정 (Backward Error Correction) | 오류 발생 시 **송신측에 재전송 요청** | CRC, Parity, 블록 합 검사 |

> [!warning] FEC(전진) = 수신측 자체 수정 / BEC(후진) = 재전송 요청
> 이 방향이 자주 헷갈림!

---

## Hamming Code (해밍 코드)

- **FEC 방식** — 재전송 없이 수신측에서 직접 수정
- **1비트 오류** 검출 및 정정 가능
- 선형 블록 부호 + 순회 부호
- 미국 Bell 연구소 Hamming이 고안
- 데이터에 **여러 개의 검사 비트** 추가

> [!example] 기출 (2025년 3회차 4번)
> "재전송 없이 수신 측에서 자체 수정" → **FEC**
> "전송 데이터에 여러 검사 비트 추가하여 오류 검출 및 수정" → **Hamming**

---

## CRC (Cyclic Redundancy Check)

- **BEC 방식** — 오류 검출 후 재전송 요청
- **다항식**을 사용하여 오류 검출
- 데이터를 다항식으로 나눈 **나머지**를 CRC 값으로 사용
- 3글자 영어 약자: **CRC**

> [!example] 기출 (2025년 1회차 3번)
> "정해진 다항식으로 2진수 나눗셈하고 나머지를 CRC 값으로" → **CRC**

> [!example] 기출 (2025년 3회차 4번)
> "(⑤) 검사는 특정 다항식을 사용하여 오류를 검출" → **CRC**

---

## Parity Check (패리티 검사)

- **BEC 방식**
- 데이터 블록 끝에 **1비트** 검사 비트 추가
- 짝수 패리티 / 홀수 패리티
- 가장 단순한 오류 검출 방식

---

## 오류 방식 전체 구조

```
오류 처리 방식
├── FEC (Forward Error Correction) — 수신측 직접 수정
│   └── Hamming Code
└── BEC (Backward Error Correction) — 재전송 요청
    ├── Parity Check (패리티 검사)
    ├── CRC (순환 중복 검사)
    └── 블록 합 검사 (Block Sum Check)
```

> [!example] 기출 (2023년 2회차 12번)
> ① Hamming, ② FEC, ③ BEC, ④ Parity, ⑤ CRC

## HDLC 프로토콜

### HDLC 프레임 구조

| 프레임 | 앞 비트 | 역할 |
|--------|--------|------|
| **정보(I-frame)** | `0` | 실제 사용자 데이터 전송, Seq(순서번호) 포함 |
| **감독(S-frame)** | `10` | 흐름제어/오류제어, Seq 없음 (Next만 존재) |
| **비번호(U-frame)** | `11` | 순서번호 없음, 링크 설정/해제/모드 설정 |

### HDLC 통신 모드

| 모드 | 설명 |
|------|------|
| **비동기 균형 모드(ABM)** | 두 국이 **동등한 위치**, 명령/응답 주고받음 |
| **비동기 응답 모드(ARM)** | 종국이 주국 **허가 없이** 응답 전송 가능 |

> [!example] 기출 (2026년 1회차 6번, 2023년 2회차 13번)
> 1. 정보(I) 2. 감독(S) 3. 비번호(U)
> 4. 비동기 균형 모드(ABM) 5. 비동기 응답 모드(ARM)

## 라우팅 프로토콜

| 프로토콜 | 방식 | 알고리즘 | 최대 홉 | 특징 |
|----------|------|---------|--------|------|
| **RIP** | 거리 벡터 | Hop Count | **15** | IGP, 간단, 소규모 |
| **OSPF** | 링크 상태 | **Dijkstra** | 없음 | 빠른 수렴, 대규모 |

> [!example] 기출 (2024년 1회차 7번)
> "최소 Hop count 파악, 거리와 방향, 최대 Hop count 15, IGP" → **RIP**

> [!example] 기출 (2024년 1회차 7번)
> "링크 상태 라우팅, Dijkstra 알고리즘, 최적 경로" → **OSPF**

## 패킷 교환 방식

| 방식 | 설명 | 특징 |
|------|------|------|
| **가상 회선** | 첫 패킷으로 경로 고정, 이후 패킷은 고속 전송 | 연결 지향, ATM |
| **데이터그램** | 각 패킷을 독립적으로 처리/교환 | 비연결, 경로 장애에 강함 |

> [!example] 기출 (2023년 1회차 5번)
> "처음 패킷으로 경로 고정, ATM" → **가상 회선**
> "각 패킷 독립 처리, 비연결형, 장애 시 우회 가능" → **데이터그램**
