# 오답 분석 & 출제 방침

> [!important] 이 파일의 역할
> 1. **출제 방침**: 개념별로 다음에 어떤 형식(객관식/단답식/계산)으로 낼지 정한다. 일일체크 출제 전에 Claude가 반드시 확인한다.
> 2. **오답 원인 기록**: 채점 후 사용자가 직접 밝힌 "왜 틀렸는지"를 남겨서 공부 방향을 맞춘다.
>
> 개념별 시도/정답 통계는 `concepts/`, 문제 원문과 해설은 `07-일일체크/`에 있다.

### 출제 형식

| 영역 / 개념 | 형식 | 근거 |
|------------|------|------|
| 응집도 · 결합도 | **단답식** | 10-06 Q10·Q11 정답. 객관식은 졸업 |
| 보안 (공격기법 · 보안 프로토콜 · 암호 알고리즘 · 접근제어) | **단답식** (틀려도 OK) | 10-06 Q14~16 정답. "아예 모르는 수준은 아님" |
| GoF 디자인 패턴 | 당분간 **객관식** | 10-06 Q12 정답이지만 "간신히 아는 수준" |
| 페이지 교체 계산 | **FIFO · LRU · LFU 세 방식 모두** 풀게 하기 | 10-06 Q19 재계산하니 정답. 방식 간 혼동 방지 |
| 그 외 | 객관식 (4지선다) 기본 | — |

### 재확인 · 강화 대상

| 개념 | 우선순위 | 할 일 |
|------|---------|------|
| **DB 기본 개념 · 정규형** | 🔥 critical | [[../99-나를위한개념/DB-기본개념]] 학습 후 재출제. 키 · 함수 종속 · 정규형 판별 · ACID 골고루 |
| **서브넷 계산** | 🔥 높음 | [[../99-나를위한개념/서브넷-계산]] 학습 후 재출제. 풀이 과정을 말로 설명하게 해서 확인 (찍기 방지) |
| 집계함수 NULL 처리 | 높음 | **반복 출제**. 다짐("NULL은 COUNT(*)만")을 하고도 잊는다 → 형태를 바꿔 계속 확인 |
| static / 인스턴스 메서드 · 필드 | 높음 | 강화. 특히 "메서드 안의 필드 = 메서드가 적힌 클래스의 필드" 규칙 |
| 비트 연산 — **시프트(`>>`, `<<`)** | 중간 | 다음 체크에서 재확인 (&, ^는 정답이었음) |
| Python 슬라이싱 | 중간 | [[../99-나를위한개념/Python-슬라이싱]] 학습 후 음수 step 포함해 재확인 |
| OUTER JOIN | 중간 | LEFT / RIGHT / FULL 행 수 계산 |
| 통신 프로토콜 (ARP · RARP · ICMP · DHCP · SSH 등) | 중간 | 출제 범위 넓히기. 노트는 만들지 않음 |

### 공통 원칙
- **오늘 틀린 것만 반복하지 않는다.** 재확인 개념은 문제의 절반 이하로 두고, 나머지는 아직 안 다룬 개념으로 채운다.
- 재확인할 때는 같은 문제를 다시 내지 않고 **다른 코드 · 다른 맥락**으로 낸다.
- 채점 후 틀린 문제는 사용자에게 **틀린 이유**를 묻고 아래 기록에 남긴다.
