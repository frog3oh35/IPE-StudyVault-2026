# 오답 분석 & 출제 방침

> [!important] 이 파일의 역할
> 1. **출제 방침**: 개념별로 다음에 어떤 형식(객관식/단답식/계산)으로 낼지 정한다. 일일체크 출제 전에 Claude가 반드시 확인한다.
> 2. **오답 원인 기록**: 채점 후 사용자가 직접 밝힌 "왜 틀렸는지"를 남겨서 공부 방향을 맞춘다.
>
> 개념별 시도/정답 통계는 `concepts/`, 문제 원문과 해설은 `07-일일체크/`에 있다.

| 페이지 교체 계산 | **FIFO · LRU · LFU 세 방식 모두** 풀게 하기 | 10-06 Q19 재계산하니 정답. 방식 간 혼동 방지 |
| 그 외 | 객관식 (4지선다) 기본 | — |

### 재확인 · 강화 대상

| 개념 | 우선순위 | 할 일 |
|------|---------|------|
| **DB 기본 개념 · 정규형** | 🔥 critical | [[../99-나를위한개념/DB-기본개념]] 학습 후 재출제. 키(10-08 슈퍼키↔후보키 오답) · 함수 종속 · 정규형 판별 · ACID(2연속 오답) · 관계대수 골고루 |
| **서브넷 계산** | 🔥 높음 | **노트 학습 전까지 출제 보류** (10-08 "아직 공부 안 함"). 학습했다고 하면 재출제하고 풀이 과정을 말로 설명하게 해서 확인 |
| static / 인스턴스 메서드 · 필드 | 높음 | 강화. 10-08엔 오버라이딩된 메서드(규칙 ②)를 놓침 → 세 규칙을 한 코드에 섞어 계속 확인 |
| 페이지 교체 계산 | 중간 | 세 방식 모두 + **표 그리기**. 초기 부재(빈 프레임 채우기) 포함 여부 확인 |
| 공격기법 (DoS 계열) | 중간 | 단답식 유지. 워터링 홀을 DoS에 붙이는 패턴 2회 → SYN Flooding / Smurf / Land / Ping of Death / Teardrop 구분 |
| 10-08 신규 오답 (String ==, dict.get, switch, 관계대수, DDL 옵션, 커버리지, UML, OSI, 상태 전이, HRN, Diffie-Hellman) | 중간 | 다른 맥락으로 한 번씩 재확인 |
| 집계함수 NULL 처리 | 낮음 | 10-08 2문제 모두 정답. 형태 바꿔 한 번 더 맞히면 졸업 |
| 시프트 · 슬라이싱 · OUTER JOIN · HAVING | 낮음 | 10-08 정답 (회복). 가끔 섞어서 유지 확인 |
| 통신 프로토콜 (ARP · RARP · ICMP · DHCP · SSH 등) | 중간 | 출제 범위 넓히기. 노트는 만들지 않음 (ICMP · UDP 정답) |

### 공통 원칙
- **오늘 틀린 것만 반복하지 않는다.** 재확인 개념은 문제의 절반 이하로 두고, 나머지는 아직 안 다룬 개념으로 채운다.
- 재확인할 때는 같은 문제를 다시 내지 않고 **다른 코드 · 다른 맥락**으로 낸다.
- 채점 후 틀린 문제는 사용자에게 **틀린 이유**를 묻고 아래 기록에 남긴다.
