## 생성 패턴 (Creational)

### Singleton (싱글톤)
- 인스턴스를 **하나만** 생성, 전역 접근 제공
- 주로 DBCP(DataBase Connection Pool) 등에 사용
- `static` 멤버로 단일 인스턴스 보관

```java
// 2024년 1회차 1번 — Connection.get() 패턴
Connection conn1 = Connection.get(); // 최초 생성
Connection conn2 = Connection.get(); // 동일 객체 반환
```

### Factory Method (팩토리 메서드)
- 객체 **생성을 서브클래스에 위임**
- 상위 클래스에서 인터페이스 정의, 실제 생성은 하위 클래스

### Abstract Factory (추상 팩토리)
- **관련 객체군**을 묶어 생성하는 인터페이스 제공
- `kit`라고도 불림
- 연관성 있는 여러 종류 객체를 일관된 방식으로 생성

> [!example] 기출 (2024년 1회차 20번)
> "구체적인 클래스에 의존하지 않고 서로 연관되거나 의존적인 객체들의 조합을 만드는 인터페이스" → **Abstract Factory**

### Builder (빌더)
- 복잡한 객체를 **단계별**로 생성
- 동일한 생성 절차로 다른 표현 결과 생성

### Prototype (프로토타입)
- 기존 객체를 **복제**해서 생성
- `clone()` 메서드 활용

## 구조 패턴 (Structural)

### Adapter (어댑터)
- **인터페이스 변환** — 맞지 않는 인터페이스를 연결
- 기존 클래스를 감싸서(wrapper) 인터페이스 변환
- `Adaptee` → `Adapter` → `Target`

> [!example] 기출 (2025년 1회차 14번)
> "서로 다른 인터페이스를 가진 클래스들을 연결해 사용 가능하게 한다" → **Adapter**

### Bridge (브리지)
- **기능 계층과 구현 계층을 분리**
- 두 계층을 독립적으로 확장 가능

> [!example] 기출 (2026년 1회차 2번)
> "기능의 클래스 계층과 구현의 클래스 계층을 연결" → **Bridge**

### Composite (컴포지트)
- 트리 구조로 **부분-전체 계층** 표현
- 단일 객체와 복합 객체를 동일하게 취급

### Decorator (데코레이터)
- 객체에 **기능을 동적으로 추가**
- 상속 대신 래핑(wrapping)으로 기능 확장

### Facade (퍼사드)
- 복잡한 서브시스템에 **단순한 인터페이스** 제공

### Proxy (프록시)
- **대리 객체**로 실제 객체 접근 제어
- 실제 객체 생성 지연(lazy), 접근 로깅, 보안 적용
- 실제 객체를 감춰 정보은닉 강화

> [!example] 기출 (2025년 2회차 7번, 2023년 1회차 11번)
> "어떤 객체에 대한 접근을 제어하거나 추가 기능을 부여하기 위해 대리 객체를 사용" → **Proxy**

## 행위 패턴 (Behavioral)

### Observer (옵저버)
- 한 객체의 **상태 변경 시 의존 객체들에게 자동 알림**
- 이벤트 핸들링, MVC의 Model-View 관계

> [!example] 기출 (2026년 1회차 2번)
> "한 객체의 상태가 바뀌면 그 객체에 의존하는 객체들이 알림을 받아 자동으로 갱신" → **Observer**

### Strategy (전략)
- 알고리즘을 캡슐화하고 **교체 가능**하게 만듦
- 런타임에 알고리즘 선택 가능

### Iterator (이터레이터)
- **내부 구조 노출 없이** 컬렉션 요소에 순차 접근
- Java의 `Iterator` 인터페이스 구현체

> [!example] 기출 (2024년 2회차 10번)
> "컬렉션 객체의 내부 구조를 노출하지 않고 순차적으로 접근" → **Iterator**

### Visitor (비지터)
- **기존 코드 변경 없이 새로운 기능 추가**
- 호스트 객체 내부 상태에 접근하는 방법 제공

> [!example] 기출 (2023년 2회차 11번)
> "호스트 객체의 내부 상태에 접근해 새로운 기능 추가 가능, 기존 코드 변경 없음" → **Visitor**

### Command (커맨드)
- 요청을 **객체로 캡슐화**
- 실행 취소(Undo), 작업 큐에 활용

### Chain of Responsibility (책임 연쇄)
- 요청을 처리할 수 있는 객체를 **체인으로 연결**
- 각 객체가 처리 여부 결정 후 다음으로 전달

### Template Method (템플릿 메서드)
- 상위 클래스에서 알고리즘 **골격 정의**, 세부는 서브클래스에서

### State (상태)
- 객체 **내부 상태에 따라 행동 변경**
- 상태를 클래스로 캡슐화

### Mediator (중재자)
- 객체들이 직접 통신하지 않고 **중재자를 통해 통신**
- 결합도 감소

## 시험 빈출 패턴 요약 비교

| 패턴 | 핵심 한 줄 | 분류 |
|------|-----------|------|
| **Singleton** | 인스턴스 하나만 | 생성 |
| **Abstract Factory** | 관련 객체군 묶어 생성 (kit) | 생성 |
| **Adapter** | 인터페이스 변환 (wrapper) | 구조 |
| **Bridge** | 기능/구현 계층 분리 | 구조 |
| **Proxy** | 대리 객체, 접근 제어 | 구조 |
| **Observer** | 상태 변경 → 의존 객체 알림 | 행위 |
| **Iterator** | 내부 구조 숨기고 순차 접근 | 행위 |
| **Visitor** | 기존 코드 변경 없이 기능 추가 | 행위 |
| **Strategy** | 알고리즘 캡슐화, 교체 가능 | 행위 |
