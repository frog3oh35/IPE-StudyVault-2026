## Q1. 01-프로그래밍 — Python 리스트 슬라이싱 (음수 인덱스 + step)

**문제**
`a = [10, 20, 30, 40, 50, 60]` 일 때, `print(a[-4:-1:2])` 의 출력은?

**보기**
1. [30, 40, 50]
2. [30, 50]
3. [40, 60]
4. [20, 40]

**내 답**: [20, 40] (오답)
**정답**: [30, 50]

**해설**

| 값      | 10  | 20  | 30  | 40  | 50  | 60  |
| ------ | --- | --- | --- | --- | --- | --- |
| 양수 인덱스 | 0   | 1   | 2   | 3   | 4   | 5   |
| 음수 인덱스 | -6  | -5  | -4  | -3  | -2  | -1  |

- start `-4` → 30 (인덱스 2), end `-1` → 60 (인덱스 5, **포함 안 됨**)
- 인덱스 2, 3, 4 중 step 2 → 인덱스 2, 4 → `[30, 50]`
- 고른 [20, 40]은 시작점을 한 칸 앞(-5)으로 잡은 결과다. **-1이 마지막 원소**이므로 -4는 뒤에서 4번째인 30이다.

**연관 함정 지식**
- 슬라이싱 `[start:end:step]`에서 **end는 항상 미포함**이다.
- 음수 인덱스 변환: `음수 + len` → -4 + 6 = 2
- step이 음수면 역방향이다: `a[-1:-4:-1]` → [60, 50, 40], `a[::-1]`은 전체를 뒤집는다.
- 범위를 벗어난 슬라이싱은 에러 없이 빈 리스트 `[]`를 돌려준다 (인덱싱 `a[10]`은 IndexError).

## Q2. 01-프로그래밍 — C 포인터 산술 / 음수 인덱스 (재확인)

**문제**
```c
char s[] = "ABCDEFG";
char *p = s + 3;
printf("%c%c%c", *p, p[-2], *(p+2));
```
의 출력은?

**보기**
1. DAF
2. CAE
3. DBF
4. DBE

**내 답**: DBF (정답)
**정답**: DBF

**해설**
- `p = s + 3` → `s[3]` = 'D'를 가리킨다.
- `*p` = 'D', `p[-2]` = `*(p-2)` = `s[1]` = 'B', `*(p+2)` = `s[5]` = 'F'

지난번(10/01) 틀렸던 "p 현재 위치 기준 음수 인덱스"를 다른 코드로 맞혔다.

**연관 함정 지식**
- `p[i] ≡ *(p+i)`이고, 기준은 **p가 지금 가리키는 위치**다.
- `*p + 1`(값에 1 더하기)과 `*(p + 1)`(다음 원소)의 차이에 주의한다. 문자에서 `*p + 1`은 'D'+1 = 'E'다.
- `p++` 후에는 기준점 자체가 바뀐다. 문자열 포인터 `printf("%s", p)`는 p부터 끝까지 출력한다 ("DEFG").

## Q3. 01-프로그래밍 — static vs 인스턴스 메서드 바인딩 (필드 숨김 변형)

**문제**
```java
class A {
    int x = 1;
    int getX() { return x; }
}
class B extends A {
    int x = 2;
    int getX() { return x; }
}

A obj = new B();
System.out.println(obj.x + obj.getX() * 10);
```
의 출력은?

**보기**
1. 22
2. 11
3. 12
4. 21

**내 답**: 30 (보기에 없는 답 직접 입력 — 오답)
**정답**: 21

**해설**
- `obj.x`: **필드는 오버라이딩되지 않는다** → 참조 타입(A) 기준 → 1
- `obj.getX()`: 오버라이딩된 인스턴스 메서드 → 실제 객체(B) 기준 → B의 `getX()`가 B의 x를 반환 → 2
- `1 + 2 * 10` → **곱셈 먼저** → 1 + 20 = 21
- 30은 `(1 + 2) * 10`으로 계산한 값으로 보인다. 바인딩(1과 2)은 맞게 판단했을 수 있지만 **연산자 우선순위**를 놓쳤다. 다른 이유로 30이 나왔다면 다음에 풀이를 말로 설명하게 해서 확인한다.

**연관 함정 지식**
- 필드와 static 메서드는 **참조 타입**, 오버라이딩된 인스턴스 메서드는 **실제 객체** 기준이다.
- 메서드 안의 `x`는 **그 메서드가 정의된 클래스**의 필드다. B의 getX() 안 x → B.x = 2. 만약 B에 getX()가 없어서 A의 getX()가 호출되면 A.x = 1이 된다.
- `((B)obj).x`처럼 캐스팅하면 B의 필드 2에 접근한다.
- 출력문 안 산술식은 `* / %`가 `+ -`보다 먼저다. 문자열이 섞이면(`"" + 1 + 2`) 왼쪽부터 문자열 연결이 되는 함정도 있다.

## Q4. 01-프로그래밍 — 비트 연산 (&, ^, >>)

**문제**
```c
int a = 12, b = 10;
printf("%d", (a & b) + (a ^ b) + (a >> 2));
```
의 출력은?

**보기**
1. 17
2. 20
3. 15
4. 26

**내 답**: 20 (오답)
**정답**: 17

**해설**
```
a = 12 = 1100
b = 10 = 1010
a & b  = 1000 = 8   (둘 다 1일 때만 1)
a ^ b  = 0110 = 6   (서로 다를 때만 1)
a >> 2 = 0011 = 3   (오른쪽 2칸 이동 = 12 / 4)
```
8 + 6 + 3 = **17**

**연관 함정 지식**
- `|`(OR) = 1110 = 14와 `^`(XOR) = 6을 헷갈리지 않는다. XOR은 "다르면 1"이다.
- `a >> n` = a / 2ⁿ (정수 나눗셈), `a << n` = a × 2ⁿ
- `~a` = -(a+1) → `~12` = -13 (2의 보수)
- 논리 연산자 `&&`, `||`(결과 0/1)와 비트 연산자 `&`, `|`를 구분한다.
- 2진수 4비트 자리값 **8 4 2 1**로 빠르게 변환하는 습관을 들인다.

## Q5. 02-SQL-DB — 집계함수 NULL 처리 (COUNT / AVG)

**문제**
EMP 테이블의 bonus 컬럼 값이 다음과 같을 때(총 5행),
bonus: 100, NULL, 200, NULL, 300
```sql
SELECT COUNT(*), COUNT(bonus), AVG(bonus) FROM EMP;
```
의 결과는?

**보기**
1. 5, 5, 120
2. 3, 3, 200
3. 5, 3, 200
4. 5, 3, 120

**내 답**: 5, 3, 120 (오답)
**정답**: 5, 3, 200

**해설**
- `COUNT(*)` = 5 (NULL 포함 전체 행) ✅
- `COUNT(bonus)` = 3 (NULL 제외) ✅
- `AVG(bonus)` = (100+200+300) / **3** = 200. AVG도 NULL을 **분모에서까지 제외**한다.
- 120은 600 / 5로 NULL 행까지 분모에 넣은 값이다.

**진전**: COUNT(*)와 COUNT(컬럼)의 NULL 처리는 이번에 둘 다 맞혔다. 남은 약점은 "다른 집계함수(AVG)도 NULL을 무시한다"는 점이다.

**연관 함정 지식**
- **NULL을 세는 건 COUNT(*) 하나뿐**이다. SUM, AVG, MAX, MIN, COUNT(컬럼)은 모두 NULL을 무시한다.
- NULL을 0으로 보고 평균을 내려면 `AVG(COALESCE(bonus, 0))` 또는 `SUM(bonus) / COUNT(*)` → 120
- 모든 값이 NULL이면 `SUM`/`AVG`는 NULL, `COUNT(컬럼)`은 0이다.

## Q6. 02-SQL-DB — LEFT OUTER JOIN 결과 행 수

**문제**
학생(학번): 1, 2, 3, 4
수강(학번, 과목): (1,DB), (1,OS), (3,NW), (5,SE)
```sql
SELECT COUNT(*)
FROM 학생 S LEFT OUTER JOIN 수강 E
  ON S.학번 = E.학번;
```
의 결과 행 수는?

**보기**
1. 6
2. 3
3. 4
4. 5

**내 답**: 4 (오답)
**정답**: 5

**해설**
| 학생.학번 | 수강.과목 |
|-----------|-----------|
| 1 | DB |
| 1 | OS |
| 2 | NULL |
| 3 | NW |
| 4 | NULL |

- LEFT JOIN은 왼쪽(학생) 행을 **모두 남기지만, 한 학생이 여러 건과 매칭되면 그만큼 행이 늘어난다.** 학번 1은 2건 → 2행.
- 4는 "학생 1명당 1행"이라고 본 값이다.
- 수강의 학번 5는 왼쪽에 없으므로 버려진다.

**연관 함정 지식**
- INNER JOIN = 3행 (1-DB, 1-OS, 3-NW)
- RIGHT JOIN = 4행 (수강 기준: 3건 매칭 + 5-SE)
- FULL OUTER JOIN = 6행 (LEFT 5행 + 오른쪽에만 있는 5-SE)
- 매칭 안 된 쪽 컬럼은 NULL이다. `WHERE E.과목 IS NULL`을 붙이면 "수강하지 않은 학생"(2, 4)을 찾는 쿼리가 된다.

## Q7. 02-SQL-DB — WHERE vs HAVING 실행 순서

**문제**
판매(지점, 금액): (서울,100) (서울,200) (부산,150) (부산,50) (대구,300)
```sql
SELECT 지점, SUM(금액)
FROM 판매
WHERE 금액 >= 100
GROUP BY 지점
HAVING SUM(금액) >= 200;
```
의 결과 행 수는?

**보기**
1. 2
2. 3
3. 1
4. 0

**내 답**: 1 (오답)
**정답**: 2

**해설**
1. **WHERE** (행 단위 필터): 금액 50인 (부산,50) 제거
2. **GROUP BY**: 서울 = 300, 부산 = 150, 대구 = 300
3. **HAVING** (그룹 단위 필터): SUM ≥ 200 → 서울(300), 대구(300) → **2행**

1을 고른 건 서울 그룹을 빠뜨렸거나, HAVING을 그룹 합계가 아닌 개별 행 기준으로 본 것으로 보인다. 대구 300 한 행만 200 이상이기 때문이다.

**연관 함정 지식**
- 실행 순서: **FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY**
- WHERE에서는 집계함수를 쓸 수 없다 (`WHERE SUM(금액) >= 200`은 에러). 그룹 조건은 HAVING에 둔다.
- WHERE가 없었다면 부산 = 200 → 3행. "WHERE가 그룹 합계를 바꾼다"는 점이 변형 포인트다.

## Q8. 02-SQL-DB — 정규화 단계 (이행적 함수 종속 → 3NF)

**문제**
기본키가 사원번호인 제2정규형 릴레이션 사원(사원번호, 부서코드, 부서명)에서 `사원번호 → 부서코드`, `부서코드 → 부서명`의 함수 종속이 있다. 다음 정규화 단계와 그때 제거하는 종속으로 알맞은 것은?

**보기**
1. BCNF — 결정자이지만 후보키가 아닌 종속 제거
2. 2NF — 부분 함수 종속 제거
3. 4NF — 다치 종속 제거
4. 3NF — 이행적 함수 종속 제거

**내 답**: 2NF — 부분 함수 종속 (오답)
**정답**: 3NF — 이행적 함수 종속

**해설**
- `사원번호 → 부서코드 → 부서명` = A → B, B → C 이므로 A → C가 **이행적**으로 성립한다. 이를 제거하면 **3NF**다.
- 문제에서 이미 "제2정규형"이라고 했고, 기본키가 **단일 속성**(사원번호)이므로 "키의 일부"가 존재할 수 없다. 부분 함수 종속은 **복합키**일 때만 생긴다.
- 분해: 사원(사원번호, 부서코드) + 부서(부서코드, 부서명)

**연관 함정 지식**
- 암기: **도부이결다조** — 도메인 원자값(1NF) → 부분 종속 제거(2NF) → 이행 종속 제거(3NF) → 결정자이면 후보키(BCNF) → 다치 종속 제거(4NF) → 조인 종속 제거(5NF)
- 판별 순서: ① 복합키인가? → 일부에만 종속되면 2NF 문제 ② 키 아닌 속성 → 키 아닌 속성 종속이면 3NF 문제 ③ 키 아닌 속성이 키 일부를 결정하면 BCNF 문제
- 10/01에는 부분 함수 종속(2NF)을 BCNF로 틀렸고, 오늘은 이행 종속(3NF)을 2NF로 틀렸다. **각 정규형의 "제거 대상 키워드"와 "복합키 여부"를 짝지어 암기**해야 한다.

## Q9. 02-SQL-DB — 트랜잭션 특성 (ACID)

**문제**
트랜잭션의 특성 중, 동시에 실행되는 트랜잭션들이 서로의 중간 연산 결과를 참조할 수 없어야 한다는 성질은?

**보기**
1. 일관성 (Consistency)
2. 격리성 (Isolation)
3. 원자성 (Atomicity)
4. 지속성 (Durability)

**내 답**: 원자성 (Atomicity) (오답)
**정답**: 격리성 (Isolation)

**해설**
- 키워드 "**동시에 실행**", "**서로 간섭/참조 불가**" → 격리성(독립성)
- 원자성은 "**All or Nothing**". 트랜잭션 연산이 전부 반영되거나 전혀 반영되지 않아야 한다(Commit/Rollback). 트랜잭션 **하나 안의** 문제이고, 여러 트랜잭션 사이의 문제가 아니다.

**연관 함정 지식**
| 특성 | 키워드 | 관련 기법 |
|------|--------|-----------|
| 원자성 A | All or Nothing | Commit / Rollback |
| 일관성 C | 실행 전후 DB가 일관된 상태 유지 (무결성 제약) | 무결성 제약조건 |
| 격리성 I | 동시 실행 시 중간 결과 참조 불가 | 병행 제어 (Locking) |
| 지속성 D | 완료된 결과는 장애가 나도 영구 반영 | 회복 기법 (Log) |
- 격리 수준 4단계(Read Uncommitted → Read Committed → Repeatable Read → Serializable)도 격리성과 연결된다.

## Q10. 03-소프트웨어공학 — 응집도 (순차적 vs 교환적)

**문제**
모듈 내 하나의 활동에서 나온 출력 데이터를 그 다음 활동의 입력 데이터로 사용하는 경우의 응집도는?

**보기**
1. 교환적 응집도
2. 절차적 응집도
3. 순차적 응집도
4. 기능적 응집도

**내 답**: 순차적 응집도 (정답)
**정답**: 순차적 응집도

**해설**
- **출력 → 다음 입력**으로 이어지면 순차적(Sequential) 응집도다.
- 교환적(통신적)은 **같은 입력/출력을 공유**하며 서로 다른 기능을 수행한다. 절차적은 데이터 공유 없이 **순서만** 정해져 있다.
- 10/01 리포트에서 다음 확인 포인트로 남긴 "순차적 vs 교환적" 구분을 맞혔다.

**연관 함정 지식**
- 강도 순서(강 → 약): **기능적 > 순차적 > 교환적 > 절차적 > 시간적 > 논리적 > 우연적** — 암기 "기순교절시논우"
- 시간적 = 같은 시점에 실행 (예: 초기화 모듈), 논리적 = 플래그로 유사 기능 선택
- 응집도는 **높을수록**, 결합도는 **낮을수록** 좋다.

## Q11. 03-소프트웨어공학 — 결합도 (스탬프)

**문제**
모듈 간의 인터페이스로 배열이나 레코드 등의 자료 구조가 전달되는 경우의 결합도는?

**보기**
1. 스탬프 결합도
2. 자료 결합도
3. 제어 결합도
4. 외부 결합도

**내 답**: 스탬프 결합도 (정답)
**정답**: 스탬프 결합도

**해설**
- 자료 구조(배열, 레코드, 구조체)를 통째로 넘기면 스탬프(Stamp) 결합도다. 자료 구조가 바뀌면 그걸 받는 모든 모듈이 영향을 받는다.
- 자료 결합도는 **단순 값(파라미터)**만 주고받는 경우로, 가장 바람직하다.

**연관 함정 지식**
- 강도 순서(약 → 강, 좋은 → 나쁜): **자료 < 스탬프 < 제어 < 외부 < 공통 < 내용** — 암기 "자스제외공내"
- 제어 = 플래그 같은 제어 신호를 넘겨 상대 모듈의 흐름을 바꾼다.
- 외부 = 외부에서 선언한 데이터/통신 프로토콜 등을 참조한다.
- 공통 = 전역 변수를 공유한다.
- 내용 = 다른 모듈의 내부 코드/데이터를 직접 참조한다.

## Q17. 05-네트워크 — 서브넷 계산 (브로드캐스트 주소)

**문제**
IP 주소 192.168.10.100/27 이 속한 네트워크의 브로드캐스트 주소는?

**보기**
1. 192.168.10.95
2. 192.168.10.111
3. 192.168.10.127
4. 192.168.10.255

**내 답**: 패스 — "개념부터 공부해야 함" (오답 처리)
**정답**: 192.168.10.127

**해설 (개념부터 차근차근)**
1. **/27** = 앞 27비트가 네트워크 → 마지막 옥텟에서 앞 3비트가 네트워크, 뒤 5비트가 호스트
   → 마스크 마지막 옥텟 = `11100000` = 224 (255.255.255.224)
2. **블록 크기** = 256 − 224 = **32** (= 2⁵, 호스트 비트 5개)
3. 마지막 옥텟을 32씩 끊는다: 0~31 / 32~63 / 64~95 / **96~127** / 128~159 …
4. 100은 **96~127** 구간 → 네트워크 주소 = .96 (구간 첫 값), 브로드캐스트 = **.127** (구간 끝 값)
5. 사용 가능 호스트 = 32 − 2 = 30개 (.97 ~ .126)

- .95 = 바로 앞 구간의 끝, .111 = /28(블록 16)로 계산한 값, .255 = /24로 계산한 값

**연관 함정 지식**
- 공식 3개만 기억한다: **블록 = 256 − 마스크 옥텟**, **네트워크 = 구간 첫 값**, **브로드캐스트 = 다음 네트워크 − 1**
- 대응표: /25=128(블록) 126(호스트) · /26=64·62 · /27=32·30 · /28=16·14 · /29=8·6 · /30=4·2
- /23처럼 3번째 옥텟에서 끊기면 3번째 옥텟에서 블록(256−254=2)을 적용하고, 4번째 옥텟은 0~255 전체를 쓴다.

## Q18. 05-네트워크 — 주소 변환 프로토콜 (ARP vs RARP)

**문제**
자신의 물리 주소(MAC)는 알지만 IP 주소를 모를 때, 서버에 IP 주소를 요청하기 위해 사용하는 프로토콜은?

**보기**
1. ARP
2. ICMP
3. IGMP
4. RARP

**내 답**: ARP (오답)
**정답**: RARP

**해설**
- **ARP**: IP 주소 → MAC 주소 (상대 IP는 아는데 MAC을 모를 때)
- **RARP** (Reverse ARP): MAC 주소 → IP 주소 (내 MAC은 아는데 IP를 모를 때)
- 방향이 반대다. "MAC을 알고 IP를 구한다" = **R**everse

**연관 함정 지식**
- ICMP = 오류 보고·진단 (ping, traceroute), IGMP = 멀티캐스트 그룹 관리
- RARP는 오늘날 BOOTP → **DHCP**로 대체되었다.
- 모두 **네트워크 계층(3계층)** 프로토콜로 분류된다. ARP는 2~3계층 사이로 서술되기도 한다.

## Q19. 06-운영체제 — 페이지 교체 (FIFO 페이지 부재 횟수)

**문제**
페이지 프레임 3개(처음에는 모두 비어 있음)에서 FIFO 교체 알고리즘을 쓸 때, 다음 참조 문자열의 페이지 부재(Page Fault) 횟수는?
참조 문자열: 1, 2, 3, 4, 1, 2, 5, 1, 2, 3, 4, 5

**보기**
1. 9번
2. 10번
3. 8번
4. 7번

**내 답**: 10번 (오답)
**정답**: 9번

**해설**
| 참조 | 1 | 2 | 3 | 4 | 1 | 2 | 5 | 1 | 2 | 3 | 4 | 5 |
|------|---|---|---|---|---|---|---|---|---|---|---|---|
| F1 | 1 | 1 | 1 | **4** | 4 | 4 | **5** | 5 | 5 | 5 | 5 | 5 |
| F2 |   | 2 | 2 | 2 | **1** | 1 | 1 | 1 | 1 | **3** | 3 | 3 |
| F3 |   |   | 3 | 3 | 3 | **2** | 2 | 2 | 2 | 2 | **4** | 4 |
| 부재 | O | O | O | O | O | O | O | - | - | O | O | - |

부재 9회. 10회는 **LRU**로 풀었을 때의 값이다. 5 삽입 직후 FIFO에서는 1, 2가 남아 있어서 연속 적중한다.

**연관 함정 지식**
- FIFO = **가장 먼저 들어온** 것 교체 (최근 사용 여부와 무관), LRU = **가장 오래 사용 안 된** 것 교체
- 이 참조열은 **Belady의 모순** 예제다. 프레임을 4개로 늘리면 FIFO 부재가 10회로 오히려 늘어난다.
- 적중(hit)이어도 FIFO에서는 순서가 바뀌지 않는다. LRU에서는 적중 시 "최근 사용"으로 갱신된다는 점이 핵심 차이다.

## Q20. 06-운영체제 — 교착상태 필요조건

**문제**
다음 중 교착상태(Deadlock)가 발생하기 위한 4가지 필요조건에 해당하지 않는 것은?

**보기**
1. 상호 배제
2. 점유와 대기
3. 선점 가능
4. 환형 대기

**내 답**: 선점 가능 (정답)
**정답**: 선점 가능

**해설**
- 4가지 조건은 **상호 배제, 점유와 대기, 비선점, 환형 대기**다. 조건은 "선점 가능"이 아니라 **비선점**이다.

**연관 함정 지식**
- 4가지가 **모두** 성립해야 교착상태가 발생한다. 하나만 깨도 예방된다.
- 해결 방법: **예방**(조건 제거) / **회피**(은행원 알고리즘 — 안전 상태 유지) / **발견**(자원 할당 그래프) / **회복**(프로세스 종료, 자원 선점)
- 은행원 알고리즘 = "회피" 기법이다. "예방"과 헷갈리는 단골 함정이다.
