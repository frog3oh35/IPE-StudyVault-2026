## Q1. 01-프로그래밍 — static vs 인스턴스 메서드 바인딩

**문제**
다음 Java 코드의 출력 결과는?

```java
class Parent {
    static int x() { return 1; }
    int y() { return 10; }
}
class Child extends Parent {
    static int x() { return 2; }
    int y() { return 20; }
}
Parent p = new Child();
Child c = new Child();
System.out.println(p.x() + p.y() + c.x());
```

**보기**
1. 24
2. 23
3. 13
4. 22

**내 답**: 13 (오답)
**정답**: 23

**해설**
- `p.x()`: static 메서드이므로 **참조 타입(Parent)** 기준 → `1`
- `p.y()`: 인스턴스 메서드이므로 **실제 객체(Child)** 기준 → `20`
- `c.x()`: 참조 타입이 Child → `2`
- 합계: 1 + 20 + 2 = **23**

고른 13(= 1 + 10 + 2)은 static인 `p.x()`는 맞게 풀었지만, 인스턴스 메서드인 `p.y()`까지 참조 타입(Parent) 기준으로 계산해 10이 된 경우다. 지난번에는 둘 다 실제 객체 기준으로 풀었고, 이번에는 둘 다 참조 타입 기준으로 풀었다. 결국 두 규칙을 **메서드 종류별로 나눠서 적용**하지 못하고 있다.

**연관 함정 지식**
- 판단 순서: ① 이 메서드가 static인가? → static이면 참조 타입(변수 선언 타입) ② 아니면 오버라이딩되었는가? → 되었으면 실제 객체(`new` 뒤의 타입)
- 필드(변수)도 static처럼 **참조 타입 기준**이다. `p.필드`는 Parent의 필드이므로, 필드 숨김 문제에서도 같은 함정이 나온다.
- 기출 변형: 생성자 안에서 오버라이딩된 메서드를 호출하는 경우에도 실제 객체(자식)의 메서드가 호출된다.

## Q2. 02-SQL-DB — COUNT(DISTINCT) 집계함수

**문제**
EMP 테이블의 DEPT 컬럼 값이 '영업', '영업', '개발', NULL, '개발', '인사' (총 6행)일 때 다음 SQL의 결과는?

```sql
SELECT COUNT(*), COUNT(DEPT), COUNT(DISTINCT DEPT) FROM EMP;
```

**보기**
1. 6, 6, 4
2. 5, 5, 3
3. 6, 5, 4
4. 6, 5, 3

**내 답**: 6, 5, 4 (오답)
**정답**: 6, 5, 3

**해설**
- `COUNT(*)`: NULL을 포함한 전체 행 수 → 6
- `COUNT(DEPT)`: NULL을 제외한 행 수 → 5
- `COUNT(DISTINCT DEPT)`: NULL을 **제외**한 뒤 서로 다른 값의 개수(영업, 개발, 인사) → 3

앞의 두 개는 맞혔다. 이번에는 DISTINCT를 "값의 종류 수"로 제대로 이해했지만, NULL까지 하나의 종류로 세어 4가 나왔다. 지난번(전체 행 수를 답함)보다는 진전이 있다.

**연관 함정 지식**
- `COUNT(*)`만 NULL을 센다. `COUNT(컬럼)`과 `COUNT(DISTINCT 컬럼)`은 모두 NULL을 제외한다.
- 반면 `SELECT DISTINCT DEPT FROM EMP;`는 NULL도 결과 행 하나로 **출력한다**(4행). COUNT로 감싸느냐에 따라 NULL 처리가 달라진다는 점이 대표적인 함정이다.
- SUM/AVG/MAX/MIN도 NULL을 무시한다. 특히 `AVG(컬럼)`은 NULL 행을 분모에서도 빼기 때문에 `SUM(컬럼)/COUNT(*)`와 결과가 다를 수 있다.

## Q3. 03-소프트웨어공학 — 응집도 종류 구분

**문제**
하나의 모듈이 입력받은 코드값(1=등록, 2=조회, 3=삭제)에 따라 서로 성격이 비슷한 처리들 중 하나를 선택해 수행한다. 이 모듈의 응집도는?

**보기**
1. 절차적 응집도
2. 기능적 응집도
3. 논리적 응집도
4. 교환적 응집도

**내 답**: 기능적 응집도 (오답)
**정답**: 논리적 응집도

**해설**
"유사한 성격의 기능들을 한 모듈에 모아 두고, 매개변수(코드값)로 그중 하나를 선택해 수행"하는 것이 논리적 응집도의 정의다. 기능적 응집도는 모듈 안의 모든 요소가 **단 하나의 기능**을 위해 협력하는, 가장 강한 응집도다. 이 모듈은 등록·조회·삭제라는 서로 다른 기능 여러 개를 담고 있으므로 기능적 응집도가 될 수 없다.

**연관 함정 지식**
- 응집도 강한 순: 기능적 > 순차적 > 교환적 > 절차적 > 시간적 > 논리적 > 우연적
- 키워드 매핑
  - 단일 기능만 수행 → 기능적
  - 앞 활동의 **출력이 다음 활동의 입력** → 순차적
  - **같은 입력/출력**을 사용하는 서로 다른 기능 → 교환적
  - 순서대로 수행되지만 데이터 연관은 약함 → 절차적
  - **같은 시점**에 수행(초기화, 종료 처리) → 시간적
  - 유사 기능을 **매개변수/플래그로 선택** → 논리적
  - 아무 관련 없음 → 우연적
- 결합도의 "제어 결합도"(플래그를 넘겨 상대 모듈의 흐름을 제어)와 짝을 이루는 개념이다. 제어 플래그를 **받는 쪽** 모듈이 흔히 논리적 응집도를 갖는다.

## Q4. 05-네트워크 — 서브넷 브로드캐스트 주소 계산

**문제**
IP 주소 172.16.5.130/26 이 속한 서브넷의 브로드캐스트 주소는?

**보기**
1. 172.16.5.191
2. 172.16.5.127
3. 172.16.5.255
4. 172.16.5.190

**내 답**: 모르겠음 (오답) — 브로드캐스트 주소를 구하는 방법을 모름
**정답**: 172.16.5.191

**해설**
1. /26 → 마지막 옥텟에서 네트워크 비트 2개, 호스트 비트 6개 → 블록 크기 = 2^6 = **64**
2. 마지막 옥텟 기준 서브넷 구간: 0–63 / 64–127 / **128–191** / 192–255
3. 130은 128–191 구간에 속함 → 네트워크 주소 172.16.5.128, 브로드캐스트 주소 172.16.5.**191** (구간의 마지막 값)

오답 보기의 의미:
- .127: 바로 앞 서브넷의 브로드캐스트 주소
- .255: /24로 착각했을 때의 브로드캐스트 주소
- .190: 이 서브넷에서 호스트에 할당할 수 있는 마지막 주소 (브로드캐스트 − 1)

**연관 함정 지식**
- 공식: 블록 크기 = 256 − (마스크의 해당 옥텟 값). /26 → 마스크 255.255.255.192 → 256 − 192 = 64
- 네트워크 주소 = 블록의 첫 값, 브로드캐스트 = 다음 블록의 첫 값 − 1
- 사용 가능한 호스트 수 = 2^(호스트 비트) − 2 (네트워크 주소와 브로드캐스트 주소 제외) → /26은 62개
- 첫 번째 사용 가능 주소 = 네트워크 주소 + 1, 마지막 사용 가능 주소 = 브로드캐스트 − 1. 이 넷이 한 문제에서 함께 보기로 나온다.
