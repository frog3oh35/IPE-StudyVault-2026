## Q1. 01-프로그래밍 — Java 생성자 호출 순서 (this() / super())

**문제**
다음 Java 코드를 실행했을 때 출력 결과는?

```java
class P {
  P() { System.out.print("A"); }
  P(int n) { System.out.print("B"); }
}
class C extends P {
  C() { this(5); System.out.print("C"); }
  C(int n) { super(); System.out.print("D"); }
}
public class Main {
  public static void main(String[] args) {
    new C();
  }
}
```

**보기**
1. ACD
2. ABDC
3. ADC
4. ABD

**내 답**: ACD (오답)
**정답**: ADC

**해설**
`new C()` → `C()` 실행 → 첫 줄 `this(5)`로 `C(int)`에 위임 → `C(int)`의 `super()`로 `P()` 실행(A) → `C(int)` 본문(D) → 돌아와 `C()` 본문(C). 따라서 A, D, C. ACD는 `C()`의 본문(C)이 `C(int)`보다 먼저 실행된다고 본 것인데, `this(...)`는 호출한 생성자가 끝나야 다음 줄로 넘어간다.

**연관 함정 지식**
- 생성자 첫 줄에는 `this(...)`와 `super(...)` 중 **하나만** 올 수 있다(둘 다 불가).
- `this(5)`를 쓰면 부모 `P(int)`(B)는 호출되지 않는다. `super()`가 인자 없이 호출됐기 때문에 `P()`(A).
- 생성자에 `super()`를 안 써도 컴파일러가 자동으로 `super()`를 넣는다. 부모 생성자가 항상 먼저.

## Q2. 02-SQL-DB — 트랜잭션 특성 (고립성)

**문제**
두 사용자가 동시에 같은 계좌를 갱신하는 트랜잭션을 실행해도, 각 트랜잭션이 완료되기 전까지 중간 결과를 다른 트랜잭션이 볼 수 없도록 하는 특성은?

**보기**
1. 일관성 (Consistency)
2. 원자성 (Atomicity)
3. 지속성 (Durability)
4. 고립성 (Isolation)

**내 답**: 고립성 (정답)
**정답**: 고립성 (Isolation)

**해설**
동시에 실행되는 트랜잭션끼리 간섭하지 못하게 하는 특성이 고립성(격리성)이다. 락(Locking)이나 격리 수준으로 구현한다.

**연관 함정 지식**
- 원자성 = Rollback / 전부 아니면 전무, 일관성 = 제약조건·총액 유지, 지속성 = COMMIT 후 장애에도 유지(로그).
- 3연속 오답(10-06~10-12) 뒤 첫 정답. "동시 실행·중간 결과"가 고립성의 키워드.

## Q4. 02-SQL-DB — DCL (GRANT / WITH GRANT OPTION)

**문제**
다음 SQL을 실행했을 때 의미로 올바른 것은?

```sql
GRANT SELECT ON emp TO user1 WITH GRANT OPTION;
```

**보기**
1. user1이 emp를 조회할 수 있고, 이 권한을 수정할 수 있다
2. user1이 다른 사용자에게만 권한을 줄 수 있고, 자신은 emp를 조회할 수 없다
3. user1이 emp를 조회할 수 있고, 이 조회 권한을 다른 사용자에게 부여할 수도 있다
4. user1이 emp의 행을 조회하고 삭제할 수 있다

**내 답**: 모름 ("미안... 토끼 GRANT 모른다") (오답 처리)
**정답**: 3

**해설**
`GRANT 권한 ON 대상 TO 사용자`는 권한을 주는 DCL 명령이다. `WITH GRANT OPTION`을 붙이면 권한을 받은 사용자가 그 권한을 **다른 사용자에게 다시 부여**할 수 있다. 부여받은 권한은 SELECT뿐이라 삭제(DELETE)는 불가능하다.

**연관 함정 지식**
- 회수는 `REVOKE`. `REVOKE ... CASCADE`는 그 사용자가 다른 사람에게 준 권한까지 연쇄 회수한다.
- DCL = GRANT / REVOKE. COMMIT / ROLLBACK은 TCL로 구분한다(출제 시 DCL 보기에 섞어 나옴).

## Q5. 01-프로그래밍 — C 제어문 (continue / break) 추적

**문제**
다음 C 코드의 출력 결과는?

```c
#include <stdio.h>
int main() {
  int a[5] = {1, 2, 3, 4, 5};
  int sum = 0;
  for (int i = 0; i < 5; i++) {
    if (a[i] % 2 == 0) continue;
    sum += a[i];
    if (sum > 5) break;
  }
  printf("%d", sum);
  return 0;
}
```

**보기**
1. 4
2. 9
3. 6
4. 15

**내 답**: 6 (오답)
**정답**: 9

**해설**
i=0: 1 → sum=1. i=1: 2는 짝수라 continue. i=2: 3 → sum=4 (4>5 아님). i=3: 4는 continue. i=4: 5 → sum=9, 9>5라 break. 출력 9. **더한 뒤에** break 검사를 하므로 5를 더한 값 9가 남는다.

**연관 함정 지식**
- `continue`는 반복문의 나머지 본문을 건너뛰고 다음 반복으로, `break`는 반복문 자체를 탈출한다.
- 조건 검사 위치(더하기 전/후)에 따라 결과가 달라지므로 i / a[i] / sum 표를 적어 추적하는 습관이 필요하다.

## Q6. 05-네트워크 — TCP 3-way handshake

**문제**
TCP 연결 설정(3-way handshake) 시, 클라이언트와 서버 사이에 오가는 세 개의 세그먼트 순서로 올바른 것은? (클라이언트가 먼저 시작)

**보기**
1. SYN → ACK → SYN+ACK
2. SYN+ACK → SYN → ACK
3. SYN → FIN → ACK
4. SYN → SYN+ACK → ACK

**내 답**: SYN → SYN+ACK → ACK (정답)
**정답**: SYN → SYN+ACK → ACK

**해설**
클라이언트가 SYN으로 연결 요청 → 서버가 SYN+ACK로 수락 및 자신의 SYN 전달 → 클라이언트가 ACK로 확인.

**연관 함정 지식**
- 연결 종료는 4-way handshake(FIN → ACK → FIN → ACK).
- SYN만 대량으로 보내고 마지막 ACK를 안 보내는 공격이 SYN Flooding.

## Q7. 04-보안 — 공격기법 (Smurf) [단답식]

**문제**
출발지 IP를 공격 대상 서버의 IP로 위조한 ICMP Echo Request를 브로드캐스트 주소로 보내 네트워크 안의 수많은 호스트가 응답을 대상 서버로 한꺼번에 보내게 해서 서버를 마비시키는 공격기법의 이름은?

**내 답**: spoofing (오답)
**정답**: Smurf Attack (스머프 공격)

**해설**
IP 스푸핑은 이 공격이 쓰는 **수법**이지 공격의 이름이 아니다. 브로드캐스트 ICMP Echo로 응답을 증폭시켜 피해자에게 몰리게 하는 DoS 공격이 Smurf.

**연관 함정 지식**
- SYN Flooding(SYN만 대량), Land(출발지=목적지=피해자), Ping of Death(큰 ICMP 패킷), Teardrop(Fragment 오프셋 조작)과 구분.
- 응답이 다수 호스트에서 한 곳으로 몰리면 Smurf 계열.

## Q10. 01-프로그래밍 — Python 문자열 메서드 체이닝

**문제**
다음 Python 코드의 출력 결과는?

```python
s = "Hello, World"
print(s.split(",")[1].strip().lower()[::-1])
```

**보기**
1. dlroW
2. olleh
3. dlrow
4. world

**내 답**: olleh (오답)
**정답**: dlrow

**해설**
`s.split(",")` → `["Hello", " World"]`. `[1]`은 `" World"`. `strip()`으로 앞뒤 공백 제거 → `"World"`. `lower()` → `"world"`. `[::-1]`로 뒤집으면 `"dlrow"`. `olleh`는 `[0]`("Hello")을 뒤집었을 때의 값(소문자).

**연관 함정 지식**
- 인덱스 `[0]`/`[1]` 중 어느 쪽인지 먼저 확인.
- `strip()`은 공백만 제거, 쉼표는 `split(",")`에서 이미 사라진다.
- `[::-1]`은 전체를 역순으로 뒤집는 슬라이싱 (10-06 슬라이싱 노트 참고).

## Q11. 02-SQL-DB — 정규형 (BCNF 위반인 3NF)

**문제**
릴레이션 R(학번, 과목, 교수)에 다음 함수 종속이 있다. 모든 속성은 원자값이고, 학생은 과목마다 한 명의 교수에게만 배운다. 이 릴레이션이 현재 만족하는 가장 높은 정규형은?

```
{학번, 과목} → 교수
교수 → 과목
```

**보기**
1. 2NF
2. 3NF
3. BCNF
4. 1NF

**내 답**: 1NF (오답)
**정답**: 3NF

**해설**
후보키는 {학번, 과목}과 {학번, 교수}. 모든 속성이 원자값이라 1NF. 부분 함수 종속이 없고(비주속성이 없음) 이행 종속도 없어 2NF, 3NF 만족. 그러나 `교수 → 과목`에서 결정자 `교수`가 후보키가 아니므로 BCNF는 위반. 따라서 가장 높은 정규형은 3NF.

**연관 함정 지식**
- 3NF는 "종속 대상이 후보키의 일부(주속성)면 결정자가 후보키가 아니어도 허용". BCNF는 이것까지 금지.
- "도부이결다조": 도메인 원자(1NF) → 부분 종속 제거(2NF) → 이행 종속 제거(3NF) → 결정자가 후보키(BCNF) → 다치 종속(4NF) → 조인 종속(5NF).
- 이 문제는 "만족하는 가장 높은" 방향이다. 위반 단계가 아니라 통과한 단계를 센다.

## Q12. 04-보안 — 웹 공격기법 (CSRF) [단답식]

**문제**
로그인한 사용자의 세션을 악용한다. 공격자가 만든 페이지나 링크를 사용자가 방문하면, 사용자의 의도와 무관하게 비밀번호 변경이나 송금 같은 요청이 인증된 상태로 서버에 전송된다. 이 웹 공격기법의 이름은?

**내 답**: XSS (오답)
**정답**: CSRF (사이트 간 요청 위조)

**해설**
XSS는 악성 **스크립트**를 사이트에 삽입해 다른 사용자의 브라우저에서 실행시키는 공격이다. CSRF는 스크립트 삽입이 아니라 **로그인된 사용자의 권한**으로 의도치 않은 요청을 서버에 보내게 하는 공격이다.

**연관 함정 지식**
- XSS는 사용자가 사이트를 믿는 점을, CSRF는 사이트가 사용자의 인증을 믿는 점을 악용.
- 방어: XSS는 입력·출력 이스케이프, CSRF는 CSRF 토큰, Referer 검증, 재인증.
- SQL Injection은 입력값에 SQL 문을 삽입해 DB를 조작.

## Q13. 05-네트워크 — IPv6 (제거된 통신 방식)

**문제**
IPv4와 비교했을 때 IPv6에서 더 이상 사용하지 않는(제거된) 통신 방식은?

**보기**
1. 유니캐스트
2. 애니캐스트
3. 멀티캐스트
4. 브로드캐스트

**내 답**: 유니캐스트 (오답)
**정답**: 브로드캐스트

**해설**
IPv6는 유니캐스트, 멀티캐스트, 애니캐스트 세 가지를 쓰고 브로드캐스트는 없다(멀티캐스트로 대체). 유니캐스트는 1:1 통신이라 기본이다.

**연관 함정 지식**
- IPv4: 32비트, 유니·멀티·브로드캐스트. IPv6: 128비트(16비트씩 8그룹, 16진수), 유니·멀티·애니캐스트.
- 애니캐스트는 IPv6에서 새로 추가된 방식(그룹 중 가장 가까운 한 대와 통신).

## Q14. 06-운영체제 — 페이지 교체 (FIFO · LRU · LFU 계산) [단답식] ⚠️ 10-08과 같은 참조열

**문제**
프레임은 3개이고 처음엔 모두 비어 있다. 빈 프레임을 채울 때의 부재도 페이지 부재에 포함한다. 참조 문자열은 `7, 0, 1, 2, 0, 3, 0, 4, 2, 3`이다. FIFO, LRU, LFU 세 방식의 페이지 부재 횟수는? (LFU는 참조 횟수가 같으면 가장 먼저 들어온 페이지를 교체하고, 교체되어 나갔다가 다시 들어오면 참조 횟수는 1부터 시작한다.)

**내 답**: 7, 9, 8 (FIFO 7 오답 / LRU 9 오답 / LFU 8 정답)
**정답**: FIFO 9 / LRU 8 / LFU 8

**해설**
- FIFO 큐(왼쪽이 가장 오래된 것): `[7]` `[7,0]` `[7,0,1]` `[0,1,2]` hit `[1,2,3]` `[2,3,0]` `[3,0,4]` `[0,4,2]` `[4,2,3]` → 부재 9
- LRU(왼쪽이 가장 오래 안 쓴 것): `[7]` `[7,0]` `[7,0,1]` `[0,1,2]` hit→`[1,2,0]` `[2,0,3]` hit→`[2,3,0]` `[3,0,4]` `[0,4,2]` `[4,2,3]` → 부재 8 (hit 2번)
- LFU: 7, 0, 1 적재 → 2(7 교체) → 0 hit(횟수 2) → 3(횟수 1인 1·2 중 먼저 들어온 1 교체) → 0 hit(횟수 3) → 4(2 교체) → 2(3 교체) → 3(4 교체) → 부재 8

**내 말 (오답 원인)**: "겹치는 것을 만났을 때 그다음에 어디 페이지를 덮어쓰는지가 헷갈리기 시작함"

**연관 함정 지식**
- **hit가 났을 때 각 방식이 하는 일**: FIFO는 순서 불변 / LRU는 최근 사용으로 이동 / LFU는 횟수 +1.
- 10-08에 같은 참조열로 FIFO 6 / LRU 7 / LFU 8, 오늘 7 / 9 / 8. 두 번 모두 LFU만 정답. 이번에 LRU 값이 FIFO의 정답(9)과 같은 것으로 보아 FIFO와 LRU의 교체 기준이 섞이는 상태.
- 처음 빈 프레임을 채우는 부재 3회를 빼먹지 않는지 확인.

## Q18. 01-프로그래밍 — Java try-finally 실행 순서

**문제**
다음 Java 코드의 출력 결과는?

```java
public class Main {
  static int f() {
    try {
      return 1;
    } finally {
      System.out.print("F");
    }
  }
  public static void main(String[] args) {
    System.out.print(f());
  }
}
```

**보기**
1. 1F
2. F1
3. 1
4. F

**내 답**: 1F (오답)
**정답**: F1

**해설**
`return 1`은 반환값을 정해 둔 뒤 메서드를 빠져나가기 **직전에** `finally`를 실행한다. 그래서 `f()` 안에서 F가 먼저 출력되고, `f()`가 끝나 값 1이 반환된 뒤 `main`의 `print(f())`가 1을 출력한다. 출력 순서는 F, 1.

**연관 함정 지식**
- `finally`는 return이나 예외가 있어도 항상 실행된다(`System.exit()` 제외).
- `main`의 `print(f())`는 `f()`가 먼저 끝나야 출력하므로 `f()` 안의 출력이 앞선다.
- finally 안에서 `return`하면 try의 반환값을 덮어쓴다.

## Q20. 02-SQL-DB — 키의 종류 (슈퍼키) ⚠️ 10-08과 같은 예시

**문제**
학생(학번, 주민번호, 이름, 학과) 릴레이션에서 학번과 주민번호는 각각 튜플을 유일하게 식별한다. 속성 집합 {학번, 이름}은 튜플을 유일하게 식별하지만 최소성은 만족하지 못한다. {학번, 이름}은 어떤 키인가?

**보기**
1. 후보키
2. 대체키
3. 슈퍼키
4. 외래키

**내 답**: 대체키 (오답)
**정답**: 슈퍼키

**해설**
유일성만 만족하고 최소성은 만족하지 못하는 속성 집합이 슈퍼키. 후보키는 유일성 + 최소성. 대체키는 후보키 중 기본키로 선택되지 않은 것이라, 최소성이 없는 {학번, 이름}은 후보키도 대체키도 아니다.

**연관 함정 지식**
- 순서: 슈퍼키(유일성) ⊃ 후보키(+최소성) ⊃ 기본키(1개 선택, NULL 불가). 후보키 중 남은 것 = 대체키.
- 이 문제의 후보키는 {학번}, {주민번호}. 기본키가 학번이면 대체키는 주민번호.
- 10-08엔 후보키로, 오늘은 대체키로 오답: 유일성 / 최소성 두 조건 중 어느 쪽이 빠졌는지 먼저 따진다.
