## Q1. 02-SQL-DB — COUNT(DISTINCT) 집계함수

**문제**
PLAYER 테이블에 TEAM_ID가 'K01' 3명, 'K02' 5명, 'K03' 2명 있다. 다음 SQL의 결과값은?

```sql
SELECT COUNT(DISTINCT TEAM_ID) FROM PLAYER;
```

**보기**
1. 10
2. 3
3. 1
4. 0

**내 답**: 10 (오답)
**정답**: 3

**해설**
`COUNT(DISTINCT 컬럼)`은 "값의 종류 수"를 센다. TEAM_ID의 서로 다른 값은 K01, K02, K03 3가지이므로 결과는 3. 10은 전체 행 수(3+5+2)를 그대로 센 것으로, DISTINCT를 반영하지 않은 값이다.

**연관 함정 지식**
- `COUNT(*)`: 전체 행 수 (NULL 포함)
- `COUNT(컬럼)`: NULL 제외 행 수
- `COUNT(DISTINCT 컬럼)`: 중복 제거 후 값의 종류 수
- WHERE절이 있든 없든 DISTINCT는 항상 "필터링된 결과 안에서 서로 다른 값의 개수"를 센다는 점이 핵심

## Q2. 01-프로그래밍 — static vs 인스턴스 메서드 바인딩

**문제**
다음 Java 코드의 출력 결과는?

```java
class Animal {
    String sound() { return "..."; }
    static String kind() { return "Animal"; }
}
class Dog extends Animal {
    String sound() { return "Bark"; }
    static String kind() { return "Dog"; }
}
Animal a = new Dog();
System.out.println(a.sound() + a.kind());
```

**보기**
1. BarkDog
2. ...Animal
3. ...Dog
4. BarkAnimal

**내 답**: BarkDog (오답)
**정답**: BarkAnimal

**해설**
`sound()`는 인스턴스 메서드이므로 **런타임**에 실제 객체(Dog) 기준으로 호출 → `"Bark"`. 반면 `kind()`는 **static**이므로 **컴파일타임**에 참조 타입(Animal) 기준으로 고정 → `"Animal"`. 따라서 결과는 `"BarkAnimal"`.

**연관 함정 지식**
- 인스턴스 메서드: 런타임 바인딩 (다형성 적용, 실제 객체 타입 기준)
- static 메서드: 컴파일타임 바인딩 (다형성 미적용, 참조 타입 기준) — 오버라이딩이 아니라 "숨김(hiding)"
- 참조 타입과 실제 객체 타입이 다를 때 항상 "이 메서드가 static인가?"부터 확인하는 습관이 필요

## Q3. 03-소프트웨어공학 — 응집도 종류 구분

**문제**
여러 기능이 순서대로 실행되지만 그 기능들 간 연관성은 약한 경우의 응집도 종류는?

**보기**
1. 절차적 응집도
2. 교환적(통신적) 응집도
3. 시간적 응집도
4. 논리적 응집도

**내 답**: 논리적 응집도 (오답)
**정답**: 절차적 응집도

**해설**
"순서 관계가 있지만 연관성이 약함"은 절차적 응집도의 정의. 논리적 응집도는 순서와 무관하게 "비슷한 성격의 기능들을 매개변수 등으로 선택하여 묶은 경우"를 말한다.

**연관 함정 지식**
- 응집도 높은 순: 기능적 > 순차적 > 교환적(통신적) > 절차적 > 시간적 > 논리적 > 우연적
- 절차적: 순서 관계 O, 연관성 약함
- 논리적: 순서 관계 X, 유사한 기능을 매개변수로 선택
- 교환적(통신적): 동일 입출력 공유 + 서로 다른 기능
- 이 세 가지가 항상 함께 출제되며 서로 헷갈리는 조합

## Q4. 05-네트워크 — 서브넷 네트워크 주소 계산

**문제**
IP 주소 192.168.11.20, 서브넷 마스크 255.255.254.0(/23)일 때 네트워크 주소는?

**보기**
1. 192.168.11.0
2. 192.168.8.0
3. 192.168.10.0
4. 192.168.12.0

**내 답**: 모르겠음 (오답)
**정답**: 192.168.10.0

**해설**
세 번째 옥텟 11(00001011)과 마스크 254(11111110)를 AND 연산하면 00001010 = 10. 따라서 네트워크 주소는 192.168.10.0.

**연관 함정 지식**
- 마스크가 255인 옥텟은 IP값 그대로, 마스크가 0인 옥텟은 무조건 0
- 마스크가 254(11111110)인 옥텟은 AND 결과가 항상 짝수
- 마스크가 252(11111100)인 옥텟은 AND 결과가 항상 4의 배수
- 비트 AND 연산에 익숙하지 않다면 옥텟을 2진수로 직접 적어보는 습관부터 필요

## Q5. 05-네트워크 — 오류제어 FEC vs BEC 구분

**문제**
오류 발생 시 재전송을 요청하지 않고 수신측에서 직접 오류를 수정하는 방식은?

**보기**
1. BEC
2. FEC
3. Parity Check
4. CRC

**내 답**: 모르겠음 (오답)
**정답**: FEC

**해설**
FEC(전진 오류 수정, Forward Error Correction)는 재전송 없이 수신측이 직접 오류를 수정하는 방식이며 대표 기법은 Hamming Code다. Parity Check와 CRC는 모두 BEC(후진 오류 수정) 방식으로, 오류 검출 시 송신측에 재전송을 요청한다.

**연관 함정 지식**
- FEC = 전진 = 수신측 자체 수정 (Hamming)
- BEC = 후진 = 재전송 요청 (CRC, Parity, 블록 합 검사)
- "전진/후진"이라는 이름 자체가 직관적이지 않아 매번 헷갈리기 쉬움 → "전진 수정 = 수신측에서 앞으로 나아가며(재전송 없이) 처리"로 암기

## Q6. 04-보안 — 접근제어 모델 구분

**문제**
직무나 역할에 따라 접근 권한을 묶어서 부여하고, 직무가 바뀌면 역할만 변경하면 되는 접근 통제 모델은?

**보기**
1. MAC
2. DAC
3. ACL
4. RBAC

**내 답**: RBAC (정답)
**정답**: RBAC

**해설**
역할(Role)에 권한을 묶어 부여하고, 직무 변경 시 역할만 바꾸면 되는 것은 RBAC(Role-Based Access Control)의 정의다.

**연관 함정 지식**
- MAC: 중앙에서 보안 등급으로 강제 설정, 주체가 변경 불가 (군사/국가기밀)
- DAC: 소유자가 자유롭게 권한 설정 (파일 시스템, chmod)
- RBAC: 역할 단위로 권한 관리 (기업 조직)

## Q7. 04-보안 — 공격기법 구분

**문제**
공격자가 대상 호스트의 IP를 소스로 위장해 브로드캐스트 주소로 ICMP Echo Request를 보내고, 이를 받은 모든 호스트가 응답을 대상에게 보내게 하여 서비스 거부를 유발하는 공격은?

**보기**
1. 스머프(Smurf)
2. SYN Flooding
3. 워터링홀
4. APT

**내 답**: 워터링홀 (오답)
**정답**: 스머프(Smurf)

**해설**
IP를 위장해 브로드캐스트로 ICMP Echo Request를 뿌리고, 다수의 호스트가 보낸 ICMP Echo Reply가 대상에 몰려 서비스 거부를 유발하는 것은 스머프(Smurf) 공격이다. 워터링홀은 트래픽 폭주형 공격이 아니라, 표적이 자주 방문하는 정상 웹사이트에 악성코드를 심어두는 방식이다.

**연관 함정 지식**
- 스머프: IP 위장 + 브로드캐스트 ICMP → 응답 폭주형 DoS
- SYN Flooding: TCP 3-way handshake 악용, ACK 미전송으로 연결 대기 큐 고갈
- 워터링홀: 특정 조직이 자주 가는 "정상 사이트"에 악성코드 심기 (표적 공격, 트래픽 폭주 아님)
- APT: 침투→검색→수집→유출 4단계의 장기 표적 공격
- "트래픽/패킷이 몰려서 서비스 거부"라는 키워드가 나오면 워터링홀이 아니라 스머프/SYN Flooding 계열임을 먼저 의심할 것

비밀번호 전달 없이 Access Token을 발급하여 제3자 앱에 접근 권한을 위임하는 데 사용되는 것은?

**보기**

## Q9. 06-운영체제 — CPU 스케줄링 기법 구분

**문제**
SJF 방식을 선점형으로 구현한 것으로, 더 짧은 CPU burst를 가진 프로세스가 도착하면 실행 중인 프로세스를 즉시 중단시키는 스케줄링 기법은?

**보기**
1. FCFS
2. SRT
3. SJF
4. RR

**내 답**: SRT (정답)
**정답**: SRT

**해설**
SRT(Shortest Remaining Time)는 SJF의 선점형 버전으로, 더 짧은 남은 실행시간을 가진 프로세스가 도착하면 현재 실행 중인 프로세스를 선점한다.

**연관 함정 지식**
- SJF: 비선점, CPU burst 짧은 순
- SRT: SJF의 선점 버전
- FCFS: 비선점, 도착 순서대로 처리
- RR: 선점, 타임 퀀텀 단위로 순환

## Q10. 06-운영체제 — 페이지 교체 알고리즘 구분

**문제**
페이지 교체 시 사용 횟수(빈도)가 가장 낮은 페이지를 교체 대상으로 선택하는 알고리즘은?

**보기**
1. LRU
2. FIFO
3. OPT
4. LFU

**내 답**: LFU (정답)
**정답**: LFU

**해설**
LFU(Least Frequently Used)는 사용 빈도(Frequency)가 가장 낮은 페이지를 교체하는 알고리즘이다.

**연관 함정 지식**
- LRU: Recently — 가장 오랫동안 사용되지 않은 페이지 (시간 기준)
- LFU: Frequently — 사용 빈도가 가장 낮은 페이지 (횟수 기준)
- FIFO: 메모리에 가장 먼저 올라온 페이지 (Belady의 이상 현상 발생 가능)
- OPT: 앞으로 가장 오래 사용되지 않을 페이지 (이론적 최적)
