## Q1. 04-보안 — 접근 제어 모델 구분 (MAC/DAC/RBAC)

**문제**
보안 등급(Top Secret 등)에 따라 중앙에서 강제로 권한을 설정하며, 주체가 임의로 변경할 수 없는 접근 통제 모델은?

**보기**
1. DAC
2. RBAC
3. MAC
4. ACL

**내 답**: MAC (정답)
**정답**: MAC

**해설**
MAC(강제적 접근 통제, Mandatory AC)은 보안 등급을 기준으로 **중앙(시스템)이 강제로 권한을 설정**하며, 주체가 임의로 바꿀 수 없다. 군사/국가기밀 환경에서 사용하는, 3가지 모델 중 **보안 수준이 가장 강한** 모델.

**연관 함정 지식**
- **DAC**: 소유자가 자유롭게 권한을 부여/변경 (파일 시스템에서 흔함), 보안 수준은 상대적으로 낮음.
- **RBAC**: 권한을 개인이 아니라 **역할(Role)에 묶어서** 관리, 역할 변경으로 간접적으로 권한 변경, 기업 조직 관리에 적합.
- 3가지 모델 구분 핵심 질문: **"누가 권한을 설정/변경하는가?"** — 중앙(강제)=MAC, 소유자=DAC, 역할=RBAC.

## Q2. 04-보안 — 보안 프로토콜 식별 (IPSec vs SSH)

**문제**
네트워크 계층(3계층)에서 IP 패킷을 암호화/인증하며, AH와 ESP 두 프로토콜로 구성되어 기업 VPN 구현에 사용되는 프로토콜은?

**보기**
1. SSH
2. IPSec
3. OAuth
4. L2TP

**내 답**: SSH (오답)
**정답**: IPSec

**해설**
IPSec은 **네트워크 계층(3계층)**에서 IP 패킷 자체를 암호화/인증하는 프로토콜로, **AH(Authentication Header) + ESP(Encapsulating Security Payload)** 두 구성요소로 이루어지며 기업 VPN 구현에 널리 쓰인다.

**연관 함정 지식**
- **SSH**는 응용 계층에서 동작하는 **암호화된 원격 접속** 프로토콜(포트 22, 공개키 인증)이지 IP 패킷 자체를 감싸는 프로토콜이 아니다. "암호화"라는 단어만 보고 SSH를 고르지 말 것 — **계층(3계층)**과 **AH/ESP 구성요소**가 언급되면 IPSec.
- **L2TP**는 2계층 터널링 프로토콜(L2F+PPTP 결합)로 그 자체는 암호화 기능이 약해 IPSec과 함께 사용됨.
- **OAuth**는 암호화/터널링과 무관한 **제3자 권한 위임** 프로토콜(Access Token 기반) — 카테고리 자체가 다름.
- VPN 종류로 자주 묶여 나오는 3가지: **IPSec, SSL, L2TP**.

## Q3. 05-네트워크 — 서브넷 마스크 기반 호스트 수 계산

**문제**
IP 192.168.5.100에 서브넷마스크 255.255.255.224를 적용할 때, 이 네트워크에서 사용 가능한 최대 호스트 수는?

**보기**
1. 30
2. 14
3. 62
4. 126

**내 답**: 62 (오답)
**정답**: 30

**해설**
255.255.255.224를 이진수로 바꾸면 `11100000`이다. 마지막 옥텟에서 1인 비트(네트워크 비트)가 3개, 0인 비트(호스트 비트)가 **5개**이므로 사용 가능 호스트 수 = 2⁵ − 2 = **30개** (네트워크 주소, 브로드캐스트 주소 제외).

**연관 함정 지식**
- 62개가 나오는 마스크는 255.255.255.**192**(`11000000`, 호스트비트 6개, /26)다 — 192와 224를 헷갈리지 말 것.
- CIDR-호스트수 대응표(자주 나오는 것): `/24`(255.255.255.0)=254, `/25`(.128)=126, `/26`(.192)=62, `/27`(.224)=30, `/28`(.240)=14.
- 빠른 계산 팁: 마스크 마지막 옥텟의 **0으로 남은 비트 개수**가 호스트 비트 수 — 마스크 값이 255에 가까울수록(1이 많을수록) 호스트 비트는 줄어든다.

## Q4. 06-운영체제 — CPU 스케줄링 방식 구분 (SRT)

**문제**
SJF(Shortest Job First)를 선점형으로 확장하여, 실행 중인 프로세스보다 더 짧은 실행시간을 가진 프로세스가 도착하면 즉시 CPU를 빼앗는 스케줄링 방식은?

**보기**
1. RR
2. FCFS
3. Priority
4. SRT

**내 답**: SRT (정답)
**정답**: SRT

**해설**
SRT(Shortest Remaining Time)는 **SJF의 선점형 버전**이다. 실행 중인 프로세스보다 **남은 실행시간이 더 짧은 프로세스가 새로 도착하면 즉시 선점**한다.

**연관 함정 지식**
- **RR**은 짧은 job을 우선하는 게 아니라 **타임 퀀텀 단위로 순환** 실행하는 방식 — "더 짧은 프로세스가 오면 선점"이라는 조건과는 무관.
- **FCFS**는 비선점, 도착 순서대로만 처리 — 선점 자체가 불가능.
- **Priority**는 선점/비선점 둘 다 가능하지만 기준이 "실행시간의 길고 짧음"이 아니라 **우선순위 값**.
- "SJF + 선점" 조합 키워드가 나오면 무조건 SRT.
