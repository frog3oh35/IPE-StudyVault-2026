## Q1. 01-프로그래밍 — static/인스턴스 · 필드 (메서드 안의 필드 + 메서드 호출 섞기)

**문제**
```java
class A {
    int v = 2;
    int f() { return g() + v; }
    int g() { return v * 2; }
}
class B extends A {
    int v = 7;
    int g() { return v + 1; }
}

A o = new B();
B b = (B) o;
System.out.println(o.f() + b.v + o.v);
```
출력 결과는?

**보기**
1. 24
2. 15
3. 19
4. 13

**내 답**: 15 (오답)
**정답**: 19

**해설**
- `o.f()` → B에 f()가 없으므로 A의 f() 실행
  - `g()` → 실제 객체(B) 기준 → B.g() → B에 적힌 메서드라 B의 v(7) + 1 = 8
  - `+ v` → f()는 A에 적힌 메서드 → A의 v(2) → 8 + 2 = 10
- `b.v` → 선언 타입이 B(캐스팅) → B의 v = 7
- `o.v` → 선언 타입이 A → A의 v = 2
- 10 + 7 + 2 = **19**

**연관 함정 지식**
- 3규칙: ① `o.필드` → 선언 타입(캐스팅하면 캐스팅한 타입) ② `o.메서드()` → 실제 객체부터 찾고 없으면 부모 ③ 메서드 안의 필드 → 그 메서드가 적힌 클래스의 필드
- `(B) o` 캐스팅은 객체를 바꾸지 않고 **참조 타입만** 바꾼다 → `b.v`는 B의 필드
- 24 = f() 안의 v까지 B 기준(8+7)으로 계산한 경우

## Q2. 02-SQL-DB — 트랜잭션 특성 (지속성)

**문제**
한 온라인 쇼핑몰에서 주문 트랜잭션이 COMMIT 된 직후 서버 정전이 발생했다. 재기동 후에도 그 주문 내역이 사라지지 않고 남아 있어야 한다(로그로 회복). 이것을 보장하는 트랜잭션 특성은?

**보기**
1. 격리성 (Isolation)
2. 지속성 (Durability)
3. 일관성 (Consistency)
4. 원자성 (Atomicity)

**내 답**: 일관성 (Consistency) (오답)
**정답**: 지속성 (Durability)

**해설**
- "COMMIT **후** 장애가 나도 결과가 영구적으로 남는다 / 로그로 회복" → **지속성**
- 일관성은 트랜잭션 전후로 DB가 **무결성 제약을 만족하는 상태**여야 한다는 것(예: 이체 전후 총액 동일). 장애 후 데이터 보존과는 다른 얘기

**연관 함정 지식**
- 키워드: 원자성 = Commit/Rollback, 전부 아니면 전무 / 일관성 = 제약조건 유지 / 격리성 = 동시 실행 간섭 금지(Locking) / 지속성 = **완료 후** 영구 반영(Log, 회복)
- 3회 연속 오답: 10-06 격리성→원자성, 10-08 원자성→일관성, 오늘 지속성→일관성. **"일관성"은 제약조건 유지일 때만** 고르기

## Q3. 02-SQL-DB — 정규화 (현재 만족하는 정규형)

**문제**
릴레이션 수강(학번, 과목코드, 과목명, 성적)
기본키 = (학번, 과목코드)
함수 종속: (학번, 과목코드) → 성적, 과목코드 → 과목명
(모든 속성값은 원자값)

이 릴레이션이 만족하는 가장 높은 정규형은?

**보기**
1. 제3정규형
2. BCNF
3. 제2정규형
4. 제1정규형

**내 답**: 제2정규형 (오답)
**정답**: 제1정규형

**해설**
- 모든 속성이 원자값 → 1NF 만족
- `과목코드 → 과목명`: 기본키 (학번, 과목코드)의 **일부**(과목코드)에 종속된 **부분 함수 종속** 존재 → **2NF 위반**
- 따라서 만족하는 가장 높은 정규형은 1NF. 부분 함수 종속을 제거(수강 / 과목 테이블 분리)해야 비로소 2NF

**연관 함정 지식**
- 문제 방향 주의: "위반하는 정규형" vs "만족하는 가장 높은 정규형"은 답이 한 단계 차이
- 판별 순서: 원자값 아님 → 1NF 미만 / 부분 함수 종속 있음 → 1NF / 이행 함수 종속 있음 → 2NF / 결정자가 후보키 아님 → 3NF / 모두 통과 → BCNF
- 암기 "도부이결다조"

## Q5. 01-프로그래밍 — C 포인터 (`*p++`, 포인터 뺄셈)

**문제**
```c
int a[] = {10, 20, 30, 40, 50};
int *p = a;
p += 2;
int x = *p++;
int y = *p + *(p + 1);
printf("%d", x + y + (int)(p - a));
```
출력 결과는?

**보기**
1. 143
2. 123
3. 120
4. 113

**내 답**: 113 (오답)
**정답**: 123

**해설**
- `p += 2` → p는 a[2]
- `int x = *p++;` → `*p`(30)를 x에 대입한 **뒤** p가 a[3]으로 이동 → x = 30
- `y = *p + *(p+1)` → a[3] + a[4] = 40 + 50 = 90
- `p - a` → 포인터 뺄셈은 **원소 개수 차이** → 3
- 30 + 90 + 3 = **123**

**연관 함정 지식**
- `*p++` = `*(p++)`: 후위 증가라 **현재 값을 먼저 쓰고** 이동. `(*p)++`는 값 증가, `*++p`는 이동 후 값
- 113은 y를 80(=30+50 등)으로 계산했거나 `p - a`를 달리 계산한 경우로 추정 (본인 코멘트 없음)
- 포인터 뺄셈 결과는 바이트가 아니라 **원소 개수**

## Q6. 02-SQL-DB — UNION vs UNION ALL

**문제**
[A] x: 1, 2, 2
[B] x: 2, 3

```sql
SELECT x FROM A
UNION
SELECT x FROM B;
```
결과 행 수는?

**보기**
1. 4
2. 5
3. 2
4. 3

**내 답**: 3 (정답)
**정답**: 3

**해설**
- UNION은 합친 뒤 **중복을 제거** → {1, 2, 3} = 3행

**연관 함정 지식**
- UNION ALL이면 중복 유지 → 5행
- INTERSECT = 교집합 ({2} 1행), EXCEPT(MINUS) = 차집합 ({1} 1행)
- 각 SELECT의 컬럼 수·데이터 타입이 같아야 한다

## Q7. 03-소프트웨어공학 — 행위 패턴 (Strategy)

**문제**
여러 알고리즘(예: 정렬, 결제 방식)을 각각 별도 클래스로 캡슐화하고, 실행 중에 서로 바꿔 끼울 수 있도록 하는 행위 패턴은?

**보기**
1. State
2. Command
3. Strategy
4. Template Method

**내 답**: Template Method (오답)
**정답**: Strategy

**해설**
- **알고리즘군을 클래스로 캡슐화 + 런타임에 교체** → Strategy
- Template Method는 **상위 클래스가 알고리즘의 뼈대**를 정하고 일부 단계만 하위 클래스가 재정의 (상속 기반, 실행 중 교체 아님)

**연관 함정 지식**
- Strategy(합성, 알고리즘 통째로 교체) vs Template Method(상속, 뼈대 고정·단계 재정의) vs State(내부 상태에 따라 행동이 바뀜)
- Command = 요청을 객체로 캡슐화(실행 취소/큐잉), Observer = 상태 변화를 구독자에게 통지
- 행위 패턴: Chain of Responsibility, Command, Interpreter, Iterator, Mediator, Memento, Observer, State, Strategy, Template Method, Visitor

## Q12. 02-SQL-DB — 집계함수 NULL 처리 (COUNT(컬럼) / COUNT(*) / SUM÷COUNT)

**문제**
[T] v 값: 10, NULL, 20, NULL

```sql
SELECT COUNT(v), COUNT(*), SUM(v) / COUNT(v) FROM T;
```
실행 결과(세 값 순서대로)는?

**보기**
1. 2, 4, 7.5
2. 4, 4, 15
3. 2, 4, 15
4. 2, 2, 15

**내 답**: 2, 4, 15 (정답)
**정답**: 2, 4, 15

**해설**
- COUNT(v) = NULL 제외 → 2 / COUNT(*) = 전체 행 → 4
- SUM(v) = 30, COUNT(v) = 2 → 30 / 2 = 15

**연관 함정 지식**
- "NULL을 세는 건 COUNT(*) 하나뿐, 나머지 집계함수는 전부 NULL 무시"
- SUM(v)/COUNT(*) 였다면 30/4 = 7.5 (보기 1의 함정)
- 10-08에 이어 2회 연속 정답 → 졸업 후보

## Q13. 06-운영체제 — 스래싱

**문제**
다중 프로그래밍 환경에서 프로세스 수가 지나치게 많아 주기억장치가 부족해지면, 페이지 부재가 지속적으로 발생해 실제 작업보다 페이지 교체에 더 많은 시간을 쓰게 되어 CPU 활용률이 급락하는 현상은?

**보기**
1. 단편화
2. 스래싱
3. 에이징
4. 오버레이

**내 답**: 스래싱 (정답)
**정답**: 스래싱

**해설**
- 페이지 부재 폭증 + CPU 활용률 급락 → 스래싱(Thrashing)

**연관 함정 지식**
- 방지: **Working Set**(일정 시간 내 자주 참조하는 페이지 집합 유지), **PFF**(페이지 부재 빈도 조절), 다중 프로그래밍 정도 조절
- 에이징 = 오래 기다린 프로세스 우선순위를 올려 기아 방지, 오버레이 = 프로그램을 나눠 필요한 부분만 적재, 단편화 = 메모리 조각 낭비
