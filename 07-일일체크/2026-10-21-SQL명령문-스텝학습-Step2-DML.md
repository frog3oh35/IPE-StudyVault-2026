## 🔎 기출 유형 파악 (시나공 핵심요약 8장 SQL 응용 + 볼트 기출 기록)

출처: `studyFile/2026_정보처리기사_실기_기출문제집_핵심요약(20260223).pdf` 8장(p54~63), [[../02-SQL-DB/SQL-핵심]], [[../02-SQL-DB/SQL-연습문제]]

**실기 SQL 문제는 4가지 모양뿐**
1. **요구사항 → SQL 작성** (시나공 예제 전부 이 형식) — 예: "<사원> 테이블에서 '황진이'의 '부서'를 '기획'으로 변경하고 '기본급'을 5 인상하시오." → `UPDATE 사원 SET 부서='기획', 기본급=기본급+5 WHERE 이름='황진이';`
2. **빈칸 키워드** — 2024-2 (VALUES · SELECT · FROM · SET), 2026-1 (CONSTRAINT · FOREIGN · REFERENCES), 2023-2 (CASCADE)
3. **실행 결과 쓰기** (값 · 행 수) — 2024-2 COUNT(DISTINCT), 2025-3 JOIN 행 수, 2023-1 서브쿼리 AVG
4. **정의 → 용어 단답** — 2025-2 인덱스, DDL/DML/DCL 분류

**DML 출제 표시 (실기 회차)**: INSERT 24.7 · 23.7 / DELETE 23.4 · 20.10 / UPDATE 24.7 · 21.7 / SELECT 하위질의 24.10 · 24.4 · 22.7 / GROUP BY 24.7 · 23.4 / 조건검색 25.11 · 25.4 · 22.7

> [!warning] 시나공은 열 정의 변경에 MODIFY가 아니라 **ALTER**를 쓴다
> `ALTER TABLE 학생 ALTER 학번 VARCHAR(10) NOT NULL;` / `ALTER TABLE 테이블 ALTER 속성 [SET DEFAULT '기본값'];`
> → 시험 빈칸에서 "열 정의/기본값 변경"은 **ALTER**로 쓴다. (Step 1에서 배운 MODIFY는 Oracle·MySQL 방식)

> [!info] 시나공 표기 특징
> - 날짜는 `#05/03/73#`처럼 **#**으로 감쌈 (Access 문법)
> - LIKE 대표 문자에 `#`(숫자 하나)도 있음: `%` 모든 문자, `_` 문자 하나, `#` 숫자 하나
> - 문자열은 '작은따옴표', 예제 일부는 "큰따옴표"도 사용

## ☑️ DML 문법 체크리스트 (정처기 범위)

> 수준체크 문제가 아니라 **자기 점검용 목록**. 모르는 것만 딥하게, 아는 것은 빠르게노트로.
>
> **자가진단 결과 (10-21)**
> - A·B·C (INSERT · UPDATE · DELETE): 기본부터 다시 → **딥하게**
> - D (SELECT 기본): "정말 다 안다" → 생략
> - E (WHERE): **전부** 설명. 특히 날짜 경계에서 `>` vs `>=`, BETWEEN, 우선순위
> - F (정렬): 생략
> - G (그룹): 대부분 앎. G2는 NULL 세는지 여부만, STDDEV/VARIANCE는 출제되면
> - I · J (집합 연산 · JOIN): 공부한 적 있지만 다시 → **정성스럽게**

### A. INSERT
- [ ] A1 `INSERT INTO 테이블(속성1, 속성2) VALUES (값1, 값2);` — 일부 속성만
- [ ] A2 `INSERT INTO 테이블 VALUES (...);` — 속성명 생략 = **모든 속성 순서대로**
- [ ] A3 `INSERT INTO 테이블(속성들) SELECT ... FROM ... WHERE ...;` — 검색 결과 삽입 (VALUES 없음)

### B. UPDATE
- [ ] B1 `UPDATE 테이블 SET 속성 = 값 WHERE 조건;`
- [ ] B2 `SET 속성1 = 값, 속성2 = 값` — 여러 속성은 쉼표
- [ ] B3 `SET 기본급 = 기본급 + 5` — 자기 자신 기준 계산
- [ ] B4 WHERE 생략 → 모든 행 / 여러 문장은 바뀐 표 기준 (10-18 Q15)

### C. DELETE
- [ ] C1 `DELETE FROM 테이블 WHERE 조건;`
- [ ] C2 `DELETE FROM 테이블;` — 모든 행 삭제, 구조는 남음 (DROP과 차이)
- [ ] C3 WHERE에 하위 질의: `DELETE FROM 사원 WHERE 이름 IN (SELECT ...);`

### D. SELECT 기본
- [ ] D1 `SELECT * FROM 테이블;`
- [ ] D2 `SELECT DISTINCT 속성` — 중복 제거 / `COUNT(DISTINCT 속성)`
- [ ] D3 `AS 별칭` — `SELECT AVG(상여금) AS 평균`
- [ ] D4 `테이블명.속성명` — 두 테이블에 같은 이름 속성이 있을 때

### E. WHERE 조건
- [ ] E1 비교 `= <> > < >= <=` (`<>` = 같지 않다)
- [ ] E2 논리 `NOT > AND > OR` 우선순위 (10-18 Q1)
- [ ] E3 `LIKE` — `%` 0글자 이상, `_` 1글자, `#` 숫자 1개 (10-18 Q2)
- [ ] E4 `BETWEEN a AND b` — 양 끝 포함
- [ ] E5 `IN (값들)` / `NOT IN`
- [ ] E6 `IS NULL` / `IS NOT NULL` (10-18 Q5)

### F. 정렬
- [ ] F1 `ORDER BY 속성 [ASC | DESC]` — 생략 시 ASC
- [ ] F2 `ORDER BY 부서 ASC, 이름 DESC` — 두 번째 기준은 첫 기준이 같을 때만 (10-18 Q12)

### G. 그룹
- [ ] G1 그룹 함수 `COUNT · SUM · AVG · MAX · MIN` (+ `STDDEV` 표준편차, `VARIANCE` 분산)
- [ ] G2 `COUNT(*)` vs `COUNT(속성)` — NULL 포함 여부
- [ ] G3 `GROUP BY 속성` — 그룹별 집계
- [ ] G4 `HAVING 조건` — 그룹에 대한 조건 (WHERE는 행, HAVING은 그룹)
- [ ] G5 `WHERE → GROUP BY → HAVING` 함께 쓰기 (시나공 169 예제 2)
- [ ] G6 실행 순서 FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

### H. 하위 질의 (서브쿼리)
- [ ] H1 `WHERE 이름 = (SELECT ...)` — 결과가 1개일 때
- [ ] H2 `IN (SELECT ...)` / `NOT IN (SELECT ...)`
- [ ] H3 `> ALL` = > MAX, `< ALL` = < MIN (10-18 Q11, 시나공 167 예제 3)
- [ ] H4 `> ANY` = > MIN, `= ANY` = IN
- [ ] H5 `WHERE 성적 > (SELECT AVG(성적) FROM ...)` — 집계 서브쿼리 (2023-1)

### I. 집합 연산
- [ ] I1 `UNION` (중복 제거) / `UNION ALL` (중복 유지)
- [ ] I2 `INTERSECT` 교집합 / `EXCEPT`(MINUS) 차집합
- [ ] I3 두 SELECT의 속성 **개수 · 타입이 같아야** 함

### J. JOIN
- [ ] J1 `FROM A, B WHERE A.x = B.x` — WHERE 방식 EQUI JOIN
- [ ] J2 `A INNER JOIN B ON A.x = B.x`
- [ ] J3 `A NATURAL JOIN B` — 공통 속성 한 번만 표시
- [ ] J4 `A JOIN B USING(속성)`
- [ ] J5 `LEFT / RIGHT / FULL OUTER JOIN ... ON` — 짝 없는 쪽 NULL 붙여 추가
- [ ] J6 `CROSS JOIN` — 행 수 곱 (조건 없는 INNER = CROSS) (10-18 Q8)
- [ ] J7 용어: THETA JOIN(=, ≠, <, ≤ ...) ⊃ EQUI JOIN(=) / NATURAL = EQUI에서 중복 속성 제거

## 📖 스텝별 설명

### Step 2-1. INSERT — 새 행(튜플) 넣기

기출: 시나공 160 (실기 24.7, 23.7) · 2024-2 빈칸 (**VALUES**, **SELECT**)

#### ① 뼈대

```sql
INSERT INTO 테이블명 (속성1, 속성2, ...)
VALUES (값1, 값2, ...);
```

- 읽는 법: **"테이블 안으로(INTO) 이 값들(VALUES)을 넣어라"**
- **INTO** + **VALUES** 짝꿍 (빈칸 단골)
- 결과: 테이블에 **행이 하나 늘어남**. 열(구조)은 그대로 (열 늘리기는 ALTER ... ADD)

#### ② 형식 1 — 속성을 골라서 넣기

```sql
INSERT INTO 사원 (이름, 부서) VALUES ('홍승현', '인터넷');
```

- **짝 맞추기 규칙**: 앞 괄호 속성 ↔ 뒤 괄호 값이 **순서대로 1:1** (이름 ↔ '홍승현', 부서 ↔ '인터넷')
  - **개수**와 **타입**이 맞아야 함 (속성 2개 · 값 3개 → 오류, 숫자 칸에 '홍길동' → 오류)
  - 속성 순서는 테이블 정의 순서와 **달라도 됨**. `(부서, 이름) VALUES ('인터넷', '홍승현')`도 OK
- **안 적은 속성**(생일 · 주소 · 기본급)은? (Step 1-1 연결)
  - DEFAULT 있음 → 기본값
  - DEFAULT 없음 → **NULL**
  - 그 속성이 **NOT NULL**이거나 **PK** → **INSERT 자체가 거부**

```
<사원> 실행 후
이름    | 부서   | 생일 | 주소 | 기본급
...기존 행들...
홍승현  | 인터넷 | NULL | NULL | NULL   ← 추가된 행
```

#### ③ 형식 2 — 속성명 생략, 전부 넣기

```sql
INSERT INTO 사원 VALUES ('장보고', '기획', #05/03/73#, '홍제동', 90);
```

- 속성 목록을 **통째로 생략** = "모든 속성을, CREATE 때 정한 **순서대로**"
- 값의 개수 = **속성 개수와 정확히 같아야** 함 (<사원> 5개 → 값 5개)
- 비울 칸은 **NULL을 직접 적어** 자리를 채움: `VALUES ('장보고', '기획', NULL, '홍제동', 90)` → DEFAULT가 아니라 **NULL** (S1-4)
- 시나공 표기: 문자 `'작은따옴표'`, 숫자 따옴표 없음(90), 날짜 `#05/03/73#` (Access 문법. 답에 `'1973-05-03'`로 써도 의미는 같음)

#### ④ 형식 3 — 다른 테이블의 검색 결과를 통째로 넣기

```sql
INSERT INTO 편집부원 (이름, 생일, 주소, 기본급)
SELECT 이름, 생일, 주소, 기본급
FROM 사원
WHERE 부서 = '편집';
```

- **VALUES 자리에 SELECT**. VALUES = 값을 손으로 직접 적을 때, SELECT = 다른 테이블에서 퍼올 때 → 2024-2 빈칸 ② = **SELECT**
- **여러 행이 한 번에** 들어감 (SELECT 결과 3행 → 3행 삽입)

```
<사원> 중 부서='편집'          →     <편집부원>에 3행 추가
황진이 | 07/21/75 | 합정동 | 100      황진이 | 07/21/75 | 합정동 | 100
김선달 | 10/22/73 | 망원동 | 90       김선달 | 10/22/73 | 망원동 | 90
장길산 | 03/11/67 | 상암동 | 120      장길산 | 03/11/67 | 상암동 | 120
```

- 짝 맞추기 규칙 동일: INSERT 쪽 속성 4개 ↔ SELECT 쪽 속성 4개가 순서대로 1:1. **이름이 달라도** 순서 · 타입만 맞으면 됨
- `편집부원` 테이블은 **이미 있어야** 함 (INSERT는 DML, 테이블을 만들어 주지 않음)

#### ⑤ 함정 정리

- `INSERT 사원 VALUES ...` ❌ → **INTO** 필수 (빈칸 단골)
- `VALUES (SELECT ...)` ❌ → VALUES와 SELECT는 **둘 중 하나**
- 개수 불일치 → 오류 (형식 2에서 속성 하나 빼먹기 쉬움)
- **제약조건 위반 → 거부** (Step 1): PK 중복·NULL (S1-3), 외래키에 부모에 없는 값, CHECK 범위 밖
- "INSERT 후 COUNT(*)는?" 류에서 거부된 INSERT는 **행이 안 늘어난다**

### Step 2-2. UPDATE — 이미 있는 행의 칸 값 고치기

기출: 시나공 162 (실기 24.7, 21.7) · 2024-2 빈칸 (**SET**) · 10-18 Q15

#### ① 뼈대

```sql
UPDATE 테이블명
SET 속성 = 값 [, 속성 = 값, ...]
[WHERE 조건];
```

- 읽는 법: **"이 테이블을 고쳐라(UPDATE), 이 칸을 이 값으로 맞춰서(SET), 이 조건의 행만(WHERE)"**
- **UPDATE + SET** 짝꿍 (빈칸 단골). INSERT의 INTO/VALUES 자리에 해당
- 결과: **행 수는 그대로**, 조건에 맞는 행의 **칸 값만** 바뀐다
- 엑셀로 치면 필터를 걸고 보이는 셀만 값 덮어쓰기

> 시나공 160~162용 <사원>
> ```
> 이름   | 부서   | 생일     | 주소   | 기본급
> 홍길동 | 기획   | 04/05/61 | 망원동 | 120
> 임꺽정 | 인터넷 | 01/09/69 | 성산동 | 80
> 황진이 | 편집   | 07/21/75 | 연희동 | 100
> 김선달 | 편집   | 10/22/73 | 망원동 | 90
> 성춘향 | 기획   | 02/20/64 | 망원동 | 100
> 장길산 | 편집   | 03/11/67 | 상암동 | 120
> 일지매 | 기획   | 04/29/78 | 합정동 | 110
> 강호동 | 인터넷 | 12/11/80 | NULL   | 90
> ```

#### ② 칸 하나 고치기 (예제 1)

```sql
UPDATE 사원 SET 주소 = '수색동' WHERE 이름 = '홍길동';
```

```
실행 전                         실행 후
홍길동 | 기획 | ... | 망원동     홍길동 | 기획 | ... | 수색동
```

- 바뀐 건 홍길동 행의 주소 칸 **하나**뿐. 다른 행 · 다른 칸은 그대로

#### ③ 여러 칸 + 자기 자신 기준 계산 (예제 2)

```sql
UPDATE 사원
SET 부서 = '기획', 기본급 = 기본급 + 5
WHERE 이름 = '황진이';
```

```
실행 전: 황진이 | 편집 | ... | 100
실행 후: 황진이 | 기획 | ... | 105
```

- 여러 칸은 **쉼표(,)** 로 나열. `SET 부서='기획' AND 기본급=...` ❌ (AND는 WHERE에서 조건을 이을 때 쓴다)
- `기본급 = 기본급 + 5` → 오른쪽 `기본급`은 **바뀌기 전 값**(100), 거기에 5를 더해 왼쪽 칸에 넣는다
- "5만원 인상" → **+5** (단위가 만원). "10% 인상" → `기본급 = 기본급 * 1.1`

**왜 오른쪽은 옛날 값?** SET은 "새 값을 계산해서 → 칸에 넣는" 순서라서, 계산하는 순간엔 아직 옛날 값이 칸에 들어 있다.

#### ④ WHERE 생략 = 모든 행 / 여러 문장은 차례대로 (10-18 Q15)

```sql
UPDATE 사원 SET 기본급 = 기본급 + 10;   -- WHERE 없음 → 8명 전원 +10
```

- WHERE를 빼면 **모든 행**이 바뀐다 (DELETE와 같은 원리)
- UPDATE를 **여러 번** 실행하면, 두 번째 문장은 **첫 번째로 이미 바뀐 표**를 기준으로 조건을 다시 본다

```sql
UPDATE 사원 SET 부서 = '편집' WHERE 부서 = '기획';   -- ① 기획 3명 → 편집
UPDATE 사원 SET 기본급 = 0 WHERE 부서 = '편집';      -- ② 원래 편집 3명 + ①에서 넘어온 3명 = 6명
```

**왜?** SQL 문장은 한 줄씩 실행되고 결과가 바로 테이블에 반영된다. ②는 "처음 표"가 아니라 "①이 끝난 표"를 본다.

#### ⑤ 함정 정리

- `UPDATE 사원 부서 = '기획'` ❌ → **SET** 필수
- `UPDATE 사원.부서 SET ...` ❌ → UPDATE 뒤엔 **테이블명**, 칸 이름은 SET 뒤에
- 칸 크기·타입 바꾸기는 UPDATE가 아니라 **ALTER** (S0-2: "뭐가 들어 있나"는 UPDATE, "뭘 담을 수 있나"는 ALTER)
- **제약조건 위반 → 거부**: PK를 다른 행과 같은 값으로 고치기 (S1-14), NOT NULL 칸을 NULL로, CHECK 범위 밖
- 외래키가 보고 있는 부모 값을 고치면 → `ON UPDATE` 옵션(CASCADE / SET NULL / RESTRICT)에 따라 처리 (Step 1-1 ⑤)

### Step 2-3. DELETE — 행 통째로 지우기

기출: 시나공 161 (실기 23.4, 20.10) · Step 1-3 삭제 3형제 연결

#### ① 뼈대

```sql
DELETE FROM 테이블명 [WHERE 조건];
```

- 읽는 법: **"이 테이블에서(FROM) 이 조건의 행을 지워라"**
- **DELETE + FROM** 짝꿍. `DELETE 사원 WHERE ...` ❌
- 지우는 단위는 언제나 **행 전체**. DELETE 뒤에 칸 이름 ❌

#### ② 세 가지 예제 (시나공 161)

```sql
DELETE FROM 사원 WHERE 이름 = '임꺽정';   -- 예제 1: 1행 삭제
DELETE FROM 사원 WHERE 부서 = '인터넷';   -- 예제 2: 임꺽정·강호동 2행 삭제
DELETE FROM 사원;                         -- 예제 3: 전부 삭제, 구조는 남음
```

```
예제 2 실행 후 <사원>: 8행 → 6행
이름   | 부서 | ...
홍길동 | 기획 |
황진이 | 편집 |
김선달 | 편집 |
성춘향 | 기획 |
장길산 | 편집 |
일지매 | 기획 |
```

- 예제 3 후 `SELECT * FROM 사원;` → **0행**이 나온다 (오류 아님). DROP이었다면 "테이블 없음" 오류

#### ③ 칸 하나만 비우고 싶다면 → UPDATE

```sql
DELETE 주소 FROM 사원 WHERE 이름 = '홍길동';         -- ❌
UPDATE 사원 SET 주소 = NULL WHERE 이름 = '홍길동';   -- ✅
```

**왜?** 행은 "한 사람의 기록 한 장"이다. DELETE는 그 종이를 **찢어 버리는** 것이고, 칸 하나를 지우는 건 종이는 그대로 두고 **고쳐 쓰는** 것이라 UPDATE다.

#### ④ WHERE에 하위 질의

```sql
DELETE FROM 사원
WHERE 이름 IN (SELECT 이름 FROM 여가활동 WHERE 취미 = '씨름');
```

- 괄호 안 SELECT가 **먼저** 실행 → 결과(임꺽정)를 받아서 바깥 DELETE가 지운다 (자세한 건 2-4 ⑧)

#### ⑤ 함정 정리

- 외래키: **부모 행을 지우면** 자식 쪽 `ON DELETE` 옵션대로 → CASCADE(자식도 삭제) / SET NULL(자식 칸 NULL) / RESTRICT(자식 있으면 **그 행만** 거부, S1-8)
- `DELETE FROM 사원;` vs `TRUNCATE TABLE 사원;` → 결과는 같아 보여도 DELETE는 **DML · ROLLBACK ✅**, TRUNCATE는 **DDL · ROLLBACK ❌** (S1-9)
- "DELETE 후 COUNT(*)는?" → 지워진 행 수만큼 줄어든 값

### Step 2-4. WHERE 조건 전부 — 행을 골라내는 체

기출: 시나공 165·167 (실기 25.11, 25.4, 22.7, 21.7, 20.7) · 10-18 Q1 · Q2 · Q3 · Q4 · Q5 · Q11

> 시나공 164~167용 <사원> (이후 WHERE · 그룹 예제는 이 표)
> ```
> 이름   | 부서   | 생일     | 주소   | 기본급
> 홍길동 | 기획   | 04/05/61 | 망원동 | 120
> 임꺽정 | 인터넷 | 01/09/69 | 서교동 | 80
> 황진이 | 편집   | 07/21/75 | 합정동 | 100
> 김선달 | 편집   | 10/22/73 | 망원동 | 90
> 성춘향 | 기획   | 02/20/64 | 대흥동 | 100
> 장길산 | 편집   | 03/11/67 | 상암동 | 120
> 일지매 | 기획   | 04/29/78 | 연남동 | 110
> 강건달 | 인터넷 | 12/11/80 | NULL   | 90
> ```
> <여가활동>: 김선달 당구 10 / 성춘향 나이트댄스 5 / 일지매 태껸 15 / 임꺽정 씨름 8

WHERE는 **체(거름망)** 다. 각 행을 하나씩 체에 올려서 조건이 **참(TRUE)** 인 행만 통과시킨다. 거짓(FALSE)이나 **모름(UNKNOWN)** 인 행은 탈락.

#### ① 비교 연산자

- `=` 같다 · `<>` 같지 않다 · `>` `<` `>=` `<=`
- `<>`가 "같지 않다" (`!=`도 대부분 DB에서 되지만 시험 표기는 **`<>`**)
- 문자는 `'작은따옴표'`, 숫자는 그대로: `WHERE 부서 = '기획'`, `WHERE 기본급 >= 100`

```sql
SELECT * FROM 사원 WHERE 부서 = '기획';   -- 홍길동 · 성춘향 · 일지매 (3행)
```

#### ② 논리 연산자와 우선순위 — NOT > AND > OR (10-18 Q1)

```sql
SELECT * FROM 사원 WHERE 부서 = '기획' AND 주소 = '대흥동';   -- 성춘향 1행
```

- AND = 둘 다 참, OR = 하나만 참이어도, NOT = 뒤집기
- **괄호가 없으면 NOT → AND → OR 순서로 묶인다** (곱셈이 덧셈보다 먼저인 것과 같음)

```sql
WHERE 부서 = '편집' OR 부서 = '기획' AND 기본급 >= 110
-- 실제 묶임: 부서='편집' OR (부서='기획' AND 기본급>=110)
-- → 편집 3명 전부 + 기획 중 110 이상(홍길동 120, 일지매 110) = 5행

WHERE (부서 = '편집' OR 부서 = '기획') AND 기본급 >= 110
-- → 편집·기획 중 110 이상: 홍길동 · 장길산 · 일지매 = 3행
```

**왜 AND가 먼저?** AND는 "곱셈", OR는 "덧셈"처럼 동작하도록 정해 둔 규칙이다 (참=1, 거짓=0으로 보면 AND=곱, OR=합). 시험은 **괄호 없는 식을 일부러** 낸다 → 머릿속에서 AND 쪽에 괄호를 먼저 쳐라.

#### ③ BETWEEN — 양 끝 포함 (10-18 Q4)

```sql
SELECT * FROM 사원 WHERE 생일 BETWEEN #01/01/69# AND #12/31/73#;
-- 임꺽정(01/09/69) · 김선달(10/22/73) = 2행
```

- `BETWEEN a AND b` = `>= a AND <= b` → **양 끝 포함**
- `NOT BETWEEN a AND b` = `< a OR > b` → **양 끝 제외** (Q4 함정)
- 작은 값을 앞에: `BETWEEN 120 AND 100` → 0행 (뒤집으면 아무것도 안 나옴)

#### ④ 날짜 경계 — `>` vs `>=`, 그리고 "9월 30일 0시" 문제

- **날짜만**(DATE) 있는 칸: `<= '2026-09-30'` → 9월 30일 **포함** ✅
- **날짜+시각**(DATETIME) 칸: `'2026-09-30'`은 사실 **'2026-09-30 00:00:00'**

```
주문일시
2026-09-30 00:00:00   ← <= '2026-09-30' 통과
2026-09-30 14:20:00   ← <= '2026-09-30' 탈락!  (0시보다 늦으니까)
2026-10-01 09:00:00   ← 탈락
```

- "9월까지 주문" 을 안전하게 쓰려면 → `주문일시 < '2026-10-01'` (**다음 날 0시 미만**)
- BETWEEN도 같은 함정: `BETWEEN '2026-09-01' AND '2026-09-30'` → 9월 30일 0시 **딱 그 순간까지만**
- 문제 읽는 법
  - "이상 / 이하 / 부터 / 까지" → **포함** (`>=`, `<=`)
  - "초과 / 미만 / 이후 / 이전" → **제외** (`>`, `<`)
  - 결과 행 수 문제면 **경계값과 똑같은 행**이 있는지부터 확인

**왜 시각이 끼면 틀어지나?** 날짜만 적으면 DB는 그 날의 **시작 순간(0시 0분 0초)** 이라고 해석한다. "30일"을 하루 전체가 아니라 **한 점**으로 보는 것.

#### ⑤ LIKE — 패턴 찾기 (10-18 Q2)

```sql
SELECT * FROM 사원 WHERE 이름 LIKE '김%';   -- 김선달 1행
```

- `%` = 0글자 이상 아무거나 · `_` = 딱 1글자 · `#` = 숫자 1개 (시나공 표)
- `'김%'` 김으로 시작 / `'%동'` 동으로 끝 / `'%길%'` 길 포함 / `'_길_'` 3글자이고 가운데가 길
  - `'%길%'` → 홍길동 · 장길산 / `'_길_'` → 홍길동 · 장길산 (둘 다 3글자)
- `'%S_'` → 끝에서 **두 번째** 글자가 S (`_`가 마지막 한 글자를 먹음)
- LIKE 없이 `= '김%'` ❌ → 진짜로 "김%"라는 글자를 찾는다

#### ⑥ IN — OR 묶음 (10-18 Q3)

```sql
WHERE 주소 IN ('망원동', '합정동')
-- = WHERE 주소 = '망원동' OR 주소 = '합정동'  → 홍길동 · 황진이 · 김선달 (3행)
WHERE 주소 NOT IN ('망원동', '합정동')     -- 나머지 (단, 주소 NULL인 강건달은 탈락 → ⑦)
```

- 괄호 안에 SELECT도 가능 → ⑧

#### ⑦ NULL — `= NULL`은 안 된다 (10-18 Q5)

```sql
SELECT * FROM 사원 WHERE 주소 IS NULL;      -- 강건달 1행
SELECT * FROM 사원 WHERE 주소 = NULL;       -- 0행 (오류 아님!)
SELECT * FROM 사원 WHERE 주소 IS NOT NULL;  -- 7행
```

- NULL = "**모름**". 모르는 값과 비교하면 결과도 **모름(UNKNOWN)** → 체를 통과 못 함
- 그래서 NULL 확인은 반드시 **`IS NULL` / `IS NOT NULL`**
- `주소 <> '망원동'` 에도 강건달은 **안 나온다** (모름 ≠ 망원동? → 모름)

**왜 = NULL이 0행?** "강건달의 주소가 NULL과 같나?"는 "모르는 것이 모르는 것과 같나?"라는 질문이라 답이 "모름"이다. WHERE는 **확실한 참**만 통과시킨다.

#### ⑧ 하위 질의(서브쿼리) — 괄호 안을 먼저 (시나공 167 · 10-18 Q3 · Q11)

```sql
-- 예제 1: 결과가 1개 → = 사용
SELECT 이름, 주소 FROM 사원
WHERE 이름 = (SELECT 이름 FROM 여가활동 WHERE 취미 = '나이트댄스');
-- 괄호 = 성춘향 → 성춘향 | 대흥동

-- 예제 2: 결과가 여러 개 → IN / NOT IN
SELECT * FROM 사원 WHERE 이름 NOT IN (SELECT 이름 FROM 여가활동);
-- 괄호 = 김선달·성춘향·일지매·임꺽정 → 나머지 홍길동 · 황진이 · 장길산 · 강건달

-- 예제 3: ALL
SELECT 이름, 기본급, 주소 FROM 사원
WHERE 기본급 < ALL (SELECT 기본급 FROM 사원 WHERE 주소 = '망원동');
-- 괄호 = 120, 90 → "둘 다보다 작다" = 90보다 작다 → 임꺽정 | 80 | 서교동
```

- 순서: **괄호 안 SELECT 먼저** → 그 결과를 바깥 WHERE의 값으로 사용
- 결과가 여러 개인데 `=` 쓰면 오류 → `IN`
- **ALL / ANY 외우기**
  - `> ALL` = 전부보다 크다 = **> MAX** / `< ALL` = **< MIN**
  - `> ANY` = 하나보다만 크면 됨 = **> MIN** / `< ANY` = **< MAX**
  - `= ANY` = **IN**
- 집계 서브쿼리 (2023-1): `WHERE 기본급 > (SELECT AVG(기본급) FROM 사원)` → 평균 101.25보다 큰 홍길동 · 장길산 · 일지매

#### ⑨ 함정 정리

- 괄호 없는 AND/OR → AND 먼저 묶기
- BETWEEN은 양 끝 **포함**, NOT BETWEEN은 양 끝 **제외**
- DATETIME 칸 + 날짜만 적은 조건 → 그 날 **0시**로 해석 ("까지"는 `< 다음날`)
- LIKE 없이 `%` 쓰면 그냥 글자
- `= NULL` / `<> NULL` → 0행. **IS NULL**
- 서브쿼리 결과 여러 개 → `=` ❌ `IN` ✅

### Step 2-5. 그룹 — 묶어서 세고 더하기

기출: 시나공 168·169 (실기 25.11, 24.7, 23.4, 22.10, 21.4) · 10-18 Q7

#### ① 그룹 함수 (집계 함수)

- `COUNT` 개수 · `SUM` 합 · `AVG` 평균 · `MAX` 최대 · `MIN` 최소
- `STDDEV` 표준편차 · `VARIANCE` 분산 → **이름과 뜻만** (실기 계산 출제 기록 없음)
- 여러 행을 넣으면 **값 하나**가 나온다

#### ② COUNT(*) vs COUNT(속성) — NULL을 세느냐 (G2)

```sql
SELECT COUNT(*)    FROM 사원;   -- 8   (행 자체를 셈)
SELECT COUNT(주소) FROM 사원;   -- 7   (주소 NULL인 강건달 제외)
SELECT COUNT(DISTINCT 주소) FROM 사원;   -- 6 (망원동 중복 제거, NULL 제외)
```

- `COUNT(*)` = **줄 수**. NULL이든 뭐든 줄이 있으면 센다
- `COUNT(속성)` = 그 칸에 **값이 있는** 줄만
- SUM · AVG · MAX · MIN도 **NULL은 빼고** 계산 → AVG는 **NULL 아닌 개수로 나눈다** (Q7 함정)

```
점수: 80, NULL, 100
SUM = 180 / AVG = 180 ÷ 2 = 90   (÷3 = 60 아님!)
```

**왜?** NULL은 0이 아니라 "모름"이라 더하지도 세지도 않는다. `COUNT(*)`만 예외인 건 칸을 보지 않고 **줄**을 보기 때문.

#### ③ GROUP BY — 같은 값끼리 묶기 (시나공 169 예제 1)

<상여금>
```
부서   | 이름   | 상여내역 | 상여금
기획   | 홍길동 | 연장근무 | 100
기획   | 일지매 | 연장근무 | 100
기획   | 최준호 | 야간근무 | 120
기획   | 장길산 | 특별근무 | 90
인터넷 | 강건달 | 특별근무 | 90
인터넷 | 서국현 | 특별근무 | 90
인터넷 | 박인식 | 연장근무 | 30
편집   | 김선달 | 특별근무 | 80
편집   | 황종근 | 연장근무 | 40
편집   | 성춘향 | 야간근무 | 80
편집   | 임꺽정 | 야간근무 | 80
편집   | 황진이 | 야간근무 | 50
```

```sql
SELECT 부서, AVG(상여금) AS 평균
FROM 상여금
GROUP BY 부서;
```

```
부서   | 평균
기획   | 102.5   (100+100+120+90) ÷ 4
인터넷 | 70      (90+90+30) ÷ 3
편집   | 66      (80+40+80+80+50) ÷ 5
```

- 엑셀의 **부분합 / 피벗**과 같다. 부서별 바구니에 행을 나눠 담고 바구니마다 집계
- SELECT에 쓸 수 있는 건 **GROUP BY에 쓴 속성 + 집계 함수**뿐. `SELECT 부서, 이름, AVG(...) GROUP BY 부서` ❌ (바구니 하나에 이름이 여러 개라 하나를 못 고름)

#### ④ HAVING — 바구니에 거는 조건 (시나공 169 예제 2)

```sql
SELECT 부서, COUNT(*) AS 사원수
FROM 상여금
WHERE 상여금 >= 100
GROUP BY 부서
HAVING COUNT(*) >= 2;
```

```
WHERE 통과 (상여금>=100): 홍길동 100 · 일지매 100 · 최준호 120  (전부 기획)
GROUP BY: 기획 바구니 3개
HAVING COUNT(*)>=2: 기획 3 ✅
결과 → 기획 | 3
```

- **WHERE = 행 거르기** (묶기 전) / **HAVING = 그룹 거르기** (묶은 후)
- 집계 함수 조건(`COUNT(*) >= 2`, `AVG(...) > 80`)은 **HAVING에만**. `WHERE COUNT(*) >= 2` ❌

#### ⑤ 실행 순서 (G6)

```
FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY
```

- WHERE가 GROUP BY보다 **먼저**라서 WHERE 시점엔 아직 바구니가 없다 → 집계 함수 못 씀
- SELECT의 별칭(`AS 평균`)은 SELECT 이후인 ORDER BY에서만 쓸 수 있다

#### ⑥ 함정 정리

- `COUNT(*)` 는 NULL 포함, `COUNT(속성)` 는 NULL 제외
- AVG는 NULL을 빼고 **남은 개수로** 나눔
- 집계 조건은 HAVING, 행 조건은 WHERE
- SELECT에 GROUP BY 안 한 일반 속성 ❌

### Step 2-6. 집합 연산 — 두 SELECT 결과를 위아래로 합치기

기출: 시나공 170 (실기 23.10) · 10-18 Q13

#### ① 뼈대

```sql
SELECT 속성1, 속성2 FROM 테이블A
UNION | UNION ALL | INTERSECT | EXCEPT
SELECT 속성1, 속성2 FROM 테이블B
[ORDER BY 속성];
```

- JOIN이 표를 **옆으로** 붙이는 거라면, 집합 연산은 결과를 **위아래로** 쌓는다
- 벤 다이어그램을 그대로 SQL로 옮긴 것

#### ② 네 가지

예제용
```
<A동아리>  이름        <B동아리>  이름
           홍길동                 성춘향
           성춘향                 일지매
           김선달                 임꺽정
```

```sql
SELECT 이름 FROM A동아리 UNION     SELECT 이름 FROM B동아리;
-- 홍길동 · 성춘향 · 김선달 · 일지매 · 임꺽정 (5행, 성춘향 한 번)

SELECT 이름 FROM A동아리 UNION ALL SELECT 이름 FROM B동아리;
-- 6행 (성춘향 두 번)

SELECT 이름 FROM A동아리 INTERSECT SELECT 이름 FROM B동아리;
-- 성춘향 (1행)

SELECT 이름 FROM A동아리 EXCEPT    SELECT 이름 FROM B동아리;
-- 홍길동 · 김선달 (2행)
```

- `UNION` 합집합, **중복은 한 번만**
- `UNION ALL` 합집합, **중복도 그대로** → 행 수 = A 행 수 + B 행 수
- `INTERSECT` 교집합 (둘 다 있는 것)
- `EXCEPT` 차집합 (A에만 있는 것). Oracle에선 **MINUS** (Q13)
  - **순서가 중요**: `B EXCEPT A` → 일지매 · 임꺽정. 앞 SELECT가 기준

**왜 UNION은 중복을 지우나?** 수학의 집합은 같은 원소를 두 번 갖지 않는다. 그 규칙을 따르는 게 UNION이고, "그냥 이어 붙이기만 해 줘"가 UNION ALL이다. (중복 제거 작업이 없는 UNION ALL이 더 빠르다)

#### ③ 규칙

- 두 SELECT의 **속성 개수와 타입이 같아야** 한다. `SELECT 이름, 부서 ... UNION SELECT 이름 ...` ❌
- 결과의 열 이름은 **첫 번째 SELECT**의 이름을 따른다
- ORDER BY는 **맨 끝에 한 번만** (전체 결과를 정렬)

#### ④ 다른 문법과 같은 효과 (Q13 · Q14 연결)

- `A EXCEPT B` ≈ `A LEFT JOIN B ... WHERE B.키 IS NULL` ≈ `WHERE 이름 NOT IN (SELECT 이름 FROM B)`
- `A INTERSECT B` ≈ `WHERE 이름 IN (SELECT 이름 FROM B)`

#### ⑤ 함정 정리

- 실행 결과 행 수: UNION은 **중복 빼고**, UNION ALL은 **단순 합**
- EXCEPT는 앞뒤를 바꾸면 결과가 달라짐
- 개수 · 타입 불일치 → 오류

### Step 2-7. JOIN — 두 표를 옆으로 붙이기

기출: 시나공 171~173 (실기 25.11, 25.4, 24.4, 21.7) · 10-18 Q8 · Q14 · 2025-3 JOIN 행 수

#### ① JOIN이 하는 일

- 두 테이블에서 **공통 속성 값이 같은 행끼리** 옆으로 이어 붙여 새 표를 만든다
- 엑셀의 **VLOOKUP**: 학생 표의 학과코드로 학과 표에서 학과명을 찾아와 옆에 붙이기

예제용 (시나공 173 <학생> + 설명용 <학과>에 eng 추가)
```
<학생>                         <학과>
학번 | 이름   | 학과코드        학과코드 | 학과명
15   | 고길동 | com            com      | 컴퓨터
16   | 이순신 | han            han      | 국어
17   | 김선달 | com            eng      | 영어     ← 학생 없음
19   | 아무개 | han
37   | 박치민 | NULL           ← 학과 없음
```

#### ② 분류 지도 (J7)

```
JOIN
├─ INNER JOIN (짝 있는 행만)
│   ├─ THETA JOIN : 조건이 =, ≠, <, ≤, >, ≥ 아무거나
│   │   └─ EQUI JOIN : 조건이 = 인 것  (속성 수 = 두 표 속성 합)
│   │       └─ NATURAL JOIN : EQUI에서 같은 속성을 한 번만 표시
│   └─ NON-EQUI JOIN : = 아닌 조건
├─ OUTER JOIN (짝 없는 행도 NULL 붙여서)
│   └─ LEFT / RIGHT / FULL
└─ CROSS JOIN (조건 없이 모든 조합, 행 수 = 곱)
```

#### ③ EQUI JOIN 세 가지 표기 (J1 · J3 · J4)

```sql
-- (가) WHERE 방식
SELECT 학번, 이름, 학생.학과코드, 학과명
FROM 학생, 학과
WHERE 학생.학과코드 = 학과.학과코드;

-- (나) INNER JOIN ... ON (J2)
SELECT 학번, 이름, 학생.학과코드, 학과명
FROM 학생 INNER JOIN 학과 ON 학생.학과코드 = 학과.학과코드;

-- (다) NATURAL JOIN — 이름이 같은 속성을 알아서 찾아 = 로 연결
SELECT 학번, 이름, 학과코드, 학과명 FROM 학생 NATURAL JOIN 학과;

-- (라) JOIN ... USING — 연결할 속성을 직접 지정
SELECT 학번, 이름, 학과코드, 학과명 FROM 학생 JOIN 학과 USING(학과코드);
```

```
결과 (넷 다 4행)
학번 | 이름   | 학과코드 | 학과명
15   | 고길동 | com      | 컴퓨터
16   | 이순신 | han      | 국어
17   | 김선달 | com      | 컴퓨터
19   | 아무개 | han      | 국어
```

- 박치민(학과코드 NULL)과 eng(영어)는 **짝이 없어서 빠진다**
- `학생.학과코드` 처럼 **테이블명.속성명**: 두 표 모두 학과코드가 있으니 어느 쪽인지 밝혀야 함 (D4)
- NATURAL / USING은 학과코드가 **한 번만** 나오므로 앞에 테이블명 안 붙임
- `SELECT *` 기준 열 수: EQUI(=)는 3+2 = **5열** (학과코드 2번) / NATURAL은 **4열**

**왜 박치민이 빠지나?** NULL은 "모름"이라 `NULL = 'com'`은 참이 아니다 (2-4 ⑦). INNER JOIN은 조건이 **참**인 짝만 붙인다.

#### ④ OUTER JOIN — 짝 없는 쪽도 살리기 (J5 · 시나공 173)

```sql
SELECT 학번, 이름, 학생.학과코드, 학과명
FROM 학생 LEFT OUTER JOIN 학과
ON 학생.학과코드 = 학과.학과코드;
```

```
LEFT (5행): INNER 4행 + 왼쪽(학생)에만 있는 박치민
15 | 고길동 | com  | 컴퓨터
16 | 이순신 | han  | 국어
17 | 김선달 | com  | 컴퓨터
19 | 아무개 | han  | 국어
37 | 박치민 | NULL | NULL
```

- **LEFT** = 왼쪽 표는 **전부** 살림, 짝 없으면 오른쪽 칸을 NULL로
- **RIGHT** = 오른쪽 표 전부 → INNER 4행 + `NULL | NULL | eng | 영어` = **5행**
- **FULL** = 양쪽 전부 → INNER 4행 + 박치민 + eng = **6행**
- "왼쪽"의 기준은 **JOIN이라는 단어의 왼쪽**에 적힌 표. `학과 RIGHT JOIN 학생` = `학생 LEFT JOIN 학과` (시나공 해설)
- 짝 없는 행 찾기 (Q14): `학생 LEFT JOIN 학과 ... WHERE 학과.학과코드 IS NULL` → 박치민만

**행 수 공식**
- INNER = 짝 맞는 수
- LEFT = INNER + 왼쪽에서 짝 없는 행 수
- RIGHT = INNER + 오른쪽에서 짝 없는 행 수
- FULL = INNER + 양쪽 짝 없는 행 수

#### ⑤ CROSS JOIN — 모든 조합 (J6 · 10-18 Q8)

```sql
SELECT * FROM 학생 CROSS JOIN 학과;   -- = FROM 학생, 학과 (WHERE 없음)
```

- 학생 5행 × 학과 3행 = **15행**. 짝이 맞든 말든 전부 순서쌍
- **조건 없는 INNER JOIN = CROSS JOIN** (시나공 문장 그대로 출제 가능)
- 열 수는 **더하기** (3+2 = 5열), 행 수는 **곱하기**

#### ⑥ 한 테이블이 짝 행을 여러 개 가질 때

- 학과 com에 학생이 2명(고길동 · 김선달) → 컴퓨터 행이 결과에 **2번** 나온다
- JOIN 행 수 문제(2025-3)는 **키 값별로 (왼쪽 개수 × 오른쪽 개수)를 더하기**
  - com: 2×1 = 2 / han: 2×1 = 2 / NULL·eng: 0 → INNER 4행

#### ⑦ 함정 정리

- NULL 키는 INNER에서 **항상 탈락** (NULL = NULL도 참 아님)
- CROSS는 행 **곱**, 열 **합**
- LEFT/RIGHT의 기준 = JOIN 단어 기준 왼쪽/오른쪽
- NATURAL은 같은 이름 속성을 **한 번만** 표시 / EQUI는 두 번
- 공통 속성은 `테이블명.속성명` 으로 구분 (NATURAL · USING 제외)
