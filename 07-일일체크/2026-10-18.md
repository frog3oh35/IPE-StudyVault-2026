> **오늘의 핵심 발견**: SELECT를 **읽는** 문제는 절반 넘게 맞혔고, 테이블·데이터·권한을 **바꾸는 명령문**(ALTER · DROP RESTRICT · VIEW · UPDATE · GRANT/REVOKE)은 4문제 모두 몰랐음. 사용자 말: "이쯤 되니 내가 DCL DDL (하나 더 있는데 뭐더라) 어느 쪽을 아예 모르는지 느낌이 오지" → 생각이 안 났던 하나는 **DML**.

### SQL 명령어 3분류 한눈에

| 분류 | 뜻 | 명령어 | 대상 |
|------|-----|--------|------|
| **DDL** (Definition, 정의) | 테이블 **구조**를 만들고 바꾸고 없앰 | CREATE · ALTER · DROP · TRUNCATE | 테이블, 뷰, 인덱스 (그릇) |
| **DML** (Manipulation, 조작) | 테이블 안의 **데이터(행)**를 다룸 | SELECT · INSERT · UPDATE · DELETE | 행 (내용물) |
| **DCL** (Control, 제어) | **권한**을 주고 회수함 | GRANT · REVOKE (+ COMMIT · ROLLBACK은 TCL로 따로 분류하기도) | 사용자 |

- 짝으로 외우기: **DDL ↔ DML**: CREATE ↔ INSERT, ALTER ↔ UPDATE, DROP ↔ DELETE. 왼쪽은 그릇(구조), 오른쪽은 내용물(데이터)을 다룬다.

## Q1. 02-SQL-DB — 논리 연산자 우선순위 (AND / OR)

**문제**
[직원] 테이블

| 사번 | 부서 | 급여 |
|------|------|------|
| 101 | 영업 | 3000 |
| 102 | 개발 | 4500 |
| 103 | 영업 | 5000 |
| 104 | 인사 | 2500 |
| 105 | 개발 | 3500 |

```sql
SELECT COUNT(*) FROM 직원
WHERE 부서 = '개발' OR 부서 = '영업' AND 급여 >= 4000;
```
결과는?

**보기**
1. 1
2. 2
3. 3
4. 4

**내 답**: 2 (오답)
**정답**: 3

**해설**
**AND가 OR보다 먼저** 계산된다. 그래서 조건은 `부서='개발' OR (부서='영업' AND 급여>=4000)`이 된다.
- 개발 → 102, 105 (급여 상관없음)
- 영업이면서 4000 이상 → 103
- 합계 3행

2라고 답한 것은 왼쪽부터 읽어서 `(개발 OR 영업) AND 급여>=4000`(102, 103)으로 계산했기 때문이다.

**연관 함정 지식**
- 우선순위: **NOT > AND > OR** (곱셈이 덧셈보다 먼저인 것과 같음. AND = 곱, OR = 합)
- 기출 2024-1회 18번이 같은 유형: `EMPNO > 100 AND SAL >= 3000 OR EMPNO = 200` → `(A AND B) OR C`로 묶어서 푼다.
- 의도대로 묶고 싶으면 괄호 `( )`를 쓴다. 문제에 괄호가 없으면 AND부터 묶어 놓고 시작한다.

## Q2. 02-SQL-DB — LIKE 와일드카드 (%S_)

**문제**
[상품] 테이블의 코드 컬럼 값: 'AS1', 'BS', 'CAS9', 'S2', 'ASK', 'XSS'

```sql
SELECT COUNT(*) FROM 상품
WHERE 코드 LIKE '%S_';
```
결과는?

**보기**
1. 3
2. 4
3. 5
4. 6

**내 답**: 4 (오답)
**정답**: 5

**해설**
`'%S_'` = (아무 글자 0개 이상) + S + (정확히 1글자) → **끝에서 두 번째 글자가 S**.

| 코드 | 끝에서 두 번째 | 결과 |
|------|--------------|------|
| AS1 | S | ✅ |
| BS | B (S가 마지막이라 뒤에 1글자가 없음) | ❌ |
| CAS9 | S | ✅ |
| S2 | S (`%`가 0글자) | ✅ |
| ASK | S | ✅ |
| XSS | S (X-**S**-S) | ✅ |

→ 5개. 놓치기 쉬운 것은 **S2**(`%`는 0글자도 됨)와 **XSS**(S가 두 개라 헷갈림)이다.

**연관 함정 지식**
- `_` = **정확히 1글자**, `%` = **0글자 이상**. 10-14에 낸 `'_a%'`(두 번째 글자가 a)와는 앞뒤가 반대인 패턴이다.
- 풀이 루틴: 패턴을 뒤에서부터 맞춘다. `_` 자리에 글자 하나를 지우고, 그다음 글자가 S인지 본다.
- `LIKE 'S%'`(S로 시작), `LIKE '%S'`(S로 끝남), `LIKE '%S%'`(S 포함), `LIKE '___'`(정확히 3글자)

## Q3. 02-SQL-DB — IN + 서브쿼리

**문제**
[학생]

| 학번 | 이름 | 학과코드 |
|------|------|---------|
| 1 | 김 | C01 |
| 2 | 이 | C02 |
| 3 | 박 | C03 |
| 4 | 최 | C01 |

[학과]

| 학과코드 | 학과명 | 건물 |
|---------|-------|------|
| C01 | 컴공 | 공학관 |
| C02 | 전자 | 공학관 |
| C03 | 경영 | 인문관 |

```sql
SELECT 이름 FROM 학생
WHERE 학과코드 IN (SELECT 학과코드 FROM 학과 WHERE 건물 = '공학관');
```
결과로 출력되는 이름은?

**보기**
1. 김, 최
2. 박
3. 김, 이, 최
4. 이

**내 답**: 김, 이, 최 (정답)
**정답**: 김, 이, 최

**해설**
서브쿼리 먼저 → 공학관 학과코드 = (C01, C02). 바깥 쿼리는 `학과코드 IN ('C01', 'C02')` → 김, 이, 최.

**연관 함정 지식**
- 서브쿼리는 **안쪽부터** 풀어서 값 목록으로 바꾼 뒤 바깥 쿼리에 넣는다.
- `IN (목록)` = 목록 중 **하나라도** 같으면 참 (= `= ANY`와 같음).
- `NOT IN`은 목록에 NULL이 있으면 결과가 0행이 되는 함정이 있다(NULL과의 비교는 항상 UNKNOWN).
- 기출 2024-1회(`C IN (SELECT C FROM R2 WHERE D='k')`), 2024-3회(중첩 IN + GROUP BY HAVING)가 이 유형이다.

## Q4. 02-SQL-DB — NOT BETWEEN (경계값 포함 여부)

**문제**
[성적] 테이블의 점수 컬럼 값: 59, 60, 75, 80, 81, 90

```sql
SELECT COUNT(*) FROM 성적
WHERE 점수 NOT BETWEEN 60 AND 80;
```
결과는?

**보기**
1. 5
2. 4
3. 2
4. 3

**내 답**: 3 (정답)
**정답**: 3

**해설**
`BETWEEN 60 AND 80` = `점수 >= 60 AND 점수 <= 80` (**양 끝 포함**) → 60, 75, 80. NOT이므로 나머지 59, 81, 90 → 3.

**연관 함정 지식**
- BETWEEN은 **양 끝값을 포함**한다. NOT BETWEEN은 `점수 < 60 OR 점수 > 80`.
- `BETWEEN 80 AND 60`처럼 작은 값을 뒤에 쓰면 결과가 0행이다(순서 주의).

## Q5. 02-SQL-DB — NULL 비교 (= NULL vs IS NULL)

**문제**
[사원] 테이블의 bonus 컬럼 값: 100, NULL, 200, NULL, 0

```sql
(가) SELECT COUNT(*) FROM 사원 WHERE bonus = NULL;
(나) SELECT COUNT(*) FROM 사원 WHERE bonus IS NULL;
```
(가), (나)의 결과는 각각?

**보기**
1. 2, 2
2. 3, 2
3. 0, 3
4. 0, 2

**내 답**: 모름 — "is와 =의 차이를 솔직히 모르겠다" (오답)
**정답**: 0, 2

**해설**
- NULL은 "값이 **없음/모름**"이라는 상태이지 값이 아니다. 그래서 `bonus = NULL`은 "모르는 값과 같은가?"를 묻는 것이 되고, 결과는 참도 거짓도 아닌 **UNKNOWN**이다. WHERE는 **참인 행만** 통과시키므로 (가)는 **0행**.
- NULL인지 확인하려면 전용 문법 **`IS NULL`**을 써야 한다 → (나)는 NULL 2개 → **2**.
- 0은 NULL이 아니다(0이라는 값이 있음). 그래서 (나)는 3이 아니다.

**연관 함정 지식**
- NULL이 아닌 행: `IS NOT NULL` (`<> NULL`이나 `!= NULL`도 항상 0행)
- NULL과 하는 산술 연산은 결과가 NULL이다: `100 + NULL = NULL`
- 집계함수와 연결: COUNT(*)만 NULL 행을 세고, COUNT(컬럼)·SUM·AVG 등은 NULL을 무시한다 (기존 🔴→🟢 개념).
- Q14의 `WHERE o.고객id IS NULL`도 같은 문법이다. 오늘 Q14를 맞혔으니 "NULL 확인은 IS NULL"을 Q5에도 적용하면 된다.

## Q6. 02-SQL-DB — DCL (REVOKE ... CASCADE)

**문제**
다음 SQL을 순서대로 실행했다.

```sql
① (DBA) GRANT UPDATE ON 상품 TO kim WITH GRANT OPTION;
② (kim) GRANT UPDATE ON 상품 TO lee;
③ (DBA) REVOKE UPDATE ON 상품 FROM kim CASCADE;
```
③ 실행 후 kim과 lee의 상품 UPDATE 권한 상태는?

**보기**
1. kim 회수, lee 유지
2. kim 유지, lee 회수
3. kim, lee 모두 회수
4. 둘 다 유지 (kim은 GRANT OPTION만 잃음)

**내 답**: 모름 — "이거 아예 모른다" (오답)
**정답**: kim, lee 모두 회수

**해설**
- ① DBA가 kim에게 UPDATE 권한을 주면서 **WITH GRANT OPTION**(받은 권한을 남에게 다시 줄 수 있는 자격)도 줬다.
- ② 그래서 kim이 lee에게 UPDATE 권한을 다시 줄 수 있었다. 권한 흐름: DBA → kim → lee.
- ③ `REVOKE ... CASCADE` = kim의 권한을 회수하면서 **kim이 나눠 준 권한까지 연쇄로** 회수한다. → kim, lee 모두 회수.

**연관 함정 지식**
- 문법 모양: `GRANT 권한 ON 테이블 TO 사용자 [WITH GRANT OPTION];` / `REVOKE 권한 ON 테이블 FROM 사용자 [CASCADE];` (**GRANT는 TO, REVOKE는 FROM**. 빈칸 문제로 자주 나옴)
- `REVOKE GRANT OPTION FOR UPDATE ON 상품 FROM kim;` = 권한은 그대로 두고 **다시 줄 수 있는 자격만** 회수 (보기 4번)
- CASCADE라는 단어는 DROP에서도 쓰인다. 뜻은 똑같이 "**연쇄로 같이**"이다 (Q10 참고).

## Q7. 02-SQL-DB — GROUP BY + HAVING + 집계함수 NULL

**문제**
[주문] 테이블

| 고객 | 금액 |
|------|------|
| A | 100 |
| B | 200 |
| A | 300 |
| C | 50 |
| B | 100 |
| A | NULL |
| C | 150 |

```sql
SELECT 고객, COUNT(금액) FROM 주문
GROUP BY 고객
HAVING COUNT(*) >= 2 AND SUM(금액) >= 250;
```
결과는?

**보기**
1. A 3, B 2
2. A 2, B 2, C 2
3. A 3, B 2, C 2
4. A 2, B 2

**내 답**: A 2, B 2 (정답)
**정답**: A 2, B 2

**해설**
| 고객 | COUNT(*) | COUNT(금액) | SUM(금액) | HAVING |
|------|---------|------------|----------|--------|
| A | 3 | 2 (NULL 제외) | 400 | ✅ |
| B | 2 | 2 | 300 | ✅ |
| C | 2 | 2 | 200 | ❌ |

출력하는 것은 COUNT(금액)이라서 A는 3이 아니라 2이다.

**연관 함정 지식**
- HAVING 조건의 COUNT(*)와 SELECT의 COUNT(금액)이 **서로 다른 값**일 수 있다. 문제에서 어느 쪽인지 다시 확인한다.
- 실행 순서: FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY

## Q8. 02-SQL-DB — INNER JOIN / CROSS JOIN 행 수

**문제**
[사원]

| 사번 | 부서코드 |
|------|---------|
| 1 | D1 |
| 2 | D2 |
| 3 | D1 |
| 4 | NULL |
| 5 | D4 |

[부서]

| 부서코드 | 부서명 |
|---------|-------|
| D1 | 영업 |
| D2 | 개발 |
| D3 | 인사 |

```sql
(가) SELECT * FROM 사원 s INNER JOIN 부서 d ON s.부서코드 = d.부서코드;
(나) SELECT * FROM 사원 CROSS JOIN 부서;
```
(가), (나)의 결과 행 수는 각각?

**보기**
1. 5, 15
2. 3, 15
3. 4, 15
4. 3, 8

**내 답**: (나) 모름("크로스 조인이 뭔지 몰라") → (가)만 다시 물었을 때 4 (오답)
**정답**: 3, 15

**해설**
- (가) INNER JOIN = **양쪽에 모두 짝이 있는 행만** 남긴다.
  - 1(D1) ✅, 2(D2) ✅, 3(D1) ✅
  - 4(NULL) ❌: NULL은 어떤 값과도 같지 않다 (Q5와 같은 원리, `NULL = 'D1'`은 UNKNOWN)
  - 5(D4) ❌: 부서 테이블에 D4가 없음
  - D3(인사)는 사원 쪽에 짝이 없어서 버려짐 → **3행**
- (나) CROSS JOIN(교차 조인, 카티션 곱) = 조건 없이 **모든 조합** → 5 × 3 = **15행**

**연관 함정 지식**
- 4라고 답한 것은 NULL이나 D4 중 하나를 짝이 있는 것으로 센 것으로 보인다. JOIN의 `ON a = b`도 결국 `=` 비교라서, **NULL은 절대 매칭되지 않는다**.
- 조인 행 수 비교 (같은 데이터 기준):
  - INNER 3
  - LEFT 5 (사원 4·5가 부서 NULL로 추가)
  - RIGHT 4 (D3 인사가 추가)
  - FULL 6
  - CROSS 15
- 정처기에서의 CROSS JOIN: `CROSS JOIN` 키워드 자체는 실기에 드물다. 하지만 관계대수 **교차곱(×)**은 출제 범위이고, `FROM A, B`처럼 WHERE 없이 테이블만 나열해도 교차곱이 된다. 교차곱의 차수(열 수)는 **더하기**, 카디널리티(행 수)는 **곱하기**.

## Q9. 02-SQL-DB — ALTER TABLE (ADD / DROP)

**문제**
[학생] 테이블에 연락처 컬럼을 추가하고, 비고 컬럼을 삭제하려고 한다.

```sql
ALTER TABLE 학생 ( ① ) 연락처 VARCHAR(20);
ALTER TABLE 학생 ( ② ) 비고;
```
①, ②에 들어갈 키워드는?

**보기**
1. INSERT, DELETE
2. MODIFY, DROP
3. ADD, DELETE
4. ADD, DROP

**내 답**: 모름 — "INSERT, MODIFY, ADD 쪽은 잘 모른다. DROP이 찐 삭제라는 것 쯤만 알아" (오답, ②는 알고 있었음)
**정답**: ADD, DROP

**해설**
ALTER TABLE은 **구조(컬럼)**를 바꾸는 DDL이라서, 그 안에서도 구조용 단어를 쓴다.
- 컬럼 추가: `ALTER TABLE 학생 ADD 연락처 VARCHAR(20);`
- 컬럼 삭제: `ALTER TABLE 학생 DROP COLUMN 비고;` (`DROP 비고`로 쓰기도 함)
- 컬럼 타입 변경: `ALTER TABLE 학생 MODIFY 연락처 VARCHAR(30);` (Oracle·MySQL. 표준은 `ALTER COLUMN`)

**연관 함정 지식**
- **INSERT · DELETE는 행(데이터)용 DML**이라서 ALTER 안에 들어갈 수 없다.
  - INSERT = 행 추가 (`INSERT INTO 학생 VALUES (...)`)
  - DELETE = 행 삭제 (`DELETE FROM 학생 WHERE ...`)
- 구조 vs 데이터:

| 하고 싶은 일 | 구조(DDL) | 데이터(DML) |
|-------------|----------|------------|
| 만들기/추가 | CREATE, ALTER ... ADD | INSERT INTO ... VALUES |
| 바꾸기 | ALTER ... MODIFY | UPDATE ... SET |
| 지우기 | DROP, ALTER ... DROP | DELETE FROM |

- 삭제 3형제: **DROP**(테이블 자체를 없앰) / **TRUNCATE**(구조는 남기고 데이터 전부 삭제, 되돌리기 불가) / **DELETE**(WHERE로 고른 행만 삭제, ROLLBACK 가능)

## Q10. 02-SQL-DB — DROP TABLE ... RESTRICT (뷰가 참조할 때)

**문제**
다음을 순서대로 실행했다.

```sql
CREATE VIEW v_영업 AS
  SELECT * FROM 사원 WHERE 부서 = '영업';

DROP TABLE 사원 RESTRICT;
```
DROP TABLE 실행 결과는?

**보기**
1. 사원만 삭제, 뷰는 남음
2. 삭제가 거부됨
3. 사원과 뷰 모두 삭제
4. 데이터만 삭제

**내 답**: 사원만 삭제, 뷰는 남음 ("뷰랑 RESTRICT 몰라") (오답)
**정답**: 삭제가 거부됨

**해설**
- **뷰(VIEW)** = 실제 데이터를 따로 저장하지 않고, "사원 테이블에서 영업부만 보여 줘"라는 **SELECT문에 이름을 붙여 둔 가상 테이블**이다. v_영업을 조회할 때마다 사원 테이블에서 데이터를 가져온다. 그래서 v_영업은 사원 테이블에 **의존(참조)**한다.
- **RESTRICT** = "나를 참조하는 객체가 있으면 **삭제하지 마**" → v_영업이 사원을 참조하므로 DROP이 **거부**되고, 사원과 뷰 모두 그대로 남는다.
- **CASCADE**였다면 사원과 v_영업이 **함께** 삭제된다(보기 3).

**연관 함정 지식**
- 보기 1처럼 테이블만 지우고 뷰를 남기면, 뷰가 가리킬 테이블이 없어져 깨진다. 이런 상황을 막는 것이 RESTRICT다.
- 10-08 오답(참조 중이면 삭제 취소 → TRUNCATE로 오답)과 같은 개념이다. **RESTRICT = 거부, CASCADE = 연쇄 삭제**.
- 뷰 특징 (기출 단골): 논리적 독립성 제공, 보안(필요한 열만 노출), **ALTER로 정의 변경 불가**(DROP 후 다시 CREATE), 뷰 위에 또 뷰를 만들 수 있다, 원본 테이블이 삭제되면 뷰도 사용 불가.
- 참고: [[../02-SQL-DB/SQL-핵심]] "DROP VIEW + CASCADE"

## Q11. 02-SQL-DB — 서브쿼리 비교 연산자 (> ALL)

**문제**
[제품] 테이블

| 이름 | 가격 | 분류 |
|------|------|------|
| P1 | 100 | A |
| P2 | 300 | A |
| P3 | 250 | B |
| P4 | 400 | B |
| P5 | 350 | C |

```sql
SELECT 이름 FROM 제품
WHERE 가격 > ALL (SELECT 가격 FROM 제품 WHERE 분류 = 'A');
```
결과는?

**보기**
1. P2, P3, P4, P5
2. P3, P4, P5
3. P4
4. P4, P5

**내 답**: 모름 — "ALL의 의미를 모르겠어" (오답)
**정답**: P4, P5

**해설**
- 서브쿼리 → A 분류 가격 = (100, 300)
- `> ALL (100, 300)` = 목록의 **모든 값보다 커야** 함 = **최댓값(300)보다 커야** 함
- 300 초과: P4(400), P5(350) → 2행. P2(300)는 300보다 크지 않아서 제외.

**연관 함정 지식**
- ALL과 ANY 정리:

| 표현 | 뜻 | 바꿔 말하면 |
|------|-----|-----------|
| `> ALL (목록)` | 모든 값보다 큼 | `> MAX` |
| `< ALL (목록)` | 모든 값보다 작음 | `< MIN` |
| `> ANY (목록)` | 하나라도 보다 크면 됨 | `> MIN` |
| `< ANY (목록)` | 하나라도 보다 작으면 됨 | `< MAX` |
| `= ANY (목록)` | 하나라도 같으면 됨 | `IN` |

- 보기 1(P2~P5)은 `> ANY`(100 초과)로 계산한 결과다. ALL = "**전부** 이겨야 함", ANY(SOME) = "**하나만** 이기면 됨".

## Q12. 02-SQL-DB — ORDER BY 다중 정렬 (DESC, ASC)

**문제**
[성적] 테이블

| 이름 | 반 | 점수 |
|------|---|------|
| 가 | 1 | 80 |
| 나 | 2 | 90 |
| 다 | 1 | 95 |
| 라 | 2 | 70 |
| 마 | 1 | 85 |

```sql
SELECT 이름 FROM 성적
ORDER BY 반 DESC, 점수 ASC;
```
출력 순서는?

**보기**
1. 가, 마, 다, 라, 나
2. 나, 라, 다, 마, 가
3. 라, 나, 가, 마, 다
4. 다, 나, 마, 가, 라

**내 답**: 가, 마, 다, 라, 나 (오답)
**정답**: 라, 나, 가, 마, 다

**해설**
1. 첫 기준 `반 DESC` → **큰 반부터**: 2반 먼저, 그다음 1반
2. 같은 반 안에서 `점수 ASC` → 작은 점수부터
   - 2반: 라(70), 나(90)
   - 1반: 가(80), 마(85), 다(95)
→ 라, 나, 가, 마, 다

고른 답은 점수 ASC는 맞게 적용했지만, 반을 **1반부터(ASC)** 정렬했다. DESC를 반대로 읽은 것이다.

**연관 함정 지식**
- **ASC** = Ascending(오름차순, 작은 → 큰, **기본값**) / **DESC** = Descending(내림차순, 큰 → 작은). "Descend = 내려가다 → 큰 것에서 작은 것으로 내려감"
- 정렬 키워드는 **바로 앞 컬럼에만** 적용된다. `ORDER BY 반, 점수 DESC`는 반 ASC(생략), 점수 DESC.
- 두 번째 기준은 첫 기준 값이 **같은 행끼리만** 적용된다.

## Q13. 02-SQL-DB — 집합 연산자 (EXCEPT / MINUS)

**문제**
테이블 A(x)의 값: 1, 2, 3, 4, 4
테이블 B(x)의 값: 3, 4, 5

```sql
SELECT x FROM A
EXCEPT
SELECT x FROM B;
```
(※ EXCEPT는 Oracle에서 MINUS)

결과는?

**보기**
1. 1, 2, 4
2. 1, 2
3. 1, 2, 5
4. 5

**내 답**: 1, 2 (정답)
**정답**: 1, 2

**해설**
A에는 있고 B에는 없는 값 → 1, 2. 4는 A에 두 번 있어도 B에 있으므로 빠진다(집합 연산이라 중복도 제거됨).

**연관 함정 지식**
- UNION(합집합, 중복 제거) / UNION ALL(중복 유지) / INTERSECT(교집합) / EXCEPT·MINUS(차집합)
- 같은 데이터로 INTERSECT를 하면 3, 4 (중복 제거되어 4는 한 번)
- 차집합은 **순서가 중요**하다. `B EXCEPT A` = 5.

## Q14. 02-SQL-DB — LEFT OUTER JOIN + IS NULL (짝 없는 행 찾기)

**문제**
[고객] id 값: 1, 2, 3, 4
[주문] 고객id 값: 1, 1, 3, 5

```sql
SELECT COUNT(*)
FROM 고객 c LEFT OUTER JOIN 주문 o ON c.id = o.고객id
WHERE o.고객id IS NULL;
```
결과는?

**보기**
1. 5
2. 3
3. 1
4. 2

**내 답**: 2 (정답)
**정답**: 2

**해설**
LEFT JOIN 결과: (1,1), (1,1), (2,NULL), (3,3), (4,NULL) → 5행. 그중 주문 쪽이 NULL인 행 = 고객 2, 4 → **2** (= 주문한 적 없는 고객).

**연관 함정 지식**
- "LEFT JOIN + 오른쪽 IS NULL" = **왼쪽에만 있는 행** 찾기 (차집합과 같은 효과. Q13 EXCEPT와 연결)
- 주문의 5는 고객에 없으므로 LEFT JOIN에서 버려진다.
- 보기 1(5)은 WHERE를 빼먹고 LEFT JOIN 행 수만 센 경우다.

## Q15. 02-SQL-DB — UPDATE 순차 실행

**문제**
[계좌] 테이블

| 번호 | 잔액 |
|------|------|
| 1 | 1000 |
| 2 | 500 |
| 3 | 2000 |

```sql
UPDATE 계좌 SET 잔액 = 잔액 + 500 WHERE 잔액 < 1000;
UPDATE 계좌 SET 잔액 = 잔액 * 2 WHERE 잔액 >= 1000;
SELECT SUM(잔액) FROM 계좌;
```
마지막 SELECT의 결과는?

**보기**
1. 7000
2. 6500
3. 4500
4. 8000

**내 답**: 모름 — "UPDATE를 잘 몰라" (오답)
**정답**: 8000

**해설**
- `UPDATE 테이블 SET 컬럼 = 새 값 WHERE 조건;` = 조건에 맞는 **행들의 값을 바꾼다**. `잔액 = 잔액 + 500`은 "지금 잔액에 500을 더한 값으로 바꿔라"라는 뜻이다(프로그래밍의 `x = x + 500`과 같음).
- 1번째 UPDATE: 잔액 < 1000인 행은 2번(500)뿐 → 1000으로 변경. 이제 1000, **1000**, 2000.
- 2번째 UPDATE: **바뀐 상태 기준으로** 잔액 >= 1000 → 세 행 모두 → 2000, 2000, 4000
- 합계 = **8000**

**연관 함정 지식**
- UPDATE는 **한 문장씩 순서대로** 적용된다. 두 번째 문장은 첫 번째 결과를 본다.
  - 6500은 첫 UPDATE를 무시한 경우다(2000 + 500 + 4000).
  - 7000은 `>=`의 `=`를 놓쳐 1000을 2배 하지 않은 경우다.
- WHERE를 빼면 **모든 행**이 바뀐다 (DELETE도 마찬가지로 WHERE 없으면 전부 삭제).
- DML 4형제 문법:

```sql
SELECT 컬럼 FROM 테이블 WHERE 조건;
INSERT INTO 테이블 (컬럼1, 컬럼2) VALUES (값1, 값2);
UPDATE 테이블 SET 컬럼 = 값 WHERE 조건;
DELETE FROM 테이블 WHERE 조건;
```
- 빈칸 기출 단골: INSERT **INTO** / **VALUES**, UPDATE ... **SET**, DELETE **FROM**
