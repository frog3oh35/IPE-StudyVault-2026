# 빠르게노트 — 소프트웨어 공학 (정보처리기사 실기 핵심)

> 목적: 기출 중심으로 시험에 나오는 핵심 개념만 빠르게 암기할 수 있도록 정리. 설명 → 패턴/용어 연결형 문제 대비.

---

## 디자인 패턴 핵심 정리 (기출 빈도 높음)
- 분류: 생성(Creational) / 구조(Structural) / 행위(Behavioral)
- 자주 나오는 패턴: Singleton, Abstract Factory, Adapter, Bridge, Proxy, Observer, Iterator, Visitor, Strategy

한 줄 요약(암기용):
- Singleton — 인스턴스 하나만 제공
- Abstract Factory — 관련 객체군(kit)을 묶��� 생성
- Adapter — 인터페이스 변환 (wrapper)
- Bridge — 기능 계층과 구현 계층 분리
- Proxy — 대리 객체로 접근 제어 (lazy, 로그, 보안)
- Observer — 상태 변경 시 의존 객체에 자동 알림
- Iterator — 내부 구조 노출 없이 순차 접근
- Visitor — 기존 코드 변경 없이 기능 추가
- Strategy — 알고리즘 캡슐화/교체 가능

팁: 문제는 보통 "설명 → 패턴 이름" 또는 "패턴 → 핵심 기능" 형태로 출제.

## 응집도(Cohesion) & 결합도(Coupling)
- 목표: 좋은 설계는 "높은 응집도 + 낮은 결합도"

응집도(높을수록 좋음) — 암기 순서 (높→낮):
- 기능적 > 순차적 > 교환적(통신적) > 절차적 > 시간적 > 논리적 > 우연적
- 핵심: 기능적(모듈이 단일 목적 집중)이 최고

결합도(낮을수록 좋음) — 암기 순서 (낮→높):
- 자료 < 스탬프 < 제어 < 외부 < 공통 < 내용
- 핵심: 자료 결합(단순 파라미터 전달)이 가장 약한 결합

자주 출제되는 연결 질문 예시: "모듈이 배열/객체 전달하면? → 스탬프 결합", "전역 변수 참조·갱신하면? → 공통 결합", "다른 모듈 내부 접근하면? → 내용 결합"

## 테스트 핵심 (시험 포인트)

테스트 커버리지(구조 기반 — 화이트박스):
- 문장(Statement) — 모든 문장 1회 이상 실행
- 분기(Branch / Decision) — 모든 분기의 각 경로(참/거짓) 1회 이상
- 조건(Condition) — 각 개별 조건식의 T/F 모두 1회
- 조건/결정, MC/DC, 다중 조건, 경로(Path) — 수준별로 엄격함 증가

스텁(Stub) vs 드라이버(Driver):
- 스텁: 하향식(Top-Down) 통합 테스트에서 하위 모듈 대신 사용하는 더미
- 드라이버: 상향식(Bottom-Up) 통합 테스트에서 상위 모듈 대신 사용하는 더미

테스트 케이스 구성요소: 테스트 조건 / 테스트 데이터 / 예상 결과 (+환경·단계·성공기준)

블랙박스 기법(핵심):
- 동치 분할(Equivalence Partitioning) — 유사 입력을 그룹화해 대표값만 테스트
- 경계값 분석(Boundary Value Analysis) — 경계값 중심 테스트
- 원인-효과 그래프 — 입력(원인)→출력(효과) 관계 표현

---

## 암기 팁 & 요약 카드
- 디자인 패턴: "Singleton / Abstract Factory / Adapter / Bridge / Proxy / Observer" 순으로 핵심 한 줄씩 외우기
- 응집도 암기: 기순교절시논우 (기능>순차>교환>절차>시간>논리>우연)
- 결합도 암기: 자스제외공내 (자료<스탬프<제어<외부<공통<내용)
- 스텁/드라이버: 하향→스텁, 상향→드라이버
- 커버리지: 문장 < 분기 < 조건 < 경로 (엄격도 순)

# 빠르게 끝내기: 핵심 문장 5개
1) "Singleton은 인스턴스 하나만 제공한다."  
2) "Abstract Factory는 연관 객체군을 묶어 생성한다."  
3) "응집도는 높을수록 좋고, 결합도는 낮을수록 좋다."  
4) "스텁은 하향식, 드라이버는 상향식 통합 테스트에서 사용하는 더미다."  
5) "분기 커버리지는 모든 분기(참/거짓)를 최소 1회 실행하는 것이다."
