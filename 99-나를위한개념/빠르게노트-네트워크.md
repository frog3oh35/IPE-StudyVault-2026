# 빠르게노트 — 네트워크

> [!note] 쓰는 법
> 서브넷 계산은 [[서브넷-계산]]에서 따로. 여기는 **외워서 답하는 개념**만. ⚠️ = 틀렸거나 아직 확인 안 한 것.

## 1. OSI 7계층 ⚠️

| 계층 | 장비 · 주소 | PDU | 대표 |
|---|---|---|---|
| 7 응용 | 게이트웨이 | 메시지 | HTTP, FTP, SMTP, DNS |
| 6 표현 | | | 암호화, 코드 변환, 압축 |
| 5 세션 | | | 대화 설정·유지·종료(동기점) |
| 4 전송 | 포트 번호 | **세그먼트** | TCP, UDP |
| 3 네트워크 | **라우터 / IP 주소** | **패킷** | IP, ICMP, ARP |
| 2 데이터링크 | **스위치·브리지 / MAC 주소** | **프레임** | HDLC, 이더넷 |
| 1 물리 | 허브·리피터 | 비트 | 케이블 |

> [!warning] IP로 경로 선택 = 라우터 = 3계층
> MAC으로 전달하는 스위치가 2계층. 라우터를 2계층으로 답한 적 있음.

- TCP/IP 4계층: 응용 / 전송 / 인터넷 / 네트워크 접속

## 2. TCP vs UDP

| | TCP | UDP |
|---|---|---|
| 연결 | 연결형 | 비연결형(데이터그램) |
| 신뢰성 | 흐름·오류·혼잡 제어 | 없음, 대신 빠름 |
| 예 | HTTP, FTP | 스트리밍, DNS |

- **연결 수립 (3-way)**: SYN → SYN+ACK → ACK
- ⚠️ **연결 종료 (4-way)**: FIN → ACK → FIN → ACK (아직 확인 안 함)

## 3. 주소 · 관리 프로토콜

| 키워드 | 정답 |
|---|---|
| IP로 **MAC** 알아냄 | **ARP** |
| ⚠️ MAC으로 **IP** 알아냄 (Reverse) | **RARP** |
| IP 자동 할당 | **DHCP** (RARP → BOOTP → DHCP로 대체) |
| 오류 보고, ping | **ICMP** |
| **멀티캐스트 그룹** 관리 | **IGMP** |
| 사설 IP ↔ 공인 IP | **NAT** |
| 도메인 → IP | **DNS** |

## 4. IPv6 ⚠️

- **128비트**, 16진수 8그룹(콜론 구분). IPv4는 32비트
- 통신 방식: **유니캐스트 / 멀티캐스트 / 애니캐스트** — ⚠️ **브로드캐스트 없음** (유니캐스트로 오답한 적 있음)
- 헤더 40바이트 고정, IPSec 기본 내장
- 전환 방법: 듀얼 스택 / 터널링 / 주소 변환

## 5. 라우팅 · 교환

| 키워드 | 정답 |
|---|---|
| 거리 벡터, **홉 수**, 최대 **15홉** | **RIP** |
| 링크 상태, **Dijkstra**, 대규모 | **OSPF** |
| 서로 다른 AS(자율 시스템) 간 | **BGP** |
| 첫 패킷으로 경로 고정, ATM | **가상 회선** |
| 패킷마다 독립 경로, 비연결 | **데이터그램** |

## 6. 오류 제어 / HDLC

- **FEC(전진)**: 재전송 없이 수신측이 직접 수정 → **해밍 코드**
- **BEC(후진)**: 오류 발견 시 재전송 요청 → **CRC, 패리티**, ARQ(Stop-and-Wait, Go-Back-N, Selective Repeat)
- **HDLC 프레임**: I(정보, `0`) / S(감독, `10`) / U(비번호, `11`)
- **HDLC 모드**: ABM(비동기 균형, 동등) / ARM(비동기 응답, 허가 없이 응답) / NRM(정규 응답, 주국 허가 필요)

## 7. 포트 번호

| FTP | SSH | Telnet | SMTP | DNS | DHCP | HTTP | POP3 | IMAP | HTTPS |
|---|---|---|---|---|---|---|---|---|---|
| 20/21 | **22** | 23 | 25 | 53 | 67/68 | 80 | 110 | 143 | 443 |

## 8. 기타 단골

- **Ad-hoc**: 기지국(AP) 없이 단말끼리 직접 통신
- **블루투스**: 피코넷 = 마스터 1 + 슬레이브 최대 7 / 스캐터넷 = 피코넷 여러 개
- **AJAX**: 새로고침 없이 비동기로 일부만 갱신
- **REST**: 무상태, URI로 자원 식별, GET·POST·PUT·DELETE

## 9. URL 구조

```
https://www.example.com:8080/board/list.html?page=2&sort=new#top
```

- **스킴(프로토콜)** — 맨 앞 `https`. 어떤 규칙으로 통신할지 정한다 (`http`, `https`, `ftp` 등)
- **호스트(도메인)** — `www.example.com`. 서버 이름이고, DNS가 이걸 IP 주소로 바꿔 준다
- **포트** — `:` 뒤의 `8080`. 생략하면 기본값을 쓴다 (http는 80, https는 443)
- **경로** — `/board/list.html`. 서버 안에서 어느 자원인지
- **쿼리스트링** — `?` 뒤의 `page=2&sort=new`. `key=value` 꼴로 서버에 값을 넘기고, 여러 개면 `&`로 잇는다
- **프래그먼트(앵커)** — `#` 뒤의 `top`. 페이지 안의 특정 위치로 이동한다

> [!tip] 왜 프래그먼트는 서버로 안 가나?
> `#` 뒤는 "이 페이지의 어디를 보여 줄지"라서 브라우저만 알면 된다. 서버에 필요한 값은 `?` 쿼리스트링으로 보낸다.

> [!warning] 구분자 문제로 나온다
> 포트 앞은 `:`, 쿼리 시작은 `?`, 쿼리끼리 연결은 `&`, 프래그먼트는 `#`. 기출(2025-3)에서 "포트를 지정하는 구분자"를 물었다.

## 10. VPN · 터널링 프로토콜

- **VPN**은 인터넷 같은 **공중망 위에 암호화된 터널**을 만들어서 사설망처럼 쓰는 기술이다
- **터널링**은 원래 패킷을 다른 패킷 안에 **통째로 감싸서(캡슐화)** 보내는 것
- VPN을 만드는 프로토콜은 계층별로 나뉜다
  - **L2TP** — **2계층** 터널링. **L2F + PPTP**를 합친 것
  - **IPSec** — **3계층**. IP 패킷 자체를 암호화·인증하고, AH와 ESP로 구성된다
  - **SSL VPN** — 웹 브라우저로 접속하는 방식이라 별도 프로그램이 거의 필요 없다

> [!tip] 왜 L2TP는 IPSec과 같이 쓰나?
> L2TP는 **터널만 만들고 암호화는 안 한다.** 그래서 보통 IPSec으로 암호화를 얹어서 "L2TP/IPSec"으로 쓴다.

> [!warning] 이름으로 계층 구분
> 이름에 **L2**가 들어가면 2계층(L2TP), **IP**Sec은 IP 계층(3계층). 보안 노트의 IPSec AH·ESP와 엮여서 나온다 → [[빠르게노트-보안]]

## 11. CSMA/CD vs CSMA/CA

여러 기기가 **하나의 통신 매체를 같이 쓰면**, 동시에 보냈을 때 데이터가 충돌한다. 둘 다 보내기 전에 매체가 비었는지 **먼저 들어 보는 것(CSMA, Carrier Sense)**까지는 같고, 충돌을 처리하는 방식이 다르다.

- **CSMA/CD** (Collision **Detection**, 충돌 **감지**)
  - **유선** 이더넷 (IEEE 802.3)
  - 일단 보내고, 보내는 도중 충돌을 **감지하면** 멈춘 뒤 임의 시간을 기다렸다가 다시 보낸다
- **CSMA/CA** (Collision **Avoidance**, 충돌 **회피**)
  - **무선** LAN (IEEE 802.11)
  - 매체가 비어 있어도 **임의 시간을 더 기다린 뒤** 보내서 충돌을 미리 피한다

> [!tip] 왜 무선은 감지가 아니라 회피인가?
> 무선은 내가 보내는 신호가 너무 세서 **보내는 도중에 다른 신호를 들을 수 없다.** 충돌을 감지할 수 없으니 애초에 피하는 쪽을 택한 것이다.

> [!warning] 외우는 법
> **CA**의 **A** = **A**ir(무선)로 외우고, 나머지 CD는 유선. 둘 다 2계층(데이터링크).

근거: 실기 교재 기출 목록(CSMA/CA, CSMA/CD). 볼트 기출 노트에는 아직 없음

## 12. VLAN

- **VLAN**(Virtual LAN)은 물리적으로 같은 스위치에 꽂혀 있어도 **논리적으로 LAN을 나누는** 기술이다
- 예를 들어 한 층에 있는 개발팀 PC와 인사팀 PC가 같은 스위치에 꽂혀 있어도, VLAN으로 나누면 서로 다른 네트워크처럼 동작한다

> [!tip] 왜 나누나?
> 같은 LAN이면 **브로드캐스트가 전체에 퍼진다.** VLAN으로 쪼개면 브로드캐스트가 퍼지는 범위(도메인)가 줄어서 **트래픽이 줄고**, 부서끼리 분리되니 **보안**도 좋아진다.

> [!warning] 키워드
> "**물리적 위치와 상관없이**", "**논리적으로** 분할", "**스위치**", "브로드캐스트 도메인 분리"가 보이면 VLAN. VLAN끼리 통신하려면 3계층 장비(라우터)가 필요하다.

근거: 실기 교재 기출 목록(VLAN). 볼트 기출 노트에는 아직 없음

## 13. IPv4 클래스 · 사설 IP

서브넷 문제를 풀 때 기본으로 깔고 들어가는 지식이다. **첫 옥텟(맨 앞 숫자)**만 보면 클래스를 알 수 있다.

- **A 클래스** — 0 ~ 127, 기본 마스크 /8 (255.0.0.0). 127은 자기 자신을 가리키는 **루프백**
- **B 클래스** — 128 ~ 191, 기본 마스크 /16 (255.255.0.0)
- **C 클래스** — 192 ~ 223, 기본 마스크 /24 (255.255.255.0)
- **D 클래스** — 224 ~ 239, **멀티캐스트**용
- **E 클래스** — 240 ~ 255, 연구용(예약)

**사설 IP**는 내부망에서만 쓰고 인터넷에서는 쓰이지 않는 대역이다. `10.x.x.x`, `172.16 ~ 172.31.x.x`, `192.168.x.x` 세 가지. 사설 IP로 인터넷에 나갈 때 공인 IP로 바꿔 주는 게 **NAT**(3번 참고)다.

> [!tip] 왜 사설 IP가 있나?
> IPv4 주소는 약 43억 개라 모자란다. 그래서 내부에서는 사설 IP를 쓰고, 바깥에 나갈 때만 NAT로 공인 IP를 나눠 쓴다. 근본적인 해결책이 **IPv6**(4번)다.
