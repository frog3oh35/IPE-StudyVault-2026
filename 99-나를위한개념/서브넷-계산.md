# 서브넷 계산 — 마스크부터 브로드캐스트까지

> [!note] 이 노트를 만든 이유
> 서브넷 문제를 다섯 번 만났는데 한 번도 제대로 풀지 못했다. 10/06에는 "개념부터 공부해야 함"이라며 패스했다.
> 공식(AND 연산)부터 외우려니 막혔다. 그래서 이 노트는 **"블록 크기 하나로 구간을 나누는 방법"** 하나만 확실히 익히는 것이 목표다.
> 정처기에서는 **매 회차 1~2문제**가 나오는 단골이다 → [[../05-네트워크/IP-서브넷|IP-서브넷]]

## 0. IP 주소는 어떻게 생겼나

```
192 . 168 . 10 . 100
 ↑     ↑     ↑    ↑
1옥텟 2옥텟 3옥텟 4옥텟   ← 한 칸(옥텟) = 8비트 = 0~255
```

- IP 주소는 **32비트**이고, 8비트씩 4칸으로 나눠 10진수로 적은 것이다.
- 한 칸의 비트 자리값: **128 64 32 16 8 4 2 1** (전부 더하면 255)

> [!tip] 왜 0~255일까?
> 8비트가 전부 1이면 128+64+32+16+8+4+2+1 = 255. 8비트로 만들 수 있는 수가 0~255, 즉 256개다.
> 이 **256**이라는 숫자가 뒤에서 블록 크기를 계산할 때 계속 나온다.

IP 주소는 두 부분으로 나뉜다.
- **네트워크 부분**: "어느 동네(네트워크)인지" — 같은 동네면 이 부분이 같다
- **호스트 부분**: "그 동네의 몇 번지(컴퓨터)인지"

어디까지가 네트워크 부분인지 알려 주는 게 **서브넷 마스크**다.

## 1. 서브넷 마스크와 CIDR

### 규칙 한 줄
> **마스크에서 1인 비트 = 네트워크 부분, 0인 비트 = 호스트 부분**

```
255.255.255.224
= 11111111.11111111.11111111.11100000
  └──────────── 1이 27개 ────────┘└0이 5개┘
                 네트워크 27비트     호스트 5비트
```

- **CIDR 표기** `/27` = "앞에서부터 1이 27개"라는 뜻이다. `255.255.255.224`와 `/27`은 같은 말이다.
- 마스크는 항상 **1이 왼쪽에 몰려 있고**, 0이 오른쪽에 몰려 있다. 그래서 한 옥텟에 올 수 있는 값은 정해져 있다.

### 마스크 옥텟값 표 (이것만 외우면 된다)

| 1의 개수 | 2진수 | 옥텟값 | 블록 크기 (256 − 값) |
|---------|-------|-------|-------------------|
| 0 | 00000000 | **0** | 256 |
| 1 | 10000000 | **128** | 128 |
| 2 | 11000000 | **192** | 64 |
| 3 | 11100000 | **224** | 32 |
| 4 | 11110000 | **240** | 16 |
| 5 | 11111000 | **248** | 8 |
| 6 | 11111100 | **252** | 4 |
| 7 | 11111110 | **254** | 2 |
| 8 | 11111111 | **255** | 1 |

> [!tip] 표를 빨리 만드는 법
> 옥텟값은 왼쪽부터 자리값을 하나씩 더한 것이다: 128 → +64 = 192 → +32 = 224 → +16 = 240 → +8 = 248 …
> 블록 크기는 **절반씩** 줄어든다: 128 → 64 → 32 → 16 → 8 → 4 → 2

### CIDR → 어느 옥텟에서 끊기나

| CIDR | 끊기는 옥텟 | 그 옥텟의 1 개수 | 마스크 |
|------|-----------|---------------|--------|
| /24 | 3옥텟까지 꽉 참 | — | 255.255.255.0 |
| /25 ~ /32 | **4옥텟** | n − 24 | 255.255.255.□ |
| /17 ~ /23 | **3옥텟** | n − 16 | 255.255.□.0 |

예: `/27` → 4옥텟에서 1이 27 − 24 = **3개** → 224
예: `/23` → 3옥텟에서 1이 23 − 16 = **7개** → 254 → 마스크 255.255.254.0

## 2. 손으로 푸는 4단계 루틴 ⭐

> **① 끊기는 옥텟 찾기 → ② 블록 크기 = 256 − 마스크값 → ③ 블록 단위로 구간 나누기 → ④ 구간에서 답 읽기**

| 구하는 것 | 구간에서 읽는 법 |
|----------|----------------|
| **네트워크 주소** | 구간의 **첫 값** |
| **브로드캐스트 주소** | 구간의 **마지막 값** (= 다음 구간 첫 값 − 1) |
| **사용 가능 호스트 범위** | 첫 값 + 1 ~ 마지막 값 − 1 |
| **사용 가능 호스트 수** | 2^(호스트 비트 수) − 2 = 블록 크기 − 2 (4옥텟에서 끊길 때) |

> [!example] 10/06 Q17 다시 풀기 — 192.168.10.100/27 의 브로드캐스트 주소
> ① `/27` → 4옥텟에서 끊김, 1이 3개 → 마스크 224
> ② 블록 = 256 − 224 = **32**
> ③ 4옥텟을 32씩 나눈다: 0~31 / 32~63 / 64~95 / **96~127** / 128~159 / …
> ④ 100은 **96~127** 구간에 있다
> → 네트워크 주소 192.168.10.**96**, 브로드캐스트 192.168.10.**127**
> → 사용 가능 호스트 .97 ~ .126, 32 − 2 = **30개**

> [!example] 09-30 문제 다시 풀기 — 172.16.5.130/26 의 브로드캐스트
> ① `/26` → 4옥텟, 1이 2개 → 192 ② 블록 = 64
> ③ 0~63 / 64~127 / **128~191** / 192~255 ④ 130은 128~191
> → 네트워크 172.16.5.**128**, 브로드캐스트 172.16.5.**191**

> [!example] 10-01 문제 다시 풀기 — 10.0.0.77/28 의 네트워크 주소
> ① `/28` → 4옥텟, 1이 4개 → 240 ② 블록 = 16
> ③ … / 48~63 / **64~79** / 80~95 / … ④ 77은 64~79
> → 네트워크 10.0.0.**64**, 브로드캐스트 10.0.0.**79**

## 3. 3옥텟에서 끊기면? (/17 ~ /23)

방법은 똑같다. **블록을 3옥텟에 적용**하고, 4옥텟은 0~255를 통째로 쓴다는 점만 다르다.

> [!example] 09-28 문제 다시 풀기 — 192.168.11.20, 마스크 255.255.254.0 (/23)
> ① 3옥텟에서 끊김, 마스크값 254
> ② 블록 = 256 − 254 = **2**
> ③ 3옥텟을 2씩 나눈다: … / 8~9 / **10~11** / 12~13 / …
> ④ 11은 10~11 구간
> → 네트워크 주소 = 구간 첫 값 + 4옥텟 0 → 192.168.**10.0**
> → 브로드캐스트 = 구간 끝 값 + 4옥텟 255 → 192.168.**11.255**
> → 호스트 비트 = 32 − 23 = 9개 → 2⁹ − 2 = **510개**

> [!warning] 3옥텟에서 끊길 때의 함정
> - 네트워크 주소의 4옥텟은 **항상 0**, 브로드캐스트의 4옥텟은 **항상 255**다.
> - 호스트 수는 "블록 − 2"가 아니라 **2^(32 − n) − 2**로 계산한다 (블록 2 − 2 = 0개가 아니다!).

## 4. 호스트 수는 왜 −2일까?

구간의 첫 값과 마지막 값은 **컴퓨터에 줄 수 없는 특별한 주소**다.

| 주소 | 역할 | 비유 |
|------|------|------|
| 첫 값 (호스트 비트 전부 0) | **네트워크 주소** — 이 네트워크 자체의 이름 | 동네 이름 |
| 마지막 값 (호스트 비트 전부 1) | **브로드캐스트 주소** — 이 네트워크 전체에게 한 번에 보내는 주소 | 동네 전체 방송 |

그래서 **사용 가능 호스트 수 = 전체 주소 수 − 2**다.

| CIDR | /24 | /25 | /26 | /27 | /28 | /29 | /30 |
|------|-----|-----|-----|-----|-----|-----|-----|
| 블록(전체) | 256 | 128 | 64 | 32 | 16 | 8 | 4 |
| 사용 가능 호스트 | 254 | 126 | 62 | 30 | 14 | 6 | 2 |

> 09-18에 /27을 62로 답했다 → 62는 /26이다. **/27 = 32 − 2 = 30**

## 5. 더 알아보기 — 같이 알아두면 이해가 단단해지는 것

> [!info]- ① 원래 공식(AND 연산)과 블록 방법은 같은 계산이다
> 교재 공식은 **네트워크 주소 = IP AND 마스크**다.
> ```
> 100 = 0110 0100
> 224 = 1110 0000
> AND = 0110 0000 = 96   ← 블록 방법과 같은 답
> ```
> 마스크의 1 부분(네트워크 비트)은 그대로 두고, 0 부분(호스트 비트)을 전부 0으로 만드는 게 AND다.
> 호스트 비트를 0으로 만들면 = 구간의 첫 값 = 네트워크 주소.
> 브로드캐스트는 반대로 호스트 비트를 **전부 1**로 만든 것이다 → 96 + 31 = 127.
> 블록 방법은 이 비트 계산을 "32씩 나누기"로 바꾼 지름길일 뿐이다.

> [!info]- ② "서브넷을 N개로 나눠라" 유형
> 정처기에서 가끔 "192.168.100.0/24를 4개의 서브넷으로 균등 분할" 같은 문제가 나온다.
> - 4개 = 2² → 네트워크 비트를 **2개 더** 빌린다 → /24 + 2 = **/26**
> - 블록 = 64 → 서브넷: .0 / .64 / .128 / .192
> - 각 서브넷 사용 가능 호스트 = 62개
>
> 공식: **N개로 나누려면 2^k ≥ N인 최소 k만큼 CIDR에 더한다.** (3개로 나눠도 2²=4 → /26)

> [!info]- ③ 같은 네트워크인지 판별하기
> 두 IP가 **같은 구간**에 있으면 같은 네트워크다. 라우터 없이 직접 통신할 수 있다.
> 예: /27에서 .100과 .120 → 둘 다 96~127 → 같은 네트워크
> 예: /27에서 .100과 .130 → 96~127 vs 128~159 → 다른 네트워크

> [!info]- ④ 사설 IP 대역 (NAT와 함께 나옴)
> 인터넷에 직접 나가지 않는 내부망용 주소다. NAT가 공인 IP로 바꿔 준다.
> - 10.0.0.0/8 (10.x.x.x)
> - 172.16.0.0/12 (172.16.x.x ~ 172.31.x.x)
> - 192.168.0.0/16 (192.168.x.x)

> [!info]- ⑤ 시프트 연산과의 연결 (10/06 Q4)
> 블록 크기가 절반씩 줄어드는 것(128 → 64 → 32)은 `>> 1`과 같은 원리다.
> `/27`의 블록 32 = 2⁵ = `1 << 5`, 호스트 비트 5개.
> 비트 감각이 생기면 C 비트 연산 문제도 같이 쉬워진다.

## 6. 연습문제 (정처기 실기 난이도)

> 답은 접혀 있다. **4단계 루틴**을 종이에 써 가며 풀어 보자.

**P1.** 192.168.1.200/26의 네트워크 주소, 브로드캐스트 주소, 사용 가능 호스트 수는?
> [!success]- 정답
> 블록 64 → 구간 192~255 → 네트워크 **192.168.1.192**, 브로드캐스트 **192.168.1.255**, 호스트 **62개**

**P2.** 10.10.10.45, 서브넷 마스크 255.255.255.248일 때 사용 가능한 호스트 IP 범위는?
> [!success]- 정답
> 248 → 블록 8 → 구간 40~47 → **10.10.10.41 ~ 10.10.10.46** (6개)

**P3.** 255.255.255.240을 CIDR로 쓰면? 사용 가능 호스트 수는?
> [!success]- 정답
> 240 = 11110000 → 1이 24 + 4 = 28개 → **/28**, 16 − 2 = **14개**

**P4.** 172.16.50.10/21의 네트워크 주소와 브로드캐스트 주소는?
> [!success]- 정답
> /21 → 3옥텟에서 1이 5개 → 248 → 블록 **8** → 3옥텟 구간 48~55
> 네트워크 **172.16.48.0**, 브로드캐스트 **172.16.55.255**

**P5.** 192.168.100.0/24를 4개의 서브넷으로 균등 분할할 때, 세 번째 서브넷의 네트워크 주소와 서브넷 마스크는?
> [!success]- 정답
> 2² = 4 → /26 (마스크 **255.255.255.192**), 블록 64 → .0 / .64 / **.128** / .192
> 세 번째 = **192.168.100.128**

**P6.** 192.168.10.100/27과 같은 네트워크에 속하면서 호스트에 할당할 수 있는 IP를 고르면? (.95 / .97 / .127 / .128)
> [!success]- 정답
> 구간 96~127, 할당 가능 97~126 → **192.168.10.97**
> .95와 .128은 다른 구간, .127은 브로드캐스트라 할당 불가

## 한 장 요약

> [!summary]
> 1. 마스크의 1 = 네트워크, 0 = 호스트. `/n` = 1이 n개
> 2. 옥텟값 표: 128 · 192 · 224 · 240 · 248 · 252 · 254 · 255
> 3. **블록 = 256 − 끊기는 옥텟의 마스크값**
> 4. 블록 단위로 구간 → 첫 값 = 네트워크, 끝 값 = 브로드캐스트
> 5. 호스트 수 = 2^(32 − n) − 2
> 6. 3옥텟에서 끊기면 네트워크 4옥텟은 0, 브로드캐스트 4옥텟은 255
